# Claude Code 루프(Loops) 활용 가이드

> 이 문서는 ClaudeDevs의 X 아티클 "Getting started with loops"(2026-07-07, 작성: @delba_oliveira)의
> 핵심 개념을 요약·재구성한 것입니다.
> 원문: https://x.com/claudedevs/status/2074208949205881033

## 루프란?

에이전트가 **중지 조건을 만족할 때까지 작업 사이클을 반복**하는 것.
트리거 방식, 중지 조건, 사용하는 Claude Code 프리미티브에 따라 네 가지 유형으로 나뉜다.

## 네 가지 루프 유형

| 유형 | 트리거 | 중지 조건 | 적합한 작업 | 도구 |
|---|---|---|---|---|
| 턴 기반 | 사용자 프롬프트 | Claude가 완료 판단 | 짧은 일회성 작업 | 검증 스킬(SKILL.md) |
| 목표 기반 | 수동 프롬프트 | 목표 달성 또는 최대 턴 도달 | 완료 기준이 검증 가능한 작업 | `/goal` |
| 시간 기반 | 시간 간격 | 사용자 취소 또는 작업 완료 | 반복 작업, 외부 시스템 감시 | `/loop`, `/schedule` |
| 프로액티브 | 이벤트/스케줄 (사람 개입 없음) | 개별 작업은 목표 달성 시 종료 | 버그 트리아지, 마이그레이션 등 정형 반복 업무 | 위 도구 조합 + 동적 워크플로우 |

## 각 유형 요약

### 1. 턴 기반 루프
프롬프트 하나가 곧 하나의 루프(맥락 수집 → 실행 → 자체 확인 → 응답).
수동 검증 절차를 SKILL.md로 문서화하면 Claude가 스스로 더 많은 것을 검증한다.
정량적 기준(테스트 통과 수, 에러 0개 등)일수록 자체 검증이 쉬워진다.

### 2. 목표 기반 루프 (`/goal`)
"무엇이 완료인지"를 명시하면 평가 모델이 조건 충족 여부를 확인하며
목표 달성 또는 지정한 턴 수까지 반복시킨다.
예: `/goal 홈페이지 Lighthouse 점수 90 이상, 5회 시도 후 중단`
반드시 턴 상한을 함께 지정할 것.

### 3. 시간 기반 루프 (`/loop`, `/schedule`)
- `/loop 5m ...` : 로컬에서 지정 간격으로 프롬프트 재실행 (컴퓨터를 끄면 중단)
- `/schedule` : 루틴을 클라우드로 이전해 상시 실행
PR의 CI/리뷰 감시, 주기적 요약 등 외부 시스템과의 인터페이스에 적합.

### 4. 프로액티브 루프
`/schedule` + `/goal` + 스킬 + 동적 워크플로우 + 오토 모드를 조합해
사람 개입 없이 굴러가는 장기 루틴을 구성.
예: 매시간 피드백 채널을 확인 → 각 리포트를 트리아지/수정/응답,
버그 수정 시 병렬 워크트리에서 세 가지 해법을 탐색하고 심판 에이전트가 리뷰.

## 코드 품질 유지 원칙

- 코드베이스를 깨끗하게: Claude는 기존 패턴과 컨벤션을 따른다
- 자체 검증 수단 제공: "좋은 결과"의 기준을 스킬로 인코딩
- 문서 접근성 확보: 프레임워크/라이브러리 최신 문서를 참조 가능하게
- 별도 에이전트로 코드 리뷰: 새 컨텍스트의 리뷰어가 편향이 적다 (`/code-review`)
- 개별 실패를 고치는 데 그치지 말고 **시스템(스킬/규칙)에 반영해 누적**시킬 것

## 토큰 사용량 관리

- 작업에 맞는 최소한의 프리미티브와 모델 선택 (작은 작업엔 작은 모델)
- 명확한 성공/중지 기준 정의
- 대규모 실행 전 작은 슬라이스로 파일럿
- 결정적인 작업은 추론 대신 스크립트로 처리
- 루틴 실행 주기는 감시 대상의 변화 주기에 맞출 것
- `/usage`, `/goal`(인자 없이), `/workflows`로 사용량 점검

## 시작하는 법

지금 본인이 병목인 작업 하나를 골라 자문해 볼 것:
- 검증 체크를 글로 쓸 수 있는가? → 검증 스킬
- 완료 기준이 명확한가? → `/goal`
- 일정 주기로 발생하는 일인가? → `/loop`, `/schedule`

루프를 돌려보고, 어디서 멈추거나 과하게 나가는지 관찰하며 반복 개선한다.

사용 가능 여부와 세부 동작은 Claude Code 공식 문서에서 확인 필요.*
