## API Reference
- [Getting Started](https://devx.notabene.id/reference/getting-started-with-your-api.md): This page will help you get started with the Notabene APIs.
- [Create a new relationship](https://devx.notabene.id/reference/createrelationship.md): Creates a new relationship between an address and an entity. Relationships establish ownership or control over blockchain addresses. Optionally includes an ownership proof for verification.
- [List relationships for an entity](https://devx.notabene.id/reference/listrelationships.md): Retrieves all relationships associated with the specified entity, including ownership proofs for each relationship. Supports optional filtering by 'from', 'to', 'custodian', and 'asset'.
- [Confirm a relationship](https://devx.notabene.id/reference/confirmrelationship.md): Confirms a relationship between an address and an entity. Creates the relationship if it doesn't exist (upsert behavior). Optionally includes an ownership proof for verification.
- [Delete a relationship](https://devx.notabene.id/reference/deleterelationship.md): Deletes an existing relationship between an address and an entity. Use 'from' and 'to' query parameters to identify the relationship.
- [Create a new transfer](https://devx.notabene.id/reference/createtransfer.md): Creates a new transfer from the specified entity to another entity. This is the entry point for initiating a new transfer in the system.
- [List transfers for an entity](https://devx.notabene.id/reference/listtransfers.md): Retrieves a paginated list of transfers for the specified entity. Supports filtering by status, asset, direction, date range, and more.
- [Remove an agent from a transfer](https://devx.notabene.id/reference/removeagent.md): Removes an existing agent from a transfer. The agent is soft-deleted (marked with removed_at timestamp). The caller must be the transfer initiator, a gateway, or have a relationship with the agent being removed.
- [Authorize a transfer](https://devx.notabene.id/reference/authorizetransfer.md): Authorizes a transfer to proceed. Optionally accepts a settlement address and memo tag. Can be forced with the `force` query parameter to bypass certain checks, or use `ignoreFlags` to ignore flag policies.
- [Settle a transfer](https://devx.notabene.id/reference/settletransfer.md): Settles a transfer by providing settlement transaction details. This endpoint accepts optional settlement ID, settlement ID index, and revert settlement ID.
- [Add an agent to a transfer](https://devx.notabene.id/reference/addagent.md): Adds an agent (VASP, custodian, etc.) to an existing transfer. The agent must have a valid DID and role.
- [Get a specific transfer](https://devx.notabene.id/reference/gettransfer.md): Retrieves detailed information about a specific transfer including status, agents, and policy evaluations. Supports optional PII decryption, timeline, and integration results.
- [Search transfers with filters](https://devx.notabene.id/reference/searchtransfers.md)
- [Match transfers by settlement identifiers](https://devx.notabene.id/reference/matchtransfers.md)
- [Clear transfer funds](https://devx.notabene.id/reference/cleartransfer.md): Clears the funds associated with a transfer. Requires the ClearTransfer permission.
- [Reject a transfer](https://devx.notabene.id/reference/rejecttransfer.md): Rejects a transfer with a specified reason. If the reason is OTHER, a comment is required.
- [Replace an agent in a transfer](https://devx.notabene.id/reference/replaceagent.md): Replaces an existing agent in a transfer with a new agent. The caller must be the transfer initiator, a gateway, or have a relationship with the agent being replaced.
- [Add a comment to a transfer](https://devx.notabene.id/reference/addcomment.md): Appends a free-form note to a transfer. Comments are scoped to the writing entity and are not shared with the counterparty.
- [Discover address ownership information](https://devx.notabene.id/reference/discoveraddressownership.md): Performs agent discovery for a given blockchain address using multiple methods: 1. Relationships (confirmed/unconfirmed) 2. Hashed Address Service 3. Blockchain Analytics (if configured)  Returns the discovered agent/VASP information, custodian, jurisdiction, relationship status, and ownership proofs (when available).  **Authentication**: Supports both M2M tokens and delegate tokens for automated integrations.
- [Append PII data to a transfer](https://devx.notabene.id/reference/appendtransfer.md): Appends IVMS101 PII (Personally Identifiable Information) data to an existing transfer. The PII data is validated against the transfer's presentation definition (if set) and encrypted before storage. All arrays in the IVMS101 structure are limited to 25 items to prevent unbounded payload attacks.
- [Present PII data to counterparties](https://devx.notabene.id/reference/presenttransferpii.md): Used to present PII data to counterparties in a transfer. This endpoint is used for sharing PII between entities and can optionally skip validation with skipValidation=true parameter.
- [Create a delegate token](https://devx.notabene.id/reference/createdelegatetoken.md): Creates a delegate token for an entity. The delegate token is a JWT that allows a delegate to act on behalf of the entity. If a delegate DID already exists for the given delegateId, it will be reused.
- [Get entity public encryption keys](https://devx.notabene.id/reference/getentitypublickeys.md): Returns the encryption key that would be sent in webhooks for the given entity. This allows counterparties to proactively fetch encryption keys without waiting for a RequirePresentation webhook.  **V1 VASP Handling:** For entities using the TRNow protocol (V1 VASPs with did:ethr DIDs), this endpoint automatically returns the Gateway VASP's encryption keys instead of the entity's own keys, since V1 VASPs don't have their own encryption keys. The response includes a `gatewayDID` field to indicate this.  **Performance Optimization:** For did:web entities in the local database, encryption keys are resolved directly without Network API calls, enabling fast response times for local V2 entities.  **Key Selection Priority:** Uses the same priority algorithm as webhook sending: 1. Keys ending with "#pii" (highest priority) 2. Keys ending with "#notabene-pii" 3. Keys with type "X25519KeyAgreementKey2019" 4. First available key (fallback)  Response is cached via Veramo's DID resolution cache (5 minute TTL).
- [List audit log events](https://devx.notabene.id/reference/listauditlog.md): Returns a paginated list of audit log events for an entity, with optional filters for domain, action, actor, and time range.
- [Complete beneficiary name matching check](https://devx.notabene.id/reference/completebeneficiarynamematching.md): Marks the beneficiary name matching check as complete for the specified transfer. This endpoint is called after the entity has verified that the beneficiary name matches.
- [Complete internal checks](https://devx.notabene.id/reference/completeinternalchecks.md): Marks the internal checks as complete for the specified transfer. This endpoint is called after the entity has completed internal operational checks on the provided PII/Travel Rule information.
- [Get Entity](https://devx.notabene.id/reference/getvasp.md): Retrieves VASP/Entity information from the Network API by DID. Returns detailed information about the entity including regulatory status, verification status, and protocol support.
- [List entities in the network](https://devx.notabene.id/reference/listentities.md): Returns a list of VASP entities in the network. Supports filtering by various criteria including sandbox mode, verification status, and search queries. Results are paginated and can be ordered by different fields.
- [Set funding address for Flow transfer](https://devx.notabene.id/reference/setfundingaddress.md): Allows onramps (agents in a Flow transfer) to provide funding address information. The funding information is stored in the transfer (replacing any existing) and a Fund TAP message is broadcast to all agents in the transfer. This endpoint should be called after the onramp is added as an agent to the Flow transfer.
- [List customers for an entity within Flow workflows](https://devx.notabene.id/reference/listflowcustomers.md): Retrieves a paginated list of customers associated with an entity within Flow workflow contexts. Customer PII in profileData is encrypted and not included by default for security and privacy compliance.
- [Create a new customer for Flow workflows](https://devx.notabene.id/reference/createflowcustomer.md): Creates a new customer profile within a Flow workflow context. Customer PII is encrypted before storage and returned without PII by default. This endpoint checks for existing customers to prevent duplicates.  **IVMS101 Validation Requirements:** - For natural persons: `name` object is **required** - For legal persons: `name` and `nationalIdentification` objects are **required** - When `nameIdentifier` array is provided, its fields are **required** - Unknown fields are rejected (strict validation)
- [Get a customer profile by DID](https://devx.notabene.id/reference/getflowcustomer.md): Retrieves a customer profile within a Flow workflow context. Customer PII can be optionally included in the response based on the includePII query parameter and user permissions. PII data is decrypted on-demand when requested.
- [Update a customer profile within Flow workflows](https://devx.notabene.id/reference/updateflowcustomer.md): Updates an existing customer profile within a Flow workflow context. Customer PII is automatically encrypted before storage when profile data is updated. Only specified fields are updated, maintaining data integrity.  **IVMS101 Validation Requirements (when profileData is provided):** - Same validation rules as POST apply when updating profileData - For natural persons: `name` object is **required** - For legal persons: `name` and `nationalIdentification` objects are **required** - When `nameIdentifier` array is provided, its fields are **required** - Unknown fields are rejected (strict validation)
- [Delete a customer profile within Flow workflows](https://devx.notabene.id/reference/deleteflowcustomer.md): Permanently removes a customer profile from a Flow workflow context. This action cannot be undone and will remove all associated customer data and PII.
- [Create a new payin for a customer within Flow workflows](https://devx.notabene.id/reference/createflowcustomerpayin.md): Creates a new payin transaction for a customer within a Flow workflow context. This endpoint initiates a payment workflow where the customer (merchant) can receive payments. The payin includes invoice data, supported assets, and generates a payment link for customer interaction.
- [List payins for a specific customer within Flow workflows](https://devx.notabene.id/reference/listflowcustomerpayins.md): Retrieves a paginated list of payin transactions for a specific customer within Flow workflows. This endpoint filters payins by the customer (merchant) and supports filtering by client references and Flow workflow states.
- [Get a specific payin for a customer within Flow workflows](https://devx.notabene.id/reference/getflowcustomerpayin.md): Retrieves detailed information about a specific payin transaction for a customer within a Flow workflow context. This endpoint verifies that the payin belongs to the specified customer and returns comprehensive transaction details.
- [Create a new payout for a customer within Flow workflows](https://devx.notabene.id/reference/createflowcustomerpayout.md): Creates a new payout transaction for a customer within a Flow workflow context. This endpoint initiates a payout workflow where the customer can receive funds by selecting a wallet and specifying where they want the funds sent.
- [List payouts for a specific customer within Flow workflows](https://devx.notabene.id/reference/listflowcustomerpayouts.md): Retrieves a paginated list of payout transactions for a specific customer within Flow workflows. This endpoint filters payouts by the customer and supports filtering by client references and Flow workflow states.
- [Get a specific payout for a customer within Flow workflows](https://devx.notabene.id/reference/getflowcustomerpayout.md): Retrieves detailed information about a specific payout transaction for a customer within a Flow workflow context. This endpoint verifies that the payout belongs to the specified customer and returns comprehensive transaction details.
- [List payins for an entity with optional ref-based filtering](https://devx.notabene.id/reference/listflowpayins.md): Retrieves a paginated list of payin transactions for an entity within Flow workflows. Supports filtering by client references and Flow workflow states. Client references are automatically converted to database references by adding the 'flow-' prefix.
- [Create a new payin within Flow workflows (entity-level)](https://devx.notabene.id/reference/createflowpayin.md): Creates a new payin transaction within a Flow workflow context. The payin includes invoice data, supported assets, fallback settlement addresses, and generates a payment link for customer interaction.
- [List incoming payins for an entity (as responder)](https://devx.notabene.id/reference/listflowincomingpayins.md): Retrieves a paginated list of incoming payin transactions where the entity acts as the responder within Flow workflows. These are payins initiated by other entities that this entity needs to respond to. Supports filtering by client references and Flow workflow states.
- [List outgoing payins for an entity (as initiator)](https://devx.notabene.id/reference/listflowoutgoingpayins.md): Retrieves a paginated list of outgoing payin transactions where the entity acts as the initiator within Flow workflows. These are payins initiated by this entity to other entities. Supports filtering by client references and Flow workflow states.
- [Get a specific payin by ID (entity-level)](https://devx.notabene.id/reference/getflowpayin.md): Retrieves detailed information about a specific payin transaction within a Flow workflow. This includes the payin status, asset details, amounts, and associated workflow data.
- [Authorize payin by confirming settlement address and optional asset](https://devx.notabene.id/reference/authorizeflowpayin.md): Authorizes a payin by providing a settlement address and, optionally, the asset. Requirements depend on whether the entity is initiator or responder in the workflow.
- [Notify that web authorization is required for a payin](https://devx.notabene.id/reference/payinauthorizationrequired.md): Emits an AuthorizationRequired action for a PAYIN Flow transfer. The responding party supplies a web `authorizationUrl` that the initiator must present to the customer for confirmation before continuing the payment.
- [List payouts for an entity with optional ref-based filtering](https://devx.notabene.id/reference/listflowpayouts.md): Retrieves a paginated list of payout transactions for an entity within Flow workflows. Supports filtering by client references and Flow workflow states. Client references are automatically converted to database references by adding the 'flow-' prefix.
- [Create a new payout within Flow workflows (entity-level)](https://devx.notabene.id/reference/createflowpayout.md): Creates a new payout transaction within a Flow workflow context. This endpoint initiates a payout workflow where the merchant can receive funds by selecting a wallet and specifying where they want the funds sent.
- [List incoming payouts for an entity (as responder)](https://devx.notabene.id/reference/listflowincomingpayouts.md): Retrieves a paginated list of incoming payout transactions where the entity acts as the responder within Flow workflows. These are payouts initiated by other entities that this entity needs to respond to. Supports filtering by client references and Flow workflow states.
- [List outgoing payouts for an entity (as initiator)](https://devx.notabene.id/reference/listflowoutgoingpayouts.md): Retrieves a paginated list of outgoing payout transactions where the entity acts as the initiator within Flow workflows. These are payouts initiated by this entity to other entities. Supports filtering by client references and Flow workflow states.
- [Get a specific payout by ID (entity-level)](https://devx.notabene.id/reference/getflowpayout.md): Retrieves detailed information about a specific payout transaction within a Flow workflow. This includes the payout status, asset details, amounts, and associated workflow data.
- [Authorize payout by selecting asset and optional settlement address](https://devx.notabene.id/reference/authorizeflowpayout.md): Authorizes a payout by confirming the asset to be used and, optionally, a settlement address. Requirements depend on whether the entity is initiator or responder in the workflow.
- [Notify that web authorization is required for a payout](https://devx.notabene.id/reference/payoutauthorizationrequired.md): Sends an AuthorizationRequired signal for a PAYOUT Flow transfer. The responder provides a web `authorizationUrl` that the initiator should present to the customer for approval. Optionally an `expires` ISO timestamp can be provided; if omitted, a default TTL (1 hour) is applied by the server.
