컴플라이언스 서비스 — 규제 대응에 필요한 솔루션·벤더 연동을 전담하는 별도 서비스 — 의 범위·경계 결정을 기록한다.
트래블룰의 메커니즘·시나리오·배치는 [트래블룰 설계 세트](../../트래블룰/설계/00-screening-order.md)에 있고, 이 세트는 **서비스로서의 계약**만 담는다.

## 무엇을 하는 서비스인가

월렛 백엔드의 규제 확인 요청을 받아 **솔루션 왕복을 대행**하고, 솔루션 원어를 공통 어휘(TrVerdict·검증 기록)로 번역해 돌려준다.
반대 방향도 이 서비스가 받는다 — 상대 VASP 발 **사전 검증 수신**을 대기함(컴플라이언스 DB)에 쌓아 두고, 입금 도착 시 월렛의 확인 질의에 대조 결과로 답한다. 목록 동기화·PENDING 만료 스캔 같은 **주기 배치**도 이 서비스 소관이다([1장](01-interface.md)).

```
월렛 백엔드 ──(확인 요청 · TrVerdict/증적 수신)──▶ 컴플라이언스 서비스 ──(솔루션 어댑터)──▶ VerifyVASP · Notabene(Fireblocks) · Address Registry
월렛 백엔드 ◀──(주소 귀속·실명 확인 조회)── 컴플라이언스 서비스(대기함 적재) ◀──(사전 검증 수신)── 상대 VASP
```

이름을 트래블룰이 아니라 **컴플라이언스**로 잡은 이유 — 분리 근거(회사 단위 자원·규제 교체 축·복수 상품 공유, [트래블룰 8장](../../트래블룰/설계/08-gate-port.md))가 트래블룰만이 아니라 컴플라이언스 전반의 성질이다. 정체는 컴플라이언스 **판단 엔진이 아니라, 솔루션·벤더 연동 창구이자 수신 기록(대기함)의 보관소**다.

## 모듈

| 모듈 | 상태 | 상세 |
|---|---|---|
| **트래블룰 게이트** — 라우터 + 솔루션 어댑터(VerifyVASP·Notabene·개인지갑), 수신 컴포넌트, Enclave 짝, 대기함(컴플라이언스 DB) | 첫 모듈 (현재 유일) | [트래블룰 8장](../../트래블룰/설계/08-gate-port.md) |
| AML·OFAC | 미수용 — 지금은 벤더(Fireblocks) 안 별개 통합으로 남는다 | [트래블룰 6장](../../트래블룰/설계/06-verifyvasp-parallel-gate.md) |

## 경계 — 귀속·가용 전이 판단은 월렛 백엔드

- **대기함·1차 대조는 이 서비스, 귀속·가용 전이는 월렛 백엔드** — 사전 검증 기록(대기함)은 수신한 자리(컴플라이언스 DB)에 두고, 입금 도착 시 월렛의 Create Deposit Check 질의에 대조 결과로 답한다. 주소↔계정 귀속과 잔고 가용 전이는 그 데이터의 주인인 월렛이 한다.
- **출금 상태 흐름도 월렛 백엔드** — 이 서비스는 verdict(TrVerdict)를 돌려줄 뿐 출금 상태를 갖지 않는다.
- **자산 이동 경로와 무관** — 제출·서명·전파는 블록체인 매니저 소관. 이 서비스의 벤더 호출(validate/full)은 자산이 움직이지 않는 검증 전용 경로다.

## 소유 자원

- **설치물** — VerifyVASP Enclave(벤더 강제 · 키·PII), 트래블룰 수신 컴포넌트(인바운드 접점 · 얇게), CODE-Cipher(조건부).
- **자격증명** — Fireblocks 스크리닝 전용 API user (validate/full 용도 전용 · 서명 능력 없는 role · TAP 차단 · IP 제한 — [트래블룰 8장](../../트래블룰/설계/08-gate-port.md)). 키는 시크릿 스토어/KMS.
- **Address Registry 왕복** — 개인지갑 등록·해제·소유 증명의 벤더 반영과 조회. 등록 화면·소유 인증 UX·등록 유도 정책은 월렛 몫.
- **컴플라이언스 DB** — 목록 스냅샷 · check 상태 · 대기함 · 개인지갑 등록. 테이블 초안은 [2장](02-database.md).
- **물리 배치** — [트래블룰 12장](../../트래블룰/설계/12-physical-layout.md) · [인프라 0장](../../인프라/설계/00-overview.md).

## 열린 결정

1. **컴플라이언스 DB 의 범위** — 확정 세 가지: **목록 스냅샷**(수취 거래소 목록 제공용 — 솔루션 목록을 주기 동기화, 우리 발급 counterpartyId 매핑 보관), **check 상태**(checkId·verdict·요청 본문 해시 — 멱등 409 대조용), **대기함**(입금 사전 검증 기록 — 대조 키·verificationRef·txHash. PII 없음 — 원문은 Enclave·벤더 보관). verdict 이력·감사 기록(솔루션 원어 근거)을 얼마나 둘지는 미정. 테이블 초안은 [2장](02-database.md).
2. **목록 동기화 주기** — 주기 값과 수동 갱신 트리거.
3. **입금 확인 장애 시 태도** — 대기함이 이 서비스에 있으므로, 서비스 장애 중 도착한 입금의 가용 전이를 어떻게 할지(보류가 기본 후보). 시간 값은 [트래블룰 4장](../../트래블룰/설계/04-policy-and-timing.md) 국내 시간 규칙과 함께 정한다.
4. **다음 모듈 수용 기준** — AML·OFAC 을 벤더 통합에서 이 서비스로 옮기는 판단 조건.
