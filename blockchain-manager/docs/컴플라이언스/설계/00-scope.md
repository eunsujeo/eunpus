컴플라이언스 서비스 — 규제 대응에 필요한 망·벤더 연동을 전담하는 별도 서비스 — 의 범위·경계 결정을 기록한다.
트래블룰의 메커니즘·시나리오·배치는 [트래블룰 설계 세트](../../트래블룰/설계/00-screening-order.md)가 정본이고, 이 세트는 **서비스로서의 계약**만 담는다.

## 무엇을 하는 서비스인가

월렛 백엔드의 규제 확인 요청을 받아 **망 왕복을 대행**하고, 망 원어를 공통 어휘(TrVerdict·검증 기록)로 번역해 돌려준다.

```
월렛 백엔드 ──(확인 요청 · TrVerdict/증적 수신)──▶ 컴플라이언스 서비스 ──(망 어댑터)──▶ VerifyVASP · Notabene(Fireblocks) · Address Registry
```

이름을 트래블룰이 아니라 **컴플라이언스**로 잡은 이유 — 분리 근거(회사 단위 자원·규제 교체 축·복수 상품 공유, [트래블룰 8장](../../트래블룰/설계/08-gate-port.md))가 트래블룰만이 아니라 컴플라이언스 전반의 성질이다. 정체는 컴플라이언스 **판단 엔진이 아니라 망·벤더 연동 창구**다.

## 모듈

| 모듈 | 상태 | 정본 |
|---|---|---|
| **트래블룰 게이트** — 라우터 + 망 어댑터(VerifyVASP·Notabene·개인지갑), 수신 컴포넌트, Enclave 짝 | 첫 모듈 (현재 유일) | [트래블룰 8장](../../트래블룰/설계/08-gate-port.md) |
| AML·OFAC | 미수용 — 지금은 벤더(Fireblocks) 안 별개 통합으로 남는다 | [트래블룰 6장](../../트래블룰/설계/06-verifyvasp-parallel-gate.md) |

## 경계 — 판단은 월렛 백엔드

- **매칭·검증·귀속 판단과 대기함은 월렛 백엔드** — Travel Rule 정보 ↔ 입출금 tx 대조는 tx·주소·잔고의 주인이 한다. 이 서비스는 판정 재료만 넘긴다.
- **출금 상태 흐름·잔고 가용 전이도 월렛 백엔드** — 이 서비스는 판정(TrVerdict)을 돌려줄 뿐 출금 상태를 갖지 않는다.
- **자산 이동 경로와 무관** — 제출·서명·전파는 블록체인 매니저 소관. 이 서비스의 벤더 호출(validate/full)은 자산이 움직이지 않는 검증 전용 경로다.

## 소유 자원

- **설치물** — VerifyVASP Enclave(벤더 강제 · 키·PII), 트래블룰 수신 컴포넌트(인바운드 접점 · 얇게), CODE-Cipher(조건부).
- **자격증명** — Fireblocks 스크리닝 전용 API user (validate/full 용도 전용 · 서명 능력 없는 role · TAP 차단 · IP 제한 — [트래블룰 8장](../../트래블룰/설계/08-gate-port.md)). 키는 시크릿 스토어/KMS.
- **물리 배치** — [트래블룰 12장](../../트래블룰/설계/12-physical-layout.md) · [인프라 0장](../../인프라/설계/00-overview.md).

## 열린 결정

1. **자체 DB 의 범위** — 판정 이력·감사 기록(망 원어 근거 보존)을 이 서비스 DB 에 얼마나 둘지. 대기함은 월렛 백엔드로 확정이므로 여기 없다.
2. **다음 모듈 수용 기준** — AML·OFAC 을 벤더 통합에서 이 서비스로 옮기는 판단 조건.
