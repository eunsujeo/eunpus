컴플라이언스 게이트 — 규제 대응에 필요한 솔루션·벤더 연동을 전담하는 별도 서비스 — 의 범위·경계 결정을 기록한다.
트래블룰의 메커니즘·시나리오·배치는 [트래블룰 설계 세트](../../트래블룰/설계/00-screening-order.md)에 있고, 이 세트는 **서비스로서의 계약**만 담는다.

## 무엇을 하는 서비스인가

DAW-CORE의 규제 확인 요청을 받아 **솔루션 왕복을 대행**하고, 솔루션 원어를 공통 어휘(TrVerdict·검증 기록)로 번역해 돌려준다.
반대 방향도 이 서비스가 받는다 — 상대 VASP 발 **사전 검증 수신**을 사전 검증 기록(컴플라이언스 DB)에 쌓아 두고, 입금 도착 시 DAW-CORE의 확인 질의에 대조 결과로 답한다. 목록 동기화·PENDING 만료 스캔 같은 **주기 배치**도 이 서비스 소관이다([3장](03-operations.md)).

```
DAW-CORE ──(확인 요청 · TrVerdict/증적 수신)──▶ 컴플라이언스 게이트 ──(솔루션 어댑터)──▶ VerifyVASP · Notabene(Fireblocks)
DAW-CORE ◀──(주소 귀속·실명 확인 조회)── 컴플라이언스 게이트(사전 검증 기록 적재) ◀──(사전 검증 수신)── 상대 VASP
```

이름을 트래블룰이 아니라 **컴플라이언스**로 잡은 이유 — 분리 근거(회사 단위 자원·규제 변경 흡수·복수 상품 공유, [트래블룰 8장](../../트래블룰/설계/08-gate-port.md))가 트래블룰만이 아니라 컴플라이언스 전반의 성질이다. 정체는 컴플라이언스 **판단 엔진이 아니라, 솔루션·벤더 연동 창구이자 수신한 사전 검증 기록의 보관소**다.

## 모듈

| 모듈 | 상태 | 상세 |
|---|---|---|
| **트래블룰 게이트** — 라우터 + 솔루션 어댑터(VerifyVASP·Notabene), 수신 콜백 엔드포인트, Enclave 짝, 사전 검증 기록(컴플라이언스 DB) | 첫 모듈 (현재 유일) | [트래블룰 8장](../../트래블룰/설계/08-gate-port.md) |
| **AML·OFAC** — AML 스크리닝(Chainalysis·Elliptic) · OFAC 제재 주소 차단 | 다음 모듈 후보 — 지금은 벤더(Fireblocks) 안 별개 통합으로 남는다. 이 서비스로 옮기는 기준은 열린 결정 5 | [트래블룰 6장](../../트래블룰/설계/06-verifyvasp-parallel-gate.md) |

## 경계 — 귀속·가용 전이 판단은 DAW-CORE

- **사전 검증 기록·1차 대조는 이 서비스, 귀속·가용 전이는 DAW-CORE** — 상대 VASP 발 사전 검증 기록은 수신한 자리(컴플라이언스 DB)에 두고, 입금 도착 시 DAW-CORE의 Create Deposit Check 질의에 대조 결과로 답한다. 주소↔계정 귀속과 잔고 가용 전이는 그 데이터의 주인인 DAW-CORE가 한다.
- **출금 상태 흐름도 DAW-CORE** — 이 서비스는 verdict(TrVerdict)를 돌려줄 뿐 출금 상태를 갖지 않는다.
- **개인지갑 출금은 이 서비스에 오지 않는다** — 등록 지갑 확인(등록·소유 인증된 본인 지갑 목록)은 고객 데이터의 주인인 DAW-CORE가 자체 처리한다. 이 서비스는 거래소(VASP) 상대 트래블룰만 다룬다.
- **자산 이동 경로와 무관** — 제출·서명·전파는 블록체인 매니저 소관. 이 서비스의 벤더 호출(validate/full)은 자산이 움직이지 않는 검증 전용 경로다.

## 소유 자원

- **설치물** — VerifyVASP Enclave(벤더 강제 · 키·PII), CODE-Cipher(조건부). 상대 발신의 수신은 Enclave 가 이 서비스의 수신 콜백을 내부망으로 호출한다.
- **자격증명** — Fireblocks 스크리닝 전용 API user (validate/full 용도 전용 · 서명 능력 없는 role · TAP 차단 · IP 제한 — [트래블룰 8장](../../트래블룰/설계/08-gate-port.md)). 키는 시크릿 스토어/KMS.
- **컴플라이언스 DB** — VASP 레지스트리(솔루션 목록 · `cmpl_vasp_id` · 코어 `vasp_id` 매핑 · 활성화) · check 상태 · 사전 검증 기록. VASP 정체·거래 허용은 DAW-CORE의 VASP 마스터(`daw_vasp_m`) 몫이다. 테이블 초안은 [2장](02-database.md).
- **물리 배치** — [트래블룰 12장](../../트래블룰/설계/12-physical-layout.md) · [전체 배치(BC 인프라)](../../BC/설계/01-infra.md).

## 열린 결정

1. **컴플라이언스 DB 의 범위** — 확정 세 가지: **VASP 레지스트리**(동기화가 받아 둔 솔루션 목록에 `cmpl_vasp_id` 발급 + 활성화 때 코어 `vasp_id` 매핑 — 허용 판단·VASP 정체는 DAW-CORE VASP 마스터 몫 · [2장](02-database.md)), **check 상태**(checkId·verdict·요청 본문 해시 — 멱등 409 대조용), **사전 검증 기록**(입금 사전 검증 기록 — 대조 키·verificationRef·txHash. PII 없음 — 원문은 Enclave·벤더 보관). verdict 이력·감사 기록(솔루션 원어 근거)을 얼마나 둘지는 미정. 테이블 초안은 [2장](02-database.md).
2. **목록 동기화 주기** — 주기 값과 수동 갱신 트리거.
3. **입금 확인 장애 시 태도** — 사전 검증 기록이 이 서비스에 있으므로, 서비스 장애 중 도착한 입금의 가용 전이를 어떻게 할지(보류가 기본 후보). 시간 값은 [트래블룰 4장](../../트래블룰/설계/04-policy-and-timing.md) 국내 시간 규칙과 함께 정한다.
4. **Admin 운영 경로** — 솔루션 목록 동기화·VASP 온보딩(목록 조회·활성화·해제)은 설계됨(3장 운영 API 4개). 거래 허용(고객 화면 노출)은 DAW-CORE VASP 마스터(`daw_vasp_m`)가, 라우팅 활성화·매핑은 이 서비스가 나눠 갖는다. 남은 후보: check 운영 조회("왜 아직 확인 중인가" — 진행 상세·증적은 이 서비스에 있다) · 감사 기록 열람. 운영 요구가 확정되면 설계한다.
5. **다음 모듈 수용 기준** — AML·OFAC 을 벤더 통합에서 이 서비스로 옮기는 판단 조건.
