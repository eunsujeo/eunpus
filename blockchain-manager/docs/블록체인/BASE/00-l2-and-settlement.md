Base 는 Coinbase 가 운영하는 이더리움 L2 다. 실행은 Base 가 하고 기록은 이더리움에 남긴다.
빨라지는 대신 확정이 두 층이 되고, 입금 임계를 어디에 둘지가 그 두 층 사이의 선택이 된다.

이 글은 [이더리움 0~2장](../이더리움/00-block-lifecycle.md)을 읽었다는 전제로 쓴다. 블록·컨펌·finality·ERC-20 은 그쪽 정의를 그대로 쓴다.

## 1. 왜 L2 인가

이더리움의 블록 공간은 가스 한도로 묶여 있고, 붐비면 팁을 올려야 포함된다(이더리움 0장 2절). 모든 트랜잭션이 이 한 줄에 서는 구조라 소액·잦은 거래에는 비싸다.

L2 는 이 줄을 벗어나는 방법이다. 트랜잭션 실행은 이더리움 밖의 별도 체인이 하고, 그 **데이터만 이더리움에 기록**한다. 실행 비용은 낮아지고, 기록이 이더리움에 있으므로 자산의 안전은 이더리움 수준에 기댄다. Base 는 이 방식(OP Stack 롤업)으로 Coinbase 가 만들어 2023년 8월부터 운영하는 L2 다.

## 2. 구조 — 실행은 Base 에서, 기록은 이더리움에

Base 에는 이더리움의 슬롯·추첨·에폭이 없다. 블록을 만드는 주체는 **시퀀서** 하나다.

- **시퀀서** — Coinbase 가 운영하는 단일 노드가 트랜잭션을 받아 **2초마다** 블록을 만든다. 이더리움 0장의 제안자 추첨을 운영 주체 하나가 대신하는 셈이다. 2025년부터는 2초 블록을 200ms 단위 열 조각으로 쪼개 미리 확인해 주는 flashblocks 도 켜져 있다.
- **배치 기록** — 시퀀서가 만든 블록들의 데이터를 묶어(배치) 이더리움에 blob 으로 정기적으로 기록한다. 이 기록이 있으면 시퀀서가 사라져도 누구든 이더리움에 실린 데이터에서 Base 체인 전체를 다시 만들 수 있다. "보안을 이더리움에 기댄다"의 실체가 이 성질이다.

## 3. 같은 것들 — EVM 그대로

Base 는 EVM 호환이라 이더리움에서 배운 것 대부분이 그대로 적용된다.

- 계정(EOA·컨트랙트)·트랜잭션 필드·가스·receipt 의 동작이 이더리움과 같다
- USDC 는 Base 에 **네이티브 발행**된다 — 이더리움에서 브리지된 복제본이 아니라 Circle 이 Base 위에 직접 발행·상환하는 컨트랙트다 (2023년 9월부터). decimals 6, Transfer 이벤트, 동결 기능 모두 [2장](../이더리움/02-erc20.md)과 동일
- 따라서 토큰 입금 감지 코드(이벤트를 보고 receipt 로 확인)는 재사용된다. 달라지는 것은 어느 노드에 묻는가와, 아래의 확정 기준뿐이다

## 4. 다른 것 — 확정이 두 층

이더리움 1장에서 확정은 한 체인 안의 문제였다. Base 에서는 층이 두 개다 — Base 자체의 빠른 확인과, 데이터가 이더리움에 실려 이더리움 finality 까지 받는 확정.

| 태그 | 뜻 | 걸리는 시간 |
|---|---|---|
| `latest` (unsafe) | 시퀀서가 만든 최신 블록. 데이터가 아직 이더리움에 없다 — **시퀀서의 약속** | 약 2초 |
| `safe` | 블록 데이터가 배치로 이더리움에 실렸다. 이더리움이 reorg 되면 뒤집힐 수 있다 | 보통 5~10분 |
| `finalized` | 배치를 실은 이더리움 블록이 finality 에 도달했다 — 이더리움 1장의 보증 그대로 | 약 15~20분 |

```anim
l2-settlement
```

이름은 이더리움 1장의 태그와 같지만 뜻이 다르다는 점을 조심해야 한다. 이더리움의 latest 는 "방금 나온 진짜 블록"이지만, Base 의 latest(unsafe)는 **아직 이더리움에 기록되지 않은, 시퀀서만 아는 상태**다. 시퀀서는 단일 운영 주체라 장애나 오류가 나면 이 구간이 흔들린다. safe 부터는 이더리움에 기록된 데이터가 근거라서 시퀀서를 믿을 필요가 없어진다.

## 5. 입금 임계 관점

이더리움 1장 6절의 임계 교환이 Base 에서는 세 선택지가 된다.

| 기준 | 대기 시간 | 전제 |
|---|---|---|
| 시퀀서 확인 (unsafe) | 약 2초 | 시퀀서가 약속을 지킨다는 신뢰 |
| safe | 보통 5~10분 | 이더리움에 실림. 이더리움 reorg 잔여 위험만 남음 |
| finalized | 약 15~20분 | 이더리움 finality — 잔여 위험 사실상 0 |

Base 는 블록이 2초마다 나와서 컨펌 "수"를 세면 숫자만 커지고 의미가 없다. 임계는 수가 아니라 **태그 기준**으로 정하는 것이 자연스럽다 — 몇 블록 쌓였는가 대신, 내 트랜잭션의 데이터가 이더리움의 어느 단계까지 갔는가를 본다.
