정책 변경의 증적(누가·언제·무엇을)과 이 서비스가 쥐는 자격을 정리한다.
기록은 추가만 하는(append-only) 로그이고, 자격은 정책 편집용 벤더 API user 하나다.

## 감사 기록 — 요청마다 한 건

| 남기는 것 | 내용 |
|---|---|
| 요청자 | Admin 백엔드가 전달한 운영자 식별 — 호출 주체는 service-to-service 인증으로 확인 |
| 요청 원문 | 오퍼레이션 · 정책 유형 · 드래프트 규칙 원문 |
| 벤더 응답 | 갱신·게시 요청에 대한 벤더 응답 원문 |
| 스냅샷 | 게시 요청 시점의 드래프트 · 발효 확인 시점의 활성 정책 |

- 기록은 추가만 한다 (append-only).
- **발효 대조** — 게시 요청 스냅샷과 발효 후 활성 정책을 비교한다(1장). 다르면 벤더 Console 쪽에서 수정된 채 승인된 것 — 경보를 올리고 수동 확인한다.

## 자격

| 자격 | 역할 | 위치 |
|---|---|---|
| 정책 편집용 벤더 API user | Policy Editor 편집·게시 요청 · Compliance 조회 | 이 서비스 |
| 거래 제출용 벤더 API user | 거래 생성·조회 | 블록체인 매니저 ([0장](../../블록체인매니저/설계/00-cast.md)) |

- 호출측은 Admin 백엔드 하나 — service-to-service 인증으로 확인한다.
- 편집용 API user 의 발급·회수는 벤더 Console 의 사용자 관리(Admin Quorum + Owner 승인) — 이 문서 범위 밖.

## 열린 결정

1. **감사 기록 저장소** — 서비스 전용 DB vs Admin 감사 체계 합류.
2. **운영자 식별 전달 형태** — Admin 백엔드 세션의 운영자 ID 를 요청에 실어 줄지, s2s 토큰의 claim 으로 줄지.
