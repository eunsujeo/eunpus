설계 전반에서 나온 **Fireblocks 확인 항목**을 한자리에 모은다. 공식 문서에 없어 CSM 문의로만 풀리는 것들이다.
항목의 배경은 오른쪽 장에 있고, 답이 확정되면 해당 장에 반영하고 이 목록에서 지운다.

## 문의 목록

| # | 질문 | 배경 |
|---|---|---|
| 1 | **트래블룰 대상 여부를 원화 100만원 기준으로 판정할 수 있는가** — 한국 기준은 원화 환산 100만원인데 `validate/full` 판별에는 `AmountUSD` 만 보인다. 원화 기준 판정을 지원하는가, 아니면 우리가 환산해 자체 판정해야 하는가 | 2장 · 6장 비교표 |
| 2 | **Notabene 직접 통합과 TRLink 제공자(Sumsub 등)의 병행 가능 여부** — 연결 가능 목록에 병렬로 있으나 명시가 없다 | 6장 · 10장 |
| 3 | **트래블룰 메시지를 빠뜨린 출금을 벤더가 막아 주는 설정이 있는가** — 대상 출금에 `travelRuleMessage` 를 동봉하지 않으면 기본 동작은 검사 우회(그대로 통과)다. 벤더 층에 차단 설정이 없으면 빠뜨림을 막는 강제선은 우리 층 둘(출금 상태 흐름의 순서 강제·서명 직전 검증)뿐이다 | 2장 |
| 4 | **GTR 상대 커버리지** — Fireblocks 의 GTR 제공자가 globaltravelrule.com 의 GTR 과 동일 솔루션인가. Sumsub 경유 시 원화 임계·역추적 등 솔루션 전용 기능이 보존되는가 | 10장 |
| 5 | **검사 제외 사유 "초기 정보 없음"에 드는 조건이 정확히 무엇인가** — 이 분류에 들어간 거래는 검사 없이 통과하는데, 어떤 거래가 "판정에 필요한 기초 정보가 없다"로 분류되는지 경계가 문서에 없다 (예: `travelRuleMessage` 미동봉 거래가 여기 드는가) | 4장 |
| 6 | **가격·SLA** — Compliance(premium) 구독 조건 · Notabene 측 계약. Notabene API 문서는 비공개라 CSM 경유로 접근한다 | 1장 |

## 같은 채널로 묻는 것 — Notabene

- **게이트웨이 경유 VerifyVASP 도달** — 직접 연동(경로 B)의 대체 후보. 라이브 지원 여부부터 벤더 확인이 선결이며, 검증 흐름·체크리스트는 9장.

VerifyVASP(람다256)에 확인할 것은 6장 미확정 절과 13장(부록 B)에 있다.
