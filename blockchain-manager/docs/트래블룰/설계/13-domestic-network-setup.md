국내 도입이 확정이라, 1장(Notabene 연동)에 대응하는 국내 솔루션 연동 준비를 정리한다. 국내 도달은 VerifyVASP 직접 연동(6장 경로 B)이 기준이고, CODE 회원은 상호연동 경유라 별도 준비가 없다(상호연동 실효가 부족할 때만 CODE 직접 준비 — 아래).
1장 Notabene 이 코드 0줄·SaaS 연결이었다면, 이쪽은 **자체 인프라에 설치물을 두고 운영**하는 것이 핵심 차이다.

## 준비 순서

1. **회원 가입·가격 확정** — 아래 "확인 필요"의 미확정 해소가 선행.
2. **Enclave 설치** — 아래 요건 표.
3. **수신 콜백 구현** — Enclave 가 호출하는 VASP API 를 컴플라이언스 서비스 엔드포인트로(아래).
4. **VerifyVASP 어댑터 연결** — 컴플라이언스 서비스 안(8장).
5. **테스트** — RobotVASP E2E·입출금 시나리오 테스트(공식 문서에 테스트 절차 제공).

## 준비 대상 — 둘

- **설치형 Enclave 서버** — VerifyVASP 가 강제하는 별도 배포물. 암호화 키·PII 를 우리 인프라에서 보관·처리한다(6·12장).
- **수신 콜백 엔드포인트** — Enclave 가 호출하는 VASP API 를 컴플라이언스 서비스가 구현한다. 별도 배포 없음(8장).

Notabene 은 이 둘이 없다 — SaaS 라 자체 설치물이 없고 인바운드도 벤더가 처리한다.

## 확정된 Enclave 요건 (공식 문서 확인분)

| 항목 | 요건 |
|---|---|
| 배포 | AWS ECR Docker |
| DB | 5종 (기본 MySQL) |
| 포트 | Enclave 21117 |
| 네트워크 | 공개 HTTPS 엔드포인트 + 중앙 서버발 인바운드 허용 + IP 화이트리스트 |
| 키 보관 | env 또는 HSM |

## 수신 콜백 — 컴플라이언스 서비스의 엔드포인트

- Enclave 가 호출하는 **VASP API 구현** — Verify User · User Account Verification · Callback · Check Transaction Status.
- 콜백은 **얇게** 둔다 — 검증·변환 후 서비스 내부 처리로 넘긴다. 사전 검증 기록·1차 대조는 컴플라이언스 서비스, 귀속 판단·가용 전이는 DAW-CORE다(8장 경계).
- 별도 배포 이유 — 기관 간 콜백 트래픽의 인바운드 접점을 얇게 분리(장애 격리·배포 주기).

## 우리가 새로 지는 것

- **키·PII 보관처가 우리 쪽에 생긴다** — Notabene(벤더 보관)과 달리 평문 PII·키가 우리 Enclave 안에 있다. 보안·감사 책임이 따라온다(12장 자격증명 격리와 같은 선).
- **운영 부담** — Enclave 설치·HA·모니터링. Fireblocks 스크리닝용 전용 API user 자격증명과도 별개다(12장).

| | Notabene (해외 · 1장) | VerifyVASP (국내 · 이 장) |
|---|---|---|
| 성격 | SaaS 연결 | 자체 인프라 설치·운영 |

## CODE 는?

기본은 VerifyVASP↔CODE 상호연동 경유라 **별도 준비 없음**이다(빗썸·코인원·코빗에 VerifyVASP 로 도달). 단 상호연동 실효(원화 임계·TXID 역추적 등)가 부족하면 **CODE 직접 준비**가 필요하다 — CODE-Cipher(설치형 암호화 모듈) 설치. 조건부 판단은 6장 비교표·11장 부록 A.

## 확인 필요 — 미확정(6장)

- **VerifyVASP 가격·회원 가입 조건**.
- **Enclave HA·스케일링·권장 사양** — 공식 문서에 없음.
- **운영 대행(managed) 옵션 존재 여부** — 없으면 자체 운영이 필수(PII 를 회원 인프라에만 두는 솔루션 구조상 대행이 어려울 수 있음).
- **VerifyVASP↔CODE 상호연동 실효** — CODE 직접 준비 여부를 가른다.
