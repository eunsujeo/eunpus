서비스 도입·개발·변경에서 보안·개인정보 요구사항을 정의하고 검토·시험·승인된 코드만 운영으로 이관한다.

## 개발 생명주기

1. 요구사항: 데이터·권한·외부연계·오용사례와 법적 요구를 정의한다.
2. 설계: 위협모델과 신뢰경계, 실패 차단, 감사·복구 방식을 검토한다.
3. 구현: 안전한 코딩, 비밀값 금지와 승인된 의존성을 적용한다.
4. 검증: 코드리뷰, 자동검사, 보안·기능·권한·실패 시험을 수행한다.
5. 이관: 변경·배포 승인, artifact 무결성, 롤백과 관찰계획을 확인한다.
6. 운영: 취약점·사고·지표를 개발 요구사항에 다시 반영한다.

## 환경과 데이터 분리

개발·시험·운영 계정, 네트워크, 자격과 데이터를 분리한다. 운영 개인정보·키·인증정보를 시험에 사용하지 않는다. 불가피한 운영데이터 사용은 최소화·비식별·승인·접근·파기와 검증을 기록한다.

## 소스와 공급망

개인별 계정, MFA, 최소권한, 보호 브랜치와 필수 리뷰를 적용한다. 의존성·컨테이너·빌드 도구의 출처와 취약점을 관리하고, 빌드·배포 artifact의 생성 주체와 무결성을 추적한다.

## 중요 변경

키·서명·출금·정책·주소·권한·개인정보·로그·백업 통제를 바꾸는 변경은 강화된 리뷰와 승인, 사전·사후 검증을 적용한다. 긴급변경도 사유·위험·실행자·결과를 기록하고 정해진 기한에 사후 승인·검토한다.

## 증적

보안 요구사항, 위협모델, 코드리뷰·검사·시험, 변경·배포 승인, artifact·롤백·사후확인과 긴급변경 검토 기록을 보관한다.
