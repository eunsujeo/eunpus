입금과 출금의 요청·검증·승인·서명·전파·확정·대사를 하나의 추적 가능한 상태 흐름으로 관리한다.

## 공통 원칙

- 업무 원장과 상태 전이의 정본을 지정한다.
- 동일 요청의 중복·재생·순서 역전을 식별한다.
- 금액·자산·네트워크·주소·수수료·정책의 정규화된 값으로 승인을 묶는다.
- 승인 후 핵심 값이 바뀌면 기존 승인을 폐기하고 다시 승인한다.
- 컴플라이언스·정책·원장 확인 실패 시 자산 이동을 진행하지 않는다.

## 입금

지원 네트워크·자산·주소를 확인하고 승인된 확인수·finality 기준으로 반영한다. 재조직, 잘못된 네트워크·memo, 미지원 자산, 위험 주소와 트래블룰 미확정 입금을 격리한다. 내부 원장, 벤더와 온체인 수량·상태를 대사한다.

## 출금

1. 인증된 요청자의 계정·잔액·한도·주소·네트워크를 확인한다.
2. KYC·AML·KYT·제재·트래블룰과 이상거래 정책을 평가한다.
3. 금액·위험·변경 유형에 맞는 maker-checker·정족수 승인을 받는다.
4. 승인 intent와 Fireblocks 요청·Co-signer raw transaction을 대조한다.
5. 서명·전파 후 tx hash, receipt·finality와 실패·대체 거래를 추적한다.
6. 고객 원장·벤더·온체인·수수료를 대사하고 예외를 종결한다.

## 정책과 비상통제

허용주소, 자산·네트워크, 금액·시간·속도, 컨트랙트·함수와 관리자 정책을 버전 관리한다. 정책 완화, 주소 추가, 고액·긴급 출금은 강화된 승인과 지연·알림을 적용한다. 출금 중지·Workspace freeze·자격 폐기와 안전한 재개 절차를 훈련한다.

## 증적

입출금 상태·승인·정책 판정·서명·tx·대사 기록, 거절·격리·재시도·대체거래, 정책 변경과 비상조치·재개 승인 기록을 보관한다. 트래블룰 개인정보 원문은 일반 거래 로그에 중복 저장하지 않는다.
