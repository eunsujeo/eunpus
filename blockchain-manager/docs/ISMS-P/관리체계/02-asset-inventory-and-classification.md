인증범위의 정보자산을 빠짐없이 식별하고 소유자, 중요도, 위치와 생명주기를 관리한다.

## 자산 범주

- 정보: 개인정보, 거래·원장, 지갑 주소, 정책, 소스, 계약, 로그와 백업
- 소프트웨어: 지갑 API, Admin, Policy Server, Co-signer, 배치와 외부 연계
- 인프라: 클라우드 계정, 서버·컨테이너, DB, Queue, 저장소, 네트워크, SIEM
- 계정·자격: 사용자·서비스·관리자 계정, API 자격, 인증서와 암호키
- 물리·단말: 사무실, 전산실, 관리자·업무 단말과 저장매체
- 외부 서비스: Fireblocks, 클라우드, 트래블룰, AML·KYT와 운영 협력사
- 사람: 주요 직무자, 개인정보취급자, 개발·운영·외부 관리자

## 자산 목록 필드

자산 ID, 이름, 유형, 소유자, 관리자, 서비스·환경, 물리·논리 위치, 데이터 분류, 개인정보 여부, 중요도, 외부자, 백업, 보존·폐기 기준, 최근 검토일과 상태를 기록한다.

## 중요도 평가

기밀성, 무결성, 가용성에 더해 지갑 사업 특성을 평가한다.

| 관점 | 높은 중요도의 예 |
|---|---|
| 기밀성 | 키 자료, 인증정보, KYC·트래블룰 개인정보 |
| 무결성 | 잔액·거래 원장, 주소 매핑, 출금 정책과 승인 기록 |
| 가용성 | 서명·출금·입금 탐지, Co-signer, 대사와 비상정지 |
| 자산 통제 | 자산 이전을 단독 또는 결합해 가능하게 하는 권한·키 조각 |
| 법적 영향 | 법정 보존·신고·통지 또는 가상자산사업자 의무와 연결된 정보 |

평가 척도와 계산식은 위험관리 절차에서 승인하고 임의로 바꾸지 않는다.

## 변경과 정기검토

신규 시스템·체인·자산·외부자 도입, 운영 주체·위치 변경, 대규모 데이터 이전 전에 자산을 등록한다. 소유자는 월별 변경사항과 연 1회 이상 전체 목록을 검토한다. 발견되지 않은 자산은 등록·격리·폐기 중 하나로 처리한다.

## 재사용과 폐기

자산 반출·재사용·폐기는 데이터 분류와 매체 특성에 맞는 승인된 방법을 사용한다. 클라우드·SaaS는 계정 종료만으로 삭제가 완료됐다고 가정하지 않고 활성본, 복제본, 백업과 로그의 삭제 조건·확인방법을 계약과 절차에 반영한다.

## 증적

- 정보자산 목록과 변경 이력
- 중요도 산정 결과와 소유자 승인
- 미등록 자산 탐지·조치 기록
- 반출·재사용·폐기 승인과 완료 확인
- 외부 서비스 데이터 반환·삭제 확인서
