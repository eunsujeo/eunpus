101개 인증기준별로 현재 정책, 시스템과 운영 기록을 확인하고 목표 상태와의 차이를 관리한다. 문서만 있거나 시스템 설정만 있는 경우는 충족으로 보지 않는다.

## 평가 등급

| 등급 | 판단 기준 |
|---|---|
| 충족 | 승인 문서, 적용된 통제, 반복 운영 증적과 점검 결과가 모두 있음 |
| 일부 충족 | 설계·구현은 있으나 범위가 부족하거나 반복 증적·검토가 없음 |
| 미충족 | 요구사항을 다루는 정책·통제·증적이 없거나 실제 운영과 불일치 |
| 해당 없음 | 업무·시스템에 적용되지 않으며 제외 근거와 승인이 있음 |
| 확인 필요 | 범위·법률·기술 사실이 없어 판단할 수 없음 |

## 조사 방법

각 항목은 다음 네 가지를 교차 확인한다.

1. 문서: 정책·지침·절차와 승인·배포 이력
2. 시스템: 설정, 코드, 계정·권한과 운영 화면
3. 기록: 일정 기간의 수행·검토·시정조치 증적
4. 인터뷰: 책임자와 실제 수행자의 설명

하나라도 서로 다르면 차이로 기록한다. 예를 들어 문서에는 분기 권한검토라고 쓰고 실제로 연 1회 수행했다면 `일부 충족` 또는 `미충족`으로 판단한다.

## 우선순위 산정

| 요소 | 질문 |
|---|---|
| 자산 영향 | 고객 자산 손실이나 무단 서명으로 이어지는가 |
| 개인정보 영향 | 대량 유출, 민감·고유식별정보 노출 가능성이 있는가 |
| 법적 영향 | 신고 불수리, 과징금·과태료, 통지·신고 위반 가능성이 있는가 |
| 공격 가능성 | 인터넷 노출, 특수권한, 알려진 취약점이 있는가 |
| 복구 가능성 | 사고를 탐지·차단·복구하고 대사할 수 있는가 |
| 심사 영향 | 여러 통제항목과 인증범위 전반에 공통으로 영향을 주는가 |

위험이 높은 미비점부터 소유자, 완료일, 예산, 임시 대책과 목표 증적을 정한다. 기한을 넘기면 이유와 새 일정뿐 아니라 잔여 위험 승인 여부를 기록한다.

## 초기 집중 조사

- 회사와 고객 중 누가 키와 자산을 실질적으로 통제하는가
- Fireblocks·클라우드·트래블룰 사업자의 역할과 데이터 처리 위치
- 관리자·개발자·Co-signer 계정과 긴급 접근 권한
- 출금 생성부터 정책 승인, 서명과 전파까지의 실패 차단
- KYC·트래블룰 개인정보의 처리 근거, 위탁·국외이전과 파기
- 운영·보안·접속 로그의 누락, 보존, 무결성과 정기 검토
- 지갑 원장·벤더·온체인 대사와 불일치 처리
- 키·DB·설정의 복구 가능성과 실제 시험 결과

## 차이 항목 양식

| 필드 | 내용 |
|---|---|
| 항목 ID | GAP-연도-일련번호 |
| 인증기준 | 관련 기준 ID |
| 현황·근거 | 확인한 문서·설정·증적·인터뷰 |
| 차이 | 요구사항과 다른 구체적 사실 |
| 위험 | 발생 가능한 사건과 영향 |
| 조치 | 목표 상태와 완료 조건 |
| 책임자·기한 | 실행 소유자와 완료일 |
| 임시 대책 | 완료 전 위험을 줄이는 통제 |
| 검증 | 독립 검토자, 재시험 결과와 종료일 |
