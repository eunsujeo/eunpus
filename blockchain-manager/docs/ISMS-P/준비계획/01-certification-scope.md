ISMS-P 심사에 포함할 법인, 서비스, 조직, 정보자산과 물리적 위치를 정한다. 이 문서의 승인 전에는 개별 통제 문서의 적용 범위를 확정하지 않는다.

## 범위 결정 원칙

- 고객에게 제공하는 지갑 서비스의 전체 생명주기를 기준으로 경계를 잡는다.
- 입금·출금·스윕·서명·복구·정책 판정·트래블룰에 직접 관여하는 구성 요소를 포함한다.
- 운영시스템에 접근하거나 변경할 수 있는 개발·운영·보안·협력사 조직을 포함한다.
- 개인정보가 수집·조회·전송·보관·파기되는 시스템과 취급자를 포함한다.
- 제외 대상은 단순히 다른 법인이나 외부 서비스라는 이유만으로 제외하지 않는다. 연계와 책임을 분석한다.

## 범위 초안

| 구분 | 대상 | 상태 | 결정 근거 |
|---|---|---|---|
| 인증 주체 법인 | 결정 필요 | 미확정 | 법인등기·사업자 신고 주체 확인 |
| 인증 서비스명 | 결정 필요 | 미확정 | 대외 서비스명과 인증서 표시 범위 확인 |
| 지갑 유형 | 수탁형·비수탁형·혼합형 중 결정 필요 | 미확정 | 키·서명·복구 통제권 분석 |
| 가상자산사업 행위 | 특금법 가~마목별 판단 필요 | 미확정 | 법무·준법 검토 |
| 운영 환경 | 운영, DR, 관리자 시스템 | 포함 검토 | 서비스 제공과 복구에 직접 필요 |
| 개발·시험 환경 | CI/CD, 저장소, 시험시스템 | 포함 검토 | 운영 변경과 소스 접근 가능 |
| 외부 서비스 | Fireblocks, 클라우드, 트래블룰, AML·KYT | 포함 검토 | 위탁·연계·공동책임 경계 확인 |
| 사업장 | 본사, 운영실, 전산실, DR 위치 | 미확정 | 물리적 위치와 원격근무 포함 |

## 필수 구성도

범위 승인 자료에는 다음 네 장을 별도로 작성한다.

1. 서비스 구성도: 사용자부터 지갑·관리자·외부 사업자까지의 흐름
2. 네트워크 구성도: 인터넷, 관리망, 애플리케이션, DB, 로그와 외부 연계
3. 개인정보 흐름도: 수집, 이용, 제공, 위탁, 국외이전, 보관과 파기
4. 키·서명 흐름도: 키 생성, 분산, 승인, 서명, 백업·복구와 폐기

구성도에는 시스템명, 운영 주체, 데이터 종류, 신뢰 경계, 전송 방향과 인증수단을 표시한다. 실제 IP, 비밀값과 개인 식별정보는 이 저장소에 기록하지 않는다.

|---|---|
| 사람 | 경영진, 보안·개인정보 담당자, 개발자, 운영자, 고객지원, 준법, 외부 운영자 |

| 데이터 | 고객·회원·KYC·트래블룰 정보, 주소·거래·원장, 감사·운영·접속 로그 |

| 단말·장소 | 관리자 단말, 업무용 PC, 사무실, 전산실, 원격근무 위치 |
| 외부자 | Fireblocks, 클라우드, 트래블룰, AML·KYT, 메시징, 고객지원과 유지보수 사업자 |

## 제외 관리

제외 대상마다 다음 질문에 답한다.

- 인증 서비스와 계정·네트워크·데이터·운영자가 분리돼 있는가.
- 제외 시스템 장애나 침해가 인증 서비스에 영향을 줄 수 있는가.
- 제외 시스템에서 인증범위 개인정보 또는 중요정보를 처리하는가.
- 제외 근거를 구성도와 자산목록에서 일관되게 설명할 수 있는가.

답변 중 하나라도 불명확하면 제외를 확정하지 않는다.

## 승인과 변경

범위는 정보보호 책임자, 개인정보 보호책임자, 서비스·기술 책임자와 준법 담당자가 검토하고 경영진이 승인한다. 신규 체인·자산·지갑 유형, 신규 외부자, 데이터 처리국가, 사업장 또는 운영 주체가 바뀌면 변경 전에 범위 영향을 검토한다.

## 필요한 증적

- `SCP-001` 승인된 인증범위 정의서와 변경 이력
- `SCP-002` 서비스·네트워크·개인정보·키 흐름 구성도
- `SCP-003` 조직도와 담당자 명단
- `SCP-004` 정보자산·개인정보·외부자 목록
- `SCP-005` 제외 대상과 제외 근거 승인 기록

## 결정 필요

인증 주체 법인, 서비스명, 심사 목표월, 서비스 URL·앱, 실제 운영·DR 위치, 지갑의 키 통제 구조와 개인정보 처리 시스템을 확정해야 한다.
