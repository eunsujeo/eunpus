외부 심사 전에 문서, 시스템, 증적과 담당자 설명이 일치하는지 확인한다. 체크 표시만 하지 않고 표본과 확인 결과를 기록한다.

## 신청 전 관문

- [ ] 인증 종류, 심사 유형, 법인·서비스와 목표 일정이 확정됐다.
- [ ] 최신 고시·인증기준·신청서 양식을 다시 확인했다.
- [ ] 인증범위의 조직·자산·물리적 위치와 외부 연계가 승인됐다.
- [ ] 101개 통제항목의 적용 여부, 책임자, 문서와 증적이 연결됐다.
- [ ] `해당 없음` 항목마다 구체적인 근거와 승인이 있다.
- [ ] 내부감사와 경영진 검토, 시정조치를 완료했다.
- [ ] 심사 대상 기간의 운영 증적이 누락 없이 준비됐다.

## 표본 심사 방식

다음 흐름을 서로 다른 날짜와 담당자 표본으로 추적한다.

1. 입사·직무변경·퇴사 한 건의 계정과 권한 생명주기
2. 운영 배포 한 건의 요구사항, 검토, 시험, 승인, 배포와 롤백
3. 취약점 한 건의 발견, 위험평가, 조치, 재검증과 종료
4. 외부자 한 곳의 선정, 계약, 권한, 정기점검과 계약 종료
5. 개인정보 한 건의 수집 근거부터 제공·보관·파기까지
6. 출금 한 건의 요청, 정책 판정, 승인, 서명, 전파, 대사와 감사기록
7. 장애·사고 한 건의 탐지, 보고, 복구와 재발방지

## 인터뷰 준비

담당자는 외운 답이 아니라 다음을 실제 화면과 기록으로 설명할 수 있어야 한다.

- 자신의 책임과 승인 한계
- 정상 절차와 예외·긴급 절차의 차이
- 최근 수행한 업무의 증적 위치
- 통제가 실패했을 때 보고하고 차단하는 방법
- 최근 발견한 문제와 시정조치

모르는 질문에 추측으로 답하지 않는다. 담당자를 확인하고 근거 문서와 함께 후속 답변한다.

## 심사 자료 관리

- 심사원에게 제공할 자료 목록, 제공일, 제공자와 회수 여부를 기록한다.
- 개인정보와 비밀값은 필요한 최소 범위만 제공하고 안전한 전달수단을 사용한다.
- 운영화면 시연 계정은 읽기 전용·최소 권한으로 준비한다.
- 화면 캡처의 시각·환경·대상을 식별하되 토큰·키·전체 개인정보는 노출하지 않는다.
- 질의, 답변, 추가자료, 결함과 보완기한을 하나의 이슈 목록으로 관리한다.
