사내 데이터센터 전체 플랫폼 설계를 확정하기 위해 Dfns 담당자에게 확인할 질문이다. 아래는 질의 초안이며 아직 발송하거나 답변받지 않았다. AWS 배치와 비교하되, 현재 설계 대상은 사내 데이터센터로 유지한다.

배포 프로필 차이는 [도입·배포 개요](00-on-premise-deployment.md), AWS와 사내의 자원·키·복구 차이는 [Baseline 인프라 설계](03-baseline-datacenter-design.md)에서 다룬다. 아래 질의는 사내 구축을 전제로 AWS와의 차이를 확인한다.

## 담당자에게 전달할 질문

### Q01. 사내 데이터센터의 Baseline 전체 플랫폼 배포를 지원하나요?

저희는 고객 소유 AWS 계정이 아닌 **사내 데이터센터에 API·대시보드·정책·MPC·데이터 저장소 전체를 배치**하는 방안을 검토하고 있습니다. Baseline 프로필로 이 구성을 공식 지원하나요? 지원한다면 지원 Kubernetes 배포판·CPU 아키텍처·제품 버전과 설치 모듈·운영 문서를 제공해 주실 수 있나요?

기존 개요에는 고객이 만든 Kubernetes에 Helm chart만 설치하는 방식이 지원 경로가 아니라고 되어 있습니다. 사내 환경에서 사용해야 하는 지원 배포 경로와, 별도 개발·구축 지원이 필요한 범위를 확인 부탁드립니다.

### Q02. AWS Baseline과 비교할 때 어느 계층까지 변경해야 하나요?

자료상 AWS에서도 Baseline을 사용할 수 있고, 첫 계층 이후에는 표준 Kubernetes를 사용하는 것으로 이해했습니다. **AWS의 L1 기반 서비스를 사내 서비스로 대체하면 L2 Platform·L3 Product·L4 Signing은 같은 이미지·chart로 운영할 수 있나요?** 각 계층에서 설정 변경만 필요한지, 모듈 또는 애플리케이션 수정까지 필요한지 구분해 주세요.

특히 EKS·Aurora·MSK·ElastiCache·Route53·ACM·SSM의 대체 요건과, Vault의 AWS KMS auto-unseal을 Shamir 수동 unseal 또는 사내 HSM으로 바꿀 때의 지원 조건을 알고 싶습니다. AWS API·IAM 등에 남는 의존성이 있는지도 확인 부탁드립니다.

### Q03. Vault와 데이터 서비스를 Kubernetes 밖에서 운영할 수 있나요?

Kubernetes와 Vault가 함께 중단되는 상황을 줄이기 위해, 앱·MPC는 Kubernetes에 두고 **Vault와 PostgreSQL·Kafka·Redis는 별도 VM 또는 외부 서비스로 연결**하는 구성을 제안했습니다. 이 배치가 AWS Baseline과 사내 Baseline 각각에서 지원되나요? 권장 구성과 외부 endpoint·TLS·인증·초기화 설정 방법을 안내해 주세요.

MPC Keyshares store도 함께 확인 부탁드립니다. 지원 저장 엔진과 배치 위치, party별 접근 분리, 복제·백업·복구 방식은 무엇이며 두 환경에서 같은 구성을 사용할 수 있나요? Vault·일반 서비스 DB·키 조각 저장소를 함께 복구할 때 필요한 일관성 조건과 공식 복구 순서가 있다면 제공 부탁드립니다.

AWS Baseline에서는 MSK SCRAM 등록용 Secrets Manager와 애플리케이션 전달용 Vault의 자격증명을 누가 생성·회전하나요? 배포 패키지가 담당하는 동기화 범위와 갱신 실패 시 복구 절차도 확인 부탁드립니다.

### Q04. 위탁 운영하는 전용 노드 RPC로 전체 기능을 실행할 수 있나요?

저희는 **DAW-CORE → DAWBC → 사내 Dfns Baseline → 노드 운영업체의 전용 RPC** 구성을 검토합니다. 1차 대상은 EVM 체인 1개와 ERC-20 자산 1개입니다. 연결 명세는 고객이 [RPC 제안 초안](../DAW%20구축%20설계/02-node-rpc-spec.md)으로 먼저 제시하고, Dfns의 기능 호환성과 필요한 차이를 확인하려 합니다. 노드의 설치·동기화·장애 대응은 업체에 맡기고, 지갑·MPC·키 관리는 고객 환경에 두려 합니다.

지정한 RPC를 통해 거래 전송·수수료 추정·입금 감지·확정 추적·과거 이력 조회를 모두 처리할 수 있나요? 체인별 필수 메서드, HTTP/WebSocket, archive·trace·과거 데이터 범위, 인증·TLS·호출량 요건을 제공해 주세요. 별도 외부 인덱서나 Dfns 운영 RPC가 반드시 필요한 기능이 있다면 구분 부탁드립니다.

네트워크마다 RPC endpoint 하나를 등록하는 구조에서 다중 노드의 장애 전환은 Dfns와 RPC 운영업체 중 누가 담당하나요? 뒤처진 노드 배제, endpoint 교체, 누락 구간 재인덱싱, reorg 처리, 장애 시 진단·지원 경계를 확인하고 싶습니다.

### Q05. DAWBC 어댑터와 사내 릴리스의 API 계약을 확인할 수 있나요?

DAWBC는 계정·주소 매핑, 멱등 제출, 입출금 상태 이벤트를 DAW-CORE에 제공합니다. Baseline 지원 릴리스의 OpenAPI·SDK·테스트 환경과 다음 항목을 확인할 자료를 요청드립니다.

- Service Account·API 요청 서명·승인 정책의 구성, 내부 업무 승인과 서명 실행을 연결하는 지원 방식
- 일반 전송·컨트랙트 호출의 API, 지갑·네트워크·토큰·memo/tag 모델, 수수료 추정·변경·재전송·sweep 지원 범위
- `externalId`의 API별 멱등 범위·충돌·보존 기간·조회 방법, 제출 응답 유실 후 중복 전송 없이 회수하는 절차
- Webhook 검증·재전송·이벤트 ID·순서, 입금 항목 식별자, Included·Confirmed와 체인별 확정·reorg 처리 기준. 동일 이동을 Webhook·이력 조회·재편입에서 연결하는 식별 규칙
- 플랫폼 거래 상태와 실제 수수료의 조회·대사 방법, 트래블룰 메시지와 기존 내부 검증 흐름의 연동 지원
- 백업 시점 이후 접수된 거래·지갑을 복원할 조회·보존 범위와 공식 재개 절차. 복원된 플랫폼이 기존 요청을 다시 실행하지 않도록 확인하는 방법

이 질문의 시스템 경계와 구축 순서는 [노드 운영 위탁·DAW 통합 설계](../DAW%20구축%20설계/00-integration-plan.md)에 정리했습니다.

### Q06. Baseline에서 외부 대납과 법정화폐 정산을 어떤 방식으로 연결할 수 있나요?

최종 사용자가 ETH·SOL을 준비하지 않고, 우리 회사가 대납 비용을 법정화폐로 정산하는 모델을 설계하고 있습니다. 공개 Fee Sponsors의 네이티브 자산 충전 방식과 별도로 다음을 확인하고 싶습니다.

- 사내 Baseline의 지원 릴리스에서 EVM·Base의 EIP-7702 대납과 Solana 대납을 지원하나요? 최초 위임·위임 코드 버전/변경·정책·실패·재시도·비용 조회 절차를 제공해 주세요.
- Dfns 또는 제휴업체가 네이티브 자금을 직접 조달·지불하고 법정화폐로 청구하는 서비스가 있나요? 제공 주체·지원 체인·통화·환율 시점·주기·서비스비·실패 및 초기 위임 과금 기준을 구분해 주세요.
- 외부 EVM relay 또는 ERC-4337 bundler/paymaster를 연결할 수 있나요? 지원 account 구현·EntryPoint 버전·서명 형식·nonce 관리·정책 강제·관측 API와 필요한 추가 개발 범위를 알고 싶습니다.
- Solana 외부 fee payer와 고객 Dfns 지갑이 같은 메시지에 서명할 수 있나요? 거래 구성·부분 서명 결합·blockhash 만료·재서명·전파 담당·token account 생성 자금의 책임을 확인 부탁드립니다.
- 내장 Fee Sponsors에서 대납 지갑의 서명 차단·승인 대기 정책이 전송에 미치는 영향과 권장 권한 구성을 확인해 주세요. 고객 승인 정책을 유지하면서 대납을 자동 실행할 수 있는 지원 구성이 필요합니다.
- 묶음 거래에 포함된 개별 UserOperation·relay 송금의 결과와 비용을 조회할 수 있나요? 초기 위임·실패·재시도를 합친 업무 요청 총액 및 환율 변동을 포함한 법정화폐 청구 상한을 강제할 수 있는지도 확인 부탁드립니다.
- 각 경로에서 고객 지정 RPC만 사용할 수 있나요? 외부 조회·시뮬레이션·전파 경로가 필요하면 구분해 주세요. 실제 비용·대납 ID·업무 요청·청구서 항목을 연결할 자료도 요청드립니다.

검토 중인 고객 설계는 [법정화폐 정산형 대납](../DAW%20구축%20설계/03-fiat-gas-sponsorship.md)입니다. 아직 특정 운영 주체나 대납업체를 선정하지 않았습니다.

### Q07. 여러 체인·스테이블코인의 지원 조합을 확인할 수 있나요?

1차는 EVM 체인 1개·ERC-20 자산 1개로 검증하지만 이후 Base·Solana와 여러 스테이블코인을 지원해야 합니다. 사내 릴리스별 네트워크·자산·지갑 모델·입금 감지·대납·sweep 지원 표를 제공해 주세요.

특히 Solana의 owner 주소·token account·ATA 매핑, SPL Token과 Token-2022 extension별 지원, 하나의 거래에 여러 이동이 있을 때 항목 ID와 실제 수취 금액, commitment·재편·과거 이력의 의미를 확인하고 싶습니다. EVM에서도 같은 symbol의 다른 contract를 구분하는 자산 식별, Base의 확정과 전체 수수료 구성, 신규 토큰 등록·검증·지원 변경 절차를 안내 부탁드립니다.
