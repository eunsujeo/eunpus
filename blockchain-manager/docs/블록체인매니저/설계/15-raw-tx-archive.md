블록체인 매니저가 벤더에서 받는 트랜잭션 데이터를 **원본 그대로** 보관하는 설계다. 하루 한 번, 최종 상태에 도달한(finalize) 건만 적재한다.
용도는 감사 제출·대사(reconciliation)·재처리(번역 로직에 문제가 있을 때 원본 재해석)다.

## 결정

| 항목 | 결정 |
|---|---|
| 무엇을 보관하나 | **벤더 응답 원문** — 매니저가 받은 트랜잭션 객체(JSON)를 받은 바이트 그대로. 체인 원문(RPC 의 tx·receipt)은 자체 노드 접근이 생길 때 2단계로 |
| 언제 | **하루 1회 배치** — 그날 최종 상태(완료·실패·취소 — 4장 TxStatus 의 terminal)에 도달한 건만. 상태 스냅샷 중복 없음 — 트랜잭션당 정확히 1행 |
| 어디에 | **매니저 DB(PostgreSQL)** 의 append-only 테이블 — 원본을 받는 자리에 둔다 |
| 원문 타입 | **TEXT** — JSONB 가 아니다. JSONB 는 파싱해 이진으로 저장해서 키 순서·공백이 바뀌므로, 꺼낸 값이 받은 바이트와 달라져 해시 무결성 증명이 깨진다. JSON 파생 조회가 필요해지면 그때 파생 컬럼·뷰를 추가한다 |

## 테이블

테이블·인덱스 정의는 **[BC/설계 — 블록체인 매니저 DB](../../BC/설계/03-bcm-db.md)** 의 `bcm_raw_tx_l`(코어 규약 정렬본)을 본다. 이 장은 표를 되풀이하지 않고 **보관의 목적·배치·규모·경계**만 다룬다.

## 인덱스 — 조회 패턴 셋에만

파티션-로컬 인덱스라 전체 행이 수억이 돼도 각 인덱스는 그 달 치 크기에 머문다. JSON(payload)에는 인덱스를 걸지 않는다.

| 인덱스 | 조회 패턴 |
|---|---|
| PK `(base_dt, vndr_tx_id)` | 배치 멱등 · 벤더 id 역조회 |
| `(tx_hash)` | 분쟁·역추적 — "이 온체인 tx 의 원본" |
| `(addr, base_dt)` | 지갑(주소) 기준 기간 조회 — "이 지갑의 그 기간 원본". 선두가 주소라 천만 지갑에서도 균등 분산 |

## 일 배치

1. **대상 선별** — 매니저 DB 의 상태 기준으로 그날 terminal 에 도달한 건 목록을 뽑는다. 어제 제출돼 오늘 확정된 건은 오늘 배치에 자연히 담긴다.
2. **원문 확보** — 벤더에서 해당 건의 최종 객체를 받아 바이트 그대로 payload 에, SHA-256 을 payload_hash 에.
3. **멱등** — 같은 기준일 재실행은 해당 파티션을 비우고 재적재(TRUNCATE-reload)하거나 PK 충돌 skip. 어느 쪽이든 재실행이 안전해야 한다.
4. **적재 저널** — 실행마다 `기준일 · 적재 건수 · 건 해시들의 요약 해시` 한 줄을 별도 테이블에 남긴다 — "그날 치가 빠짐·변조 없음"을 감사에 증명하는 최소 장치.
5. **권한으로 append-only 강제** — 적재 계정은 INSERT 전용(UPDATE·DELETE 권한 없음).

## 규모 — 천만 지갑 대비

일 활성률 a, 지갑 1,000만, 원문 ~5KB 로 두면: a=1% → 10만 행/일 ≈ 연 180GB, a=10% → 100만 행/일 ≈ 연 1.8TB. 앞자리는 단일 PostgreSQL + 파티셔닝으로 수년 감당 범위다. 확장은 순서를 예약해 둔다:

1. **아카이브** — 오래된 파티션을 DETACH 해 오브젝트 스토리지(Parquet 등)로 내리고, DB 는 최근 N 개월만. 규제 보존이 요구되면 스토리지의 버전 잠금(WORM)을 쓴다.
2. **분석 분리** — 지갑 기준 대량 분석 조회가 생기면 그건 웨어하우스로 — 원본 보존(RDB)과 분석을 분리한다.

## 경계

- **저장 주체는 블록체인 매니저** — 매니저 DB 의 정체(벤더 번역·운영 상태)에 "finalize 원본 보관"이 추가된다.
- **트래블룰 메시지 원본과 별개** — 그쪽은 컴플라이언스의 감사 기록(범위 미정)이고 PII 가 걸린다. 이 장은 자산 이동 데이터만 다룬다.
- 기존 흐름을 건드리지 않는다 — 웹훅 수신→번역→이벤트 경로 옆의 사본 확보다.
- **원문 출처 = `bcm_whk_l`** (수신 알림 원본 — [DB 문서](../../BC/설계/03-bcm-db.md)) — 일 배치가 그 tx 의 마지막 COMPLETED 알림 payload 를 옮긴다. 벤더 재조회가 없어 조회 한도와 무관하다.

## 미확정

- **보존 연한** — 규제 요구(거래 기록 보존 기간) 확인 후 값 확정 → 파티션 주기(월/일)와 아카이브 시점이 따라온다.
- **일 활성률 실측** — 파티션 단위·용량 계획의 입력값.
- **체인 원문(2단계)** — 자체 RPC 접근 여부는 인프라 결정.
