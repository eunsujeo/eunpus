[1장](01-problem.md)의 두 수단은 **이미 있는 재고를 맞바꾸는 것**이다. 상대에게 재고가 없으면 성립하지 않는다.

| 수단 | 상대 | 성립 조건 |
|---|---|---|
| 브릿지교환 | 카뱅지갑 | 카뱅자산에 그 BC자산 재고가 있을 때 |
| 콜드교환 | 콜드월렛 | 카뱅자산이 부족하고 업무시간일 때 |

그러면 남는 경우가 있다 — **양쪽 다 그 네트워크의 재고가 없을 때**, 그리고 **업무시간이 아닐 때**다. 이때는 자산을 실제로 다른 네트워크로 옮겨 와야 한다. 아래는 그 후보다.

## 후보

| 후보 | 상태 | 조사할 것 |
|---|---|---|
| **USDC Gateway** (Fireblocks) | [3장](03-usdc-gateway.md) 정리 완료 | 소요 시간 · 실패 시 자금 위치 |
| **Circle CCTP 직접** | 미조사 | Gateway 를 안 거치고 직접 붙일 때의 차이 — 수수료·시간·구현 부담·수탁 경계 |
| **서드파티 브릿지** | 미조사 | 어떤 것들이 있고 무엇을 신뢰해야 하나. 수탁 서비스가 쓸 수 있는 형태인가 |
| **거래소 경유** | 미조사 | 입금 후 다른 체인으로 출금하는 방식. 한도·시간·상대방 위험 |
| **재고 사전 확보** | 미조사 | 옮기지 않고 각 네트워크에 미리 깔아 두는 것. 밴드C 값을 키우는 선택 |

USDC Gateway 는 **USDC 전용**이라 원화 SC 에는 못 쓴다. 자산 범위에서 후보 대부분이 갈릴 것으로 보이므로, 어떤 BC자산을 다루는지부터 확정하는 것이 순서다.

## 비교할 축

수단마다 아래를 같은 형식으로 채운다. 채워지기 전에는 표를 비교에 쓰지 않는다.

- **자산 범위** — USDC 전용인가, 원화 SC 도 되나
- **자금이 어디에 머무나** — 우리 vault · 벤더 컨트랙트 · 제3자
- **비용** — 고정·비율·양쪽 체인 가스를 누가 내나
- **소요 시간** — 최선·최악. 업무시간 밖에도 되나
- **실패 처리** — 중간에 실패하면 자금이 어디 있고 어떻게 회수하나
- **한도** — 건당·기간당
- **벤더·정책 의존** — 정책 룰, 화이트리스트, 승인 절차
- **감지·대사** — 우리 시스템에 어떤 기록으로 남나
- **자산 경계** — 고객자산 안에서 끝나나, 카뱅자산이나 외부와 섞이나

## 정하는 순서

1. 다루는 BC자산 목록을 확정한다 — 자산 범위에서 후보 대부분이 걸러진다
2. 브릿지교환·콜드교환으로 못 메우는 경우가 실제로 얼마나 되는지 본다
3. 남은 경우에만 위 후보를 위 축으로 비교한다
