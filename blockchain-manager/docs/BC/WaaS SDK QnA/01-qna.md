Fireblocks 를 감싼 WaaS SDK 제공 업체에 물을 것과 받은 답을 질문 단위로 모은다. 답이 오면 `A.` 를 채운다.
대상 업체·제품명은 확인 후 적는다.
**Fireblocks 계약은 업체 명의로 가정한다** — 우리는 Fireblocks 와 직접 협의하지 않고 업체를 통한다.

## 워크스페이스·한도

**Q.** Fireblocks 워크스페이스가 우리 전용인가, 여러 고객이 함께 올라가는가? 우리에게 배정되는 분당 한도는 얼마이고 초과하면 어떻게 되나?
**A.** 미확인. rate limit 은 워크스페이스 단위로 공유된다(Fireblocks 확답) — 공유 구조면 다른 고객 트래픽에 우리 조회·제출이 막힌다. 배정 한도는 sweep·대사 물량 설계의 입력값이다.

**Q.** Fireblocks 콘솔을 우리가 볼 수 있나(읽기 전용이라도)? 거래·정책(확정 임계 등)·감사 로그를 우리가 직접 확인할 수단이 있나?
**A.** 미확인. 확정 임계는 워크스페이스 공통 설정이라 값을 공유받아야 한다 — 입금 확정 판정이 그 값과 컨펌 수를 비교하는 구조다. 사고 조사·감사에서도 벤더 원본을 우리 눈으로 봐야 한다.

## 키·서명

**Q.** MPC 키 셰어를 누가 보유하나? 업체가 셰어를 갖는 구조인가?
**A.** 미확인. 수탁업자는 우리인데 업체가 사슬에 들어오면 재위탁 구조라 규제 검토가 필요하다.

**Q.** API Co-signer 는 어떻게 배치되나? 우리 인프라에 두는 구성이 되나?
**A.** 미확인.

**Q.** 서명 직전 검증은 어떻게 제공되나? 목적지·금액·한도를 우리 기록과 대조하는 규칙을 그 지점에 넣을 수 있나?
**A.** 미확인. 우리 설계는 이 판단을 우리 DB 기준으로 하는 전제다.

**Q.** 계약이 끝나면 워크스페이스·vault·자산을 우리 통제로 이전할 수 있나? 업체가 서비스를 중단하거나 폐업할 때 자산에 접근하는 경로는?
**A.** 미확인. 계약이 업체 명의라 이전 절차가 계약서에 명시돼 있지 않으면 자산이 묶인다.

## 웹훅·이벤트

**Q.** 온체인 상태 변경을 우리가 어떻게 받나 — Fireblocks 웹훅을 우리 주소로 등록해 직접 받나, 업체가 받아 재전달하나?
**A.** 미확인. 우리 감지 설계가 직수신 전제다(수신 인박스·벤더 재시도·재전송 요청·tx 대사).

**Q.** 재전달이라면 유실·중복·순서를 어떻게 다루나? 재시도 횟수·간격, 놓친 것을 다시 받는 수단, 서명·인증 방식은?
**A.** 미확인. 우리가 실측한 벤더 동작이 그대로 적용되는지, 업체 정책으로 대체되는지가 복구 설계를 가른다.

**Q.** 중계 구간의 적체·장애를 우리가 관측할 수 있나? 유실을 우리가 검출할 수단이 있나?
**A.** 미확인.

**Q.** 거래 목록·단건 조회를 제공하나? 우리 기록과 대조(대사)할 수 있는 조회 수단이 있나?
**A.** 미확인. tx 대사가 벤더 기록과 직접 대조하는 구조다.

## 자산 이동

**Q.** 가스 대납이 어떻게 구현돼 있나 — 누가 대납하고, 어떤 방식이며, 수수료는 어떻게 정산되나? 지원 체인은?
**A.** 미확인. 대납 방식이 sweep·출금 구조를 좌우한다.

**Q.** 입금 주소에 모인 자산을 모으는 sweep 을 어떻게 제공하나? 여러 주소를 한 거래로 묶는 배치가 되나, 주소당 개별 전송인가?
**A.** 미확인. 입금 건수가 많아 건당 고정비와 제출 호출량이 문제가 된다.

**Q.** 출금 제출에 우리 요청 키를 실을 수 있나? 같은 키로 다시 제출하면 중복이 차단되나?
**A.** 미확인. 재제출 중복 차단이 우리 요청 키로 걸려야 한다.

## 정책·컴플라이언스

**Q.** sweep 트리거를 우리 정책으로 정할 수 있나 — 총자산 대비 비율, 가스비 한도, 자산별 임계?
**A.** 미확인. 업체 고정 모델만 지원하면 설계자 정책을 표현할 수 없다.

**Q.** 핫·콜드 계층과 밴드 관리(원화환산·상하한·자산별 동일 비율 이동)를 얹을 수 있나?
**A.** 미확인.

**Q.** 출금 정책(화이트리스트·한도)은 누가 어떻게 관리하나? 우리가 변경을 요청하면 반영까지 얼마나 걸리나?
**A.** 미확인. 화이트리스트·한도는 우리가 통제해야 하는데, 워크스페이스가 업체 것이면 변경 창구도 업체다.

**Q.** 트래블룰 솔루션(VerifyVASP·CODE·Notabene) 연동이 있나? 우리 컴플라이언스 게이트와 어디서 만나나?
**A.** 미확인. 중복 구축이나 경계 충돌이 될 수 있다.

## 운영·계약

**Q.** SDK·중계 구간의 SLA 와 장애 이력, 상태 페이지가 있나?
**A.** 미확인. Fireblocks 장애에 업체 장애가 더해진다.

**Q.** SDK 가 제공하지 않는 기능이 필요하면 어떤 경로가 있나? Fireblocks 신기능이 SDK 에 반영되는 데 얼마나 걸리나?
**A.** 미확인.

**Q.** 감사·규제 대응 자료를 제공하나? 업체 것(SOC·ISMS·보안 감사)과 Fireblocks 것을 우리 수탁 심사에 쓸 수 있나?
**A.** 미확인. 계약이 업체 명의면 벤더 자료도 업체를 통해 받아야 한다.

**Q.** 도입으로 줄어드는 구축 범위는 어디까지인가 — 감지·인박스·발행·대사·sweep 중 무엇이 완성돼 있나?
**A.** 미확인. 우리가 이미 설계·PoC 로 검증한 범위와 겹치는 만큼만 이득이다.
