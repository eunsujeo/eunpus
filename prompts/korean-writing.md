# 한글 기술 문서 작성 규칙

프로젝트에서 한국어 문서를 작성·번역·수정·검토할 때 적용한다. 본문뿐 아니라 제목, 요약, 표, 다이어그램 설명에도 같은 기준을 적용한다.

## 표현과 의미 보존

1. **한국어 개발·운영 문서에서 흔히 쓰는 표현을 사용한다.** 원문 단어를 기계적으로 옮기지 말고, 문맥에서 설명하는 동작을 한국어로 쓴다.
2. **주체·대상·행동을 구체적으로 쓴다.** 예를 들어 파일을 제공하는 상황의 “번들 인도”는 “배포 파일 제공”으로 쓴다. 주체나 동작이 원문에 없으면 추측해 추가하지 않는다.
3. **계약·법률 용어는 계약상 의미를 설명할 때 사용한다.** “인도”, “귀속”, “이행” 등을 일반적인 설치·운영 설명에 관성적으로 쓰지 않는다. 계약상 의미가 필요한 경우에는 정확한 용어를 유지한다.
4. **전문 용어는 처음 등장할 때 쉬운 설명을 붙인다.** 예: “leaf(Merkle 트리에서 개별 기록을 나타내는 항목)”. 제품명, API 식별자, 코드, 원문 직접 인용은 임의로 바꾸지 않는다.
5. **쉬운 표현으로 바꾸면서 원문의 조건·시점·책임 범위를 바꾸지 않는다.** 원문이 모호하면 그 불확실성도 유지하고 “확인 필요”로 남긴다. 특정 단어를 언제나 같은 쉬운 말로 치환하지 않는다.
6. **작성 후 번역투를 별도로 검토한다.** “한국어로 처음 작성했어도 이 표현을 썼을까?”를 기준으로 다시 읽고, 바꾼 문장이 원문의 의미를 유지하는지도 대조한다.
7. **지적받은 표현은 문서 전체에서 확인한다.** 본문뿐 아니라 제목·표·다이어그램 라벨·출처 설명과 연결된 자료 색인까지 검색한다. “인도용·인도물·인도 후”처럼 같은 어근의 다른 표현도 문맥별로 검토한다. 수정 후 다시 검색하고, 화면에 표시하는 생성 문서가 있으면 함께 갱신해 남은 표현이 없는지 확인한다. 원본 자료와 직접 인용은 보존한다.
8. **절을 가리킬 때는 기호 대신 단어로 쓴다.** `1절`, `3~5절`, `2쪽 1절`처럼 표기한다.

## 시점을 바꾸지 않는 예

`After delivery`는 문맥을 확인한 뒤 표현을 고른다.

- 배포 자료를 전달받는 시점을 뜻하면 “배포 자료를 전달받은 뒤”로 쓴다.
- 설치·구성 완료 시점을 뜻한다는 근거가 있으면 “배포 완료 후”로 쓴다.
- 어느 시점인지 불명확하면 원문 표현과 함께 “자료 전달 후인지 배포 완료 후인지 확인 필요”라고 남긴다.

“인도 후”가 어색하다는 이유만으로 “배포 완료 후”로 바꾸면, 원문에 없던 완료 조건을 추가할 수 있다.

## 자료 정리의 근거와 범위

- **정리 문서에는 추측을 넣지 않는다.** 원문에 명시된 내용과 출처가 있는 확정 결정만 기록한다. “저자 정리”, “해석”, “추정”이라고 표시해도 추측을 정리 본문·비교표·요약·다이어그램에 넣지 않는다.
- **각 사실을 해당 근거에 연결한다.** 문서명과 페이지·절 또는 공식 URL로 확인할 수 있어야 한다. 출처가 문장의 일부만 뒷받침하면 문장도 그 범위로 줄인다.
- **자료에 없다는 사실을 기능이 없다는 결론으로 바꾸지 않는다.** 확인되지 않은 내용은 생략하거나 “확인 필요” 절에 질문으로만 남긴다. 가능한 답을 추측해 붙이지 않는다.
- **보안 보장과 제품 비교의 범위를 확대하지 않는다.** 예를 들어 정책 규칙의 서명·암호화 설명을 사용자·권한 DB 전체의 변조·롤백 검증으로 확대하지 않는다. 비교 항목은 양쪽 출처가 직접 뒷받침할 때만 작성한다.
- **자료의 버전과 제품의 현재 상태를 구분한다.** 특정 자료의 “현재”, “아직”, “로드맵”은 그 자료의 설명으로 한정한다. 현재 출시·배포 상태로 단정하지 않는다. 벤더의 보안·성능 주장은 벤더의 설명임을 밝힌다.
- **검토할 때 근거 없는 문장은 삭제하거나 근거가 확인되는 범위로 고친다.** 추측에 출처를 붙이거나 표현만 완곡하게 바꾸는 것으로 처리하지 않는다.
