# Fireblocks Security Posture Management (FSPM)

*Updated 1 day ago*

## One-line summary

FSPM = **AI 기반 Policy attack simulator** (Google **Gemini** private deploy) + **continuous security posture 모니터링**. Add-on license. **Security Auditor 가 access role 에 포함** (Q-S13 정합). **6 monitoring 영역** + **3-step Agentic analysis** (weakest link / high-value targeting / autonomous drain simulation). **SOC2 compliance violation 표시**. **AI 가 policy 직접 변경 불가** — advisory only, every attack 은 Policy Engine 으로 validate (no false positive). → Q-S07 ANSWERED.

## Key Concepts

### Prerequisites
p.1:
- **Licensing**: Add-on. CSM 통해 활성화
- **Permissions** (★ Q-S13 정합): **Owner / Admin / Non-Signing Admin / Security Auditor**

→ **Security Auditor 가 FSPM access 가능** — Stage 8 `audit-log.md` 의 "Owner/Admin/NSA only" Audit Log access plane 과 별개의 plane 확인. **Audit Log = post-incident forensic**, **FSPM = pre-incident posture**. Security Auditor 는 FSPM 만 가능, Audit Log 는 제외.

### Identity / Origin
p.1: "**first security posture management solution purpose-built for digital assets**" — 디지털 자산 전용 SPM 카테고리.

> "Nearly all digital asset theft incidents stem from actions taken that were **technically authorized by weak policies**."

→ 공격 가설: 대부분 사고가 **정책 misconfiguration**. FSPM 의 mission = configuration drift 사전 발견.

### Agentic Policy Analyzer (★ 3-step)

p.1-2:

1. **Weakest link detection**: API 또는 workspace user 중 **single-handed initiator + approver + signer** (unilateral 가능) 식별 — Admin Quorum 의 "API Admin = quorum −1" 패턴 자동 분석

2. **High-value targeting**: 가장 가치 높은 account 들을 우선 분석 — attacker 시각 prioritization

3. **Autonomous drain simulation**: **Autonomous ReAct (Reasoning + Acting) loop** — 외부 주소로의 full attack path 시뮬레이션. Policy 가 simulated action 에 어떻게 응답하는지 iteratively observe + adapt
   - **Single hop**: 내부 → 외부 직접 transfer
   - **Lateral movement**: 여러 내부 account 경유 후 exit point

### Monitoring Scope (★ 6 영역)

p.2:
1. **Over-permissive and stale policies** — 과도한 권한 + 수개월 미review 거버넌스
2. **Unused users and access gaps** — inactive user, **missing API IP allowlist**, auth gaps
3. **Weak approval group thresholds** — single-user threshold, **API-only without human verification** (Stage 10 `approval-groups.md` 의 fully-API-controlled risk 자동 감지)
4. **Risky unused workspace settings** — Raw Signing / OTA / whitelist 가 사용 안되는데 enabled (attack surface 확대)
5. **Risky token allowances** — unused token approval (DeFi allowance drain risk)
6. **Outdated security software** — mobile app version drift

### Dashboard
p.2-3:
- **Console**: 좌측 nav `Security posture`
- Finding 별 표시: description / severity / category / detected date
- Side panel: risk 이유 + 해결 단계 + Console 어디에서 해결할지 안내 + "Accept risk" 옵션
- **SOC2 compliance violation** 매핑 (e.g., CC6.6 boundary protection, CC6.1 logical access security)

### Finding Lifecycle

p.3-4:
- **Open** → **Accepted** (risk 수용 시) 또는 **Resolved** (remediate 시)
- **Reopen** 가능 (Accepted finding 재검토)
- **Category 필터**: Policies / Workspace settings / Users / **Fleet Management** (mobile app version 등)

### AI Architecture & 안전성

p.4-5:
- **Powered by**: **private deployment of Google's Gemini** model
- **No fine-tuning with customer data**
- **Strict data access controls**
- **Session-level isolation**, **stateless agents** (세션 간 retain 안 함)
- **Regular auditing and monitoring** for data leakage
- 데이터 송신: workspace **policy info + masked technical user ID** 만 (수익 자산/주소 송신 안 함)
- DPA + Privacy Policy + Gemini Generative AI Prohibited Use Policy 적용

### AI Output 검증
p.5: "Every potential attack generated by the AI agent is **validated via the Fireblocks policy engine** to completely **avoid false positive results**."

→ AI 의 attack 가설 → Policy Engine 으로 시뮬레이션 검증 → false positive 차단. **Advisory + verified pipeline**.

### AI Authority Boundary
p.5: "**No.** The AI tool does **not have permission to modify your policies or any other workspace configurations**."

→ FSPM 은 read-only + advisory. 자동 remediation 없음 — 사용자가 명시 액션 필요.

### Disable 옵션
p.5: "**Although strongly not recommended**, it can be done." → Support 통해 disable 가능.
