Im still waiting for 100% confirmation from our team, however please review the below (which is 99% certain)

A transaction in the CONFIRMING state in Fireblocks generally does not move back to the BROADCASTING state, even if a blockchain reorganization ("reorg") occurs. Instead, Fireblocks updates the transaction status to reflect its actual state on-chain, and if a reorg removes it from the blockchain, the status is updated to a failed or dropped state—rather than reverting to broadcasting.
If a reorg drops a confirming transaction, Fireblocks will promptly update the status (for example, to FAILED or DROPPED_BY_BLOCKCHAIN), ensuring the UI and API are in sync with the actual blockchain state, with no lag or extra margin to "wait for reorgs to resolve"  .The transaction does not revert from CONFIRMING to BROADCASTING. Instead, in the event of a network reorg and the transaction being dropped, Fireblocks marks the transaction as failed, dropped, or expired (for example, with substatus DROPPED_BY_BLOCKCHAIN), not as returned to broadcasting (편집됨)
