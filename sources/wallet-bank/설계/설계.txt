지갑 솔루션 추상화 인터페이스
설계
코어가 특정 솔루션에 의존하지 않도록 공통 인터페이스를 정의한다.
▸주소 발급/서명/전송/조회의 솔루션 중립 계약
▸솔루션 교체 시 코어 무변경 목표

주소 생성 / 관리
개발
사용자별 입금 주소 발급과 생명주기를 관리한다.
▸계정 :양방향_화살표: 주소 매핑은 코어 원장이 원본 보유
▸주소 재사용/폐기 정책

계정 체계 설계(주소 생성 / 관리와 연계된다. 수수료 정책과 연계된다. 멀티체인 네트워크 지원와 연계된다)
개발
사용자 계정, 수수료, 미결, 옴니버스 등 내부 계정 체계를 설계한다.
▸사용자 계정과 운영 계정(수수료, 미결, 대사차이) 분리
▸자산(코인 종류)×체인 차원으로 확장 가능한 구조

트랜잭션 브로드캐스트
설계
외부 이체 요청을 온체인 트랜잭션으로 전송한다.
▸전송 실패/재시도 시 이중 전송 방지
▸논스(nonce) 관리 전략

입금 감지 / 컨펌 정책
설계
체인별 입금 감지와 확정 컨펌 수 정책을 정의한다.
▸체인별 컨펌 수 설정, 재구성(reorg) 대응
▸감지 이벤트의 정확히 한 번(exactly-once) 전달

가스비 관리
식별
출금용 가스 잔액 모니터링과 충전 운영을 정의한다.
▸가스비의 수수료 정책 반영 여부 결정
▸가스 계정 잔액 임계 알림

수수료 정책 (가스비 관리와 연계된다)
설계
거래 유형·구간별 수수료 산정 규칙을 정의한다.
▸유형(이체/온·오프램프/스왑)별 요율 테이블
▸수수료는 별도 원장 계정으로 전기


체인 장애 대응
식별
체인/솔루션 장애가 코어에 미치는 영향을 격리한다.
▸장애 시 온체인 거래만 지연, 내부 거래는 정상 동작
▸복구 후 밀린 거래 순차 처리

멀티체인 네트워크 지원
식별
다른 블록체인 네트워크 추가 시 체인별 어댑터만 추가하고 코어는 무변경을 목표로 한다.
▸체인별 주소 체계·컨펌 정책·수수료 모델 차이를 어댑터 계층에서 흡수
▸동일 자산의 체인 간 이동(브릿지) 포함 여부는 미확정

트래블룰 솔루션 연동
식별
트래블룰 솔루션과의 연동을 담당한다. 지갑 솔루션과 마찬가지로 코어는 솔루션을 모르는 상태로 추상화한다.
▸솔루션 중립 검증 인터페이스 (솔루션 교체 시 코어 무변경)
▸VASP 마스터·주소 귀속 확인 연동
▸솔루션 장애 시 fail-close 동작

거래 상태 머신(트래블룰 솔루션 연동와 연계된다)
설계
거래 유형별 상태 전이를 명시적으로 정의한다.
▸요청→검증→전기→확정/실패 공통 골격
▸온체인 거래는 브로드캐스트/컨펌 상태 추가
▸모든 전이는 이벤트로 기록

외부 vasp

VASP 간 이체 (트래블룰)
거래소 등 외부 VASP 지갑과의 이체. 제휴 계약 없이도 규제(트래블룰)가 강제하는 영역이라는 점에서 외부 지갑 연동(PTN)과 다르다. 판단은 트래블룰 솔루션, 솔루션 연동은 BCM, 순서 강제는 코어가 담당한다.

VASP 식별 / 등록 연계
식별
상대 VASP 등록·화이트리스트·주소 귀속 확인은 트래블룰 솔루션 연동(BCM)으로 처리한다. 코어는 승인/거부 결과만 수신한다.▸
VASP 마스터 데이터는 코어 밖 — 규제 변경이 코어에 전파되지 않는 구조
▸코어는 검증 결과(승인/거부/보류)만 이해하며 판단 근거를 알지 못함
연계 요구사항
INT-05 트래블룰 / AML 연계
BCM-08 트래블룰 솔루션 연동

VASP 향 송신 이체
식별
우리 지갑에서 타 VASP 지갑으로의 이체 절차를 정의한다. 검증 승인 → BCM 전송의 순서는 코어가 강제한다.
▸검증 승인 전 BCM 전달 불가 — 상태 머신으로 순서 보장
▸BCM은 전달받은 건을 무조건 실행 (재검증 없음)
▸상대 VASP 거부 시 거래 처리 규칙
연계 요구사항
INT-05 트래블룰 / AML 연계, BCM-03 트랜잭션 브로드캐스트, LDG-03 거래 상태 머신

VASP 발 수신 처리
식별
타 VASP에서 들어오는 입금의 수신 정보 대조와 잔액 반영 규칙을 정의한다.
▸수신 트래블룰 정보와 온체인 입금의 매칭
▸정보 미도착·불일치 시 보류 처리
연계 요구사항
BCM-04 입금 감지 / 컨펌 정책, INT-05 트래블룰 / AML 연계

반환 처리
식별
규제 검증 실패·상대 거부 건의 반환 절차를 정의한다.
▸반환 사유별 처리 경로 (자동 반환 vs 운영 개입)
▸반환 수수료 부담 주체 결정
연계 요구사항
LDG-03 거래 상태 머신,BCM-03 트랜잭션 브로드캐스트

개인지갑(비수탁) 이체 정책
식별
VASP가 아닌 개인지갑(unhosted wallet)으로의 이체 허용 범위와 검증 절차를 정의한다.
▸개인지갑 이체 허용 여부·한도 별도 정책
▸주소 소유 확인(사전 등록 등) 절차 필요 여부 미확정
연계 요구사항
INT-05 트래블룰 / AML 연계, POL-02 한도 정책

트래블룰 / AML 연계
식별
외부 이체 전 검증 훅(hook) 지점을 정의한다. 판단은 외부 트래블룰 솔루션(BCM 경유)이 하며 코어는 승인/거부/보류 결과만 받아 순서를 강제한다.
▸이체 상태 머신의 검증 대기 상태에서 훅 호출
▸검증 실패/보류 시 거래 상태 처리 (반환 포함)
▸검증 서비스 장애 시 외부 이체 중단 원칙 (fail-close)
연계 요구사항
BCM-08 트래블룰 솔루션 연동,LDG-03 거래 상태 머신

한도 정책
설계
사용자 등급·기간별 거래 한도를 정의한다.
▸일/월/건당 한도, KYC 등급 연동
▸한도 초과 시 거래 거절 vs 보류 규칙
