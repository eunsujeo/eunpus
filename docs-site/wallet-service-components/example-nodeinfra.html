13. 노드 인프라 어댑터 (Infura · Alchemy · GCP BNE)

관리형 RPC 노드 — 자체 구축에서 "노드"만 아웃소싱. 서명·custody 는 여전히 별도
본 페이지의 성격

설명용 의사코드다. Infura·Alchemy·QuickNode·GCP BNE 등은 공개 문서·일반 패턴 기반이므로 적용 전 각 벤더 문서로 확인하라. 이들은 Fireblocks 와 달리 키·서명(custody)을 제공하지 않는다 — RPC 노드 접근만 준다.

13.1 큰 그림 — 노드만 관리형으로

세 어댑터를 한 줄에 놓으면 위치가 분명하다.

  • 11. Fireblocks — custody·서명·노드·webhook 까지 통째로 관리형.
  • 12. 자체 구축 — HSM·노드·인덱서를 전부 자체.
  • 13. 노드 인프라 (이 장) — 그 사이. 노드/RPC 만 관리형으로 빌려 쓰고, 서명·nonce·인덱서는 자체.

즉 12. 자체 구축 의 SelfBuiltProvider 에서 "자체 노드" 자리(NodeRpc 부품)만 Infura·Alchemy·GCP BNE 로 교체하는 것이다. 나머지(서명·nonce 직렬화·인덱서)는 그대로 우리 책임이다. 노드 운영(동기화·업그레이드·가용성)을 벤더에 맡기는 것이 이점.

13.2 어느 메커니즘을 채우나

노드 인프라는 RPC 로 되는 것만 채운다. 키가 필요한 일(서명)은 못 채운다.

포트 · 메커니즘노드 인프라가 주는가
TransferPort — 전파✅ eth_sendRawTransaction
TransferPort — nonce 읽기✅ eth_getTransactionCount (pending)
TransferPort — 상태✅ eth_getTransactionReceipt
TransferPort — 수수료 추정✅ eth_feeHistory · eth_maxPriorityFeePerGas
TransferPort — 서명✗ 제공 안 함 — 자체 HSM/MPC
AccountPort — 잔액✅ eth_getBalance
AccountPort — 주소 발급— 노드 불필요(로컬 xpub 파생)
IndexerPort — 기본 수집✅ RPC 폴링(eth_getLogs). 풍부한 조회·이벤트는 Alchemy enhanced API / 자체 projection

13.3 어댑터 코드 — 노드 슬롯 구현 + 주입

// 노드 인프라 = 관리형 RPC. 12장 SelfBuiltProvider 가 받는 NodeRpc 부품을 구현.
class InfuraNodeRpc implements NodeRpc {
  sendRawTransaction(signed) = rpc('eth_sendRawTransaction', [signed])
  getTransactionCount(addr)  = rpc('eth_getTransactionCount', [addr, 'pending'])  // nonce
  getBalance(addr)           = rpc('eth_getBalance', [addr, 'latest'])
  getReceipt(hash)           = rpc('eth_getTransactionReceipt', [hash])           // 상태
  estimateFee()              = rpc('eth_feeHistory', [...])                        // 수수료
  // ★ 서명 메서드 없음 — 키는 노드 인프라에 없다 (자체 HSM 이 맡음)
  // 멀티 엔드포인트 풀 · failover 는 우리가 (2.5 절)
}

// 조립 : SelfBuiltProvider 는 그대로, NodeRpc 만 Infura 로 주입
new SelfBuiltProvider(
  new InfuraNodeRpc(endpoints),   // ← 노드만 관리형
  hsm,                            //   서명은 여전히 자체 HSM
  nonceMgr,                       //   nonce 직렬화도 자체
  indexer,                        //   인덱서도 자체(또는 Alchemy)
)

세 포트(Account·Transfer·Indexer)를 채우는 건 여전히 SelfBuiltProvider 다 — 노드 인프라는 그 안의 한 부품일 뿐이다. 그래서 지갑 서비스 백엔드 입장에선 12장과 동일하다.

13.5 주의

노드 인프라를 쓸 때 꼭 챙길 것
  • custody 미해결 — 서명·키는 별도다. 자체 HSM/MPC(또는 Fireblocks 같은 custody)와 반드시 페어링.
  • 제3자 노드 신뢰 — eth_call·잔액 응답을 그대로 믿을지, 또는 다중 provider 교차검증을 둘지 결정.
  • 가용성은 우리 책임 — 한 endpoint 가 죽거나 헤드가 뒤처질 수 있으니 멀티 provider 풀·failover 를 직접 운영 (2.5 노드/RPC 접근).
  • 공용 vs 전용 — Infura·Alchemy 는 공용(rate limit·요금), GCP BNE 는 전용 노드. state 일관성·지연·비용 특성이 다르다.

정리하면 — 노드 인프라 어댑터는 자체 구축의 "노드"만 관리형으로 바꾼 형태이고, 기능별 포트 관점에선 10.4 의 "약한 부분만 교체" 의 한 사례다. 처음으로 — 0. Overview.
