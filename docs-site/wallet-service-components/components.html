1. 컴포넌트 개요

7 컴포넌트를 한눈에 — 두 층(블록체인 매니저 엔진 / 지갑 서비스 백엔드)으로

컴포넌트를 나누는 기준은 "기능" 이 아니라 책임 경계다. 즉 "무엇을 결정하고, 무엇을 받기만 하고, 어디서 외부와 맞닿는가" 로 나눈다. 경계가 분명해야 한 컴포넌트의 장애나 변경이 다른 컴포넌트로 번지지 않는다.

7 컴포넌트는 두 층에 속한다
  • 블록체인 매니저 (체인 엔진) — 멀티체인 어댑터 · 인덱서 · 트랜잭션/Nonce/Broadcast · 서명. 체인과 직접 대화하는 부분으로, Fireblocks 가 통째로 제공하거나 자체 구축한다.
  • 지갑 서비스 백엔드 (벤더 무관 · 항상 내 것) — API 게이트웨이 · 온체인 정합성·추적 · 이벤트/알림. 블록체인 특화가 아닌 서비스 로직.

이 두 층을 가르는 경계가 10. 추상화 의 기능별 포트(AccountPort·TransferPort·IndexerPort)다.

1.2 책임 경계 매트릭스

각 컴포넌트가 무엇을 하는지 세 가지로 나눈다 — D=결정(스스로 판단) · X=집행(받아서 실행) · E=외부 위임.

관심사주관 컴포넌트성격
요청 진입 · 멱등API 게이트웨이집행(X)
체인 규칙 정규화멀티체인 어댑터결정(D) — 체인 semantic 한정
수신 트랜잭션 감지 · 확정 판단인덱서결정(D) — 확정 정책 적용

1.3 가벼운 두 컴포넌트

API 게이트웨이

왜 필요
모든 요청의 단일 진입점. 인증·rate limit 과 멱등 키로 "재시도해도 한 번만 실행" 을 보장하는 곳. 이게 없으면 네트워크 재시도가 곧바로 이중 출금으로 이어진다.
하는 일
주소 발급, 송신 트랜잭션 요청(출금), 잔액/상태 조회를 받아 트랜잭션 빌더(쓰기)·온체인 정합성(조회)으로 라우팅. 비즈니스 판단은 안 한다.
경계
얇게 유지 — 로직은 뒤 컴포넌트로 위임.

이벤트 · 알림

왜 필요
상위 서비스·고객이 폴링하지 않고도 수신·확정·송신 완료를 즉시 알 수 있어야 한다.
하는 일
인덱서·트랜잭션·온체인 정합성의 상태 변화를 webhook/스트림으로 push. 재시도·순서·서명 검증.
경계
상태를 만들지 않고 전달만 한다. 멱등 전달(같은 이벤트 중복 수신 대비)을 소비자에게 보장.
범위 밖 (다시 강조)

준비자산 운용(자금)과 회계 원장 대사·기표(회계 평면)는 매니저가 소유·결정하지 않는다. 출금도 매니저가 승인하지 않으며, 승인이 끝난 요청을 받아 집행만 한다.
