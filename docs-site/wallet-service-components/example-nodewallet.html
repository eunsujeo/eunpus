14. NodeWallet 어댑터 (온프렘 custody 제품)

옵션 2(자체 custody)를 직접 짓는 대신 기성 제품으로 — Fireblocks 와 같은 custody 자리, 키는 고객 보유
본 페이지의 성격

설명용 의사코드다. NodeWallet 의 기능 범위는 벤더(NodeInfra) 공개·gated 문서의 자체 주장이며(독립 검증 아님), 메서드 이름은 형태 참고용이다. Solana 전용 제품인 점에 유의. 적용 전 최신 문서로 확인하라.

14.1 큰 그림 — Fireblocks 와 같은 자리, 다른 custody 모델

NodeWallet 은 11.5 의 옵션 2(자체 custody)를 "직접 구축(13장)" 하지 않고 기성 제품으로 도입하는 길이다. 구조적으로는 12. Fireblocks 와 같다 — custody 제품의 SDK 를 얇게 감싸 AccountPort·TransactionPort 를 채우는 어댑터. 다른 건 custody 모델이다.

14.2 어댑터 코드

class NodeWalletProvider implements AccountPort, TransactionPort {
  constructor(private nw: NodeWalletSDK) {}        // Java/Spring SDK

  createAccount(ref)        = nw.createWallet(ref, Chain.SOLANA)   // Solana 전용
  deriveAddress(wallet, _)  = nw.address(wallet)
  getBalance(wallet, asset) = nw.balance(wallet, asset)

  // 제출 한 번 — 내부에서 3-키 다중서명(개시 → 승인 → 실행 SGX)
  submitTransaction(req) {
    return nw.submitTransfer({
      from: req.from, to: req.to, amount: req.amount,
      idempotencyKey: req.idempotencyKey,          // 코어 멱등 키
    })
  }
  getStatus(txRef) = nw.tx(txRef).status
  // bumpFee: Solana 는 EVM nonce 가 없어 재전송 모델이 다름(blockhash 만료) → 제품 정책 따름
}

내 지갑 수신·확정 이벤트는? NodeWallet 이 자체 원장·입금 검증으로 감지해 TransactionPort 의 onChainEvent 로 준다. 다만 임의 외부 주소·커스텀 조회(ChainQueryPort)는 Fireblocks 와 마찬가지로 ✗ — 필요하면 그 포트만 자체 인덱서로 따로 붙인다(11.4). 즉 NodeWallet 도 Account·Transaction 두 포트를 채우는 custody 제품이다.

Figure 14-2. NodeWallet 송신. 어댑터엔 submitTransaction 한 번이지만, 제품 내부에서 개시(코디네이터) → 승인(정책 엔진, 승인 키 co-sign) → 실행(SGX 실행 키 서명) 3-키 의식이 일어난다. 키는 분리된 HSM 파티션/SGX 엔클레이브에 있어 한 서비스가 뚫려도 단독 서명이 안 된다.

정책 엔진이 제품에 내장 — 승인 게이트 중첩 주의

NodeWallet 의 승인자(정책 엔진)가 한도·트래블룰 등 컴플라이언스 정책과 승인 단계(approval tier)를 제품 안에서 집행한다. 우리 상위 비즈니스 레이어의 승인과 역할이 겹칠 수 있으니, "어디서 무엇을 승인하는지" 경계를 한 번 정리해야 한다(이중 승인/공백 방지).

14.5 주의

NodeWallet 을 택할 때
  • Solana 전용 — 멀티체인 지갑이면 NodeWallet 만으론 EVM/BTC 미커버. 체인별로 어댑터를 달리 둬야 함.
  • 승인 중첩 — 제품 내장 정책 엔진과 우리 비즈 레이어 승인의 경계 정리(14.3).
  • 운영 복잡도 — 망분리 IDC·HSM·SGX 운영 부담을 고객이 진다(벤더 무의존의 대가).
  • 근거 tier — 기능은 벤더 자체 주장(독립 검증 아님). 인증(ISMS 등) 상태·범위 확인.

정리하면 — NodeWallet 어댑터는 옵션 2(자체 custody)를 "사서" 채우는 길이다. custody 축에서 보면 12. Fireblocks(SaaS 위탁) · 13. 자체 구축(직접 빌드) · 14. NodeWallet(온프렘 제품 도입) 세 점이고, 매니저 코어는 어느 쪽이든 같은 포트만 의존한다. 처음으로 — 0. Overview.
