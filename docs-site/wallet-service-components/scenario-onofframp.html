10. 온·오프램프 (수탁) — 매니저는 언제 호출되나

현금↔코인 전환은 은행 앱의 내부 DB 작업 — 블록체인 매니저는 온체인 가장자리에서만

앞 시나리오(입금·출금)와 달리, 온/오프램프(현금↔코인 전환)는 블록체인 매니저의 일이 아니다. 수탁(custodial) 지갑에서는 고객의 코인 잔액이 은행 앱 안의 내부 장부(DB) 로 관리되므로, 현금↔코인 전환은 대부분 은행 앱의 DB 변경 + 코어뱅킹 처리로 끝난다. 블록체인 매니저는 실제 온체인 이동이 필요한 순간(외부 입금·외부 출금·준비자산 이동) 에만 호출된다.

그래서 "온/오프램프 커넥터" 는 매니저의 컴포넌트가 아니다

온/오프램프 오케스트레이션(현금 처리 → 코인화 결정)은 은행 앱(상위)의 일이다. 매니저가 제공하는 것은 온체인 입금 감지(인덱서)와 외부 출금(트랜잭션 빌더·서명)뿐이다. 그래서 본 가이드는 온/오프램프를 컴포넌트가 아니라 "은행 앱이 매니저를 언제 호출/미호출하는가" 시나리오로만 다룬다. (전제: 은행이 만드는 수탁 지갑 앱)

10.1 온/오프램프 = 은행 앱의 내부 DB 작업 (매니저 미호출)

고객이 현금을 코인으로(온램프) 또는 코인을 현금으로(오프램프) 바꿀 때, 자산은 밖으로 나가지 않는다. 은행 앱 안에서 코어뱅킹 잔액과 수탁 코인 잔액(DB)만 서로 조정될 뿐이다.

매니저는 자산이 실제로 체인을 건너는 순간에만 등장한다.

10.3 정리

  • 온/오프램프는 은행 앱의 오케스트레이션 — 현금 처리(코어뱅킹) + 코인 잔액(수탁 DB) 조정. 매니저 밖.
  • 수탁이라 내부 이동은 DB로 충분 — 코인이 실제로 체인을 건너지 않으면 온체인 tx 가 없고, 매니저도 부르지 않는다.
  • 매니저는 온체인 가장자리 전용 — 외부 입금(인덱서)·외부 출금(트랜잭션 빌더·서명)·준비자산 이동에서만.
