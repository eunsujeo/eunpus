1. 문제 — EVM 의 gas 는 발신 계정에서 나간다

수탁 지갑에서 gas 가 아픈 두 지점, 그리고 "운영 목적의 ETH 상시 보유"라는 부담
본 페이지의 출처

Fireblocks Gasless Service · Gas Station 내용은 Fireblocks 공식 문서(헬프센터·개발자 문서)에서 확인한 사실이다. GSN · ERC-4337 Paymaster 절은 일반 EVM 표준에 대한 저자 정리로, 본인 환경 적용 전 1차 자료 검증을 권장한다. 미확정으로 표시한 항목(정산 단가 등)은 Fireblocks 담당 매니저(CSM)나 지원팀(Support)에 확인할 대상이다.

EVM 은 토큰(USDC 등)을 보낼 때도 수수료(gas)를 base asset(ETH)으로, 발신 계정에서 차감한다.

지점왜 아픈가
고객 vault → 중앙 vault 이동(sweep)고객별 vault 수만 개 각각에 ETH 가 있어야 그 안의 토큰을 옮길 수 있다 — ETH 배포·잔고 모니터링·충전이 대량 운영이 된다.
운영 전반의 ETH 보유gas 용 ETH 를 상시 조달·보관해야 한다 — 은행 관점에서 "운영 목적의 가상자산 상시 보유"는 재무·회계·리스크 처리 부담이 크다.

"ETH 필요 없음"은 토큰 전송 기준이다 — 공식 문서가 명시한다: Universal Gasless 는 ETH 네이티브 전송을 대납하지 않으며, ETH 자체의 이동(sweep)은 Gas Station 몫이다. 우리 서비스는 스테이블코인 전용이라 ETH 자체를 취급하지 않으므로, ETH-free 운영이 된다.

3. Fireblocks Gasless Service — 확정 사실

Gas Station 과 별개 제품 · ERC-3009 / ERC-2771 / EIP-7702 · Universal Gasless 는 vault 를 smart contract wallet 로 upgrade

지원 토큰의 fee 지불을 전용 vault / 외부 워크스페이스 / Fireblocks 에 위임하는 서비스다. 공식 문서가 명시한다 — "Gasless Service 는 Gas Station 과 별개 제품이고, 다른 프로토콜을 쓴다."

항목내용
메커니즘ERC-3009 · ERC-2771 · EIP-7702 — ERC-4337 paymaster 가 아니다.
Limited Gasless (구)이더리움의 USDC·DAI(ERC-3009) + tokenization mint/burn(ERC-2771)에 한정.
Universal Gasless (신)EIP-7702(Pectra?) 기반 — 첫 gasless 거래 때 vault(EOA)가 smart contract wallet? 로 자동 upgrade 된다. 이후 모든 이더리움 자산(ERC-20/721/1155)의 Transfer · Contract Call · Mint · Burn 을 지원.
지원 체인 (Universal)Ethereum(1) · Optimism(10) · Base(8453) · Arbitrum(42161) · Polygon PoS(137) · BSC(56) + 각 testnet. Solana·Tron(GasFree)은 별도 메커니즘.
설정Console: Settings → General → Gasless transactions — relay 3택 + 기본값 3모드(On by default / Off by default / Off, 거래별 재정의 가능) + Policies 연동.
API트랜잭션 API 에 Gasless(meta-tx) 경로 존재 — 미설정 시 error 1455 "Missing Gasless configuration (relayer/fee payer)".
Fireblocks Relay 지원 범위위 표(Universal 통합 6체인)와 별개로 Relay 서비스 자체는 "모든 EVM 호환 체인 + 그 위 모든 토큰" — 일부 non-EVM(특정 USDC 오퍼레이션 포함)은 CSM 문의.
도입 절차 (Fireblocks Relay)Console 설정(Fireblocks relay 선택) → Support 요청 → CSM 협의(대상 체인 · 월 거래량 · 유스케이스) → 서비스 계약 서명 → 활성화.

gasless 거래 한 건의 흐름. 발신 vault 에 ETH 가 없어도 토큰이 이동하고, gas 는 지정 relay 가 낸다. 상태 전이·확정 판정(DCCP·numOfConfirmations)은 일반 거래와 동일하다.

운영 caveat — 대납이어도 남는 것
  • 새 실패 모드가 생긴다 — 공식 문서 명시: relay 가 요청을 거절하거나 gas 를 대지 못하면 gasless 거래는 실패한다. relay 상호작용은 서명·거래 생성 단계(체인 전송 전)에 일어나므로, 상태 처리에 "relay 거절" 실패 사유가 추가되고 relay 잔고·정책이 모니터링 대상이 된다.
  • 제시한 fee 가 낮아 체인에서 처리되지 않고 대기 중인 거래(stuck)를 자동으로 재촉해 주지 않는다 — 공식 문서 명시: Gasless Relay 는 auto-boost 를 지원하지 않는다. 수동 RBF boost 가 필요하므로, 막힘 점검과 boost·cancel 운영은 대납을 써도 그대로 필요하다.
  • 비용이 사라지는 게 아니라 지불 수단이 바뀐다 — 온체인 ETH → 월말 청구서(법정화폐). 정산은 회계 층의 일이 된다. 단가·구독료 수준은 미확정(CSM 확인 대상).
  • MPC 서명 ↔ EIP-7702 위임의 내부 동작은 공식 문서에 상세가 없다 — PoC/CSM 확인 대상.

4. 일반 표준과의 구분 — GSN · ERC-4337 Paymaster

같은 문제를 푸는 두 일반 표준 — Fireblocks 는 이 둘을 그대로 쓰지 않는다 (저자 정리)
GSN (Gas Station Network)ERC-4337 Paymaster
무엇meta-transaction relay 네트워크 — 사용자는 서명만 하고, relayer 가 대신 온체인 제출하며 gas 를 낸다account abstraction 의 gas 대납 컨트랙트 — UserOperation 의 gas 를 스폰서하거나 ERC-20(USDC 등)으로 받는다
전제수신 컨트랙트가 ERC-2771(trusted forwarder)을 지원해야 — 일반 ERC-20 전송엔 못 쓴다지갑이 smart account 여야 + EntryPoint·bundler 인프라
왜 쓰나ETH 없는 사용자의 온보딩 UXgasless UX · 토큰으로 수수료 · 스폰서십
체인EVM (컨트랙트가 지원할 때)EntryPoint 가 배포된 EVM 전반 — Base 생태계가 활발
현황생태계가 4337 로 이동 — GSN 자체는 쇠퇴 계보account abstraction 표준의 주류

관계 정리 — Fireblocks 는 GSN "네트워크"가 아니라 ERC-2771 표준을 자체 relay 로 구현했고, paymaster(4337) 대신 EIP-7702 노선을 택했다. Fireblocks 의 "Gas Station"(충전 자동화)은 GSN 과 이름만 유사할 뿐 무관하다. 이 두 표준은 사용자가 자기 지갑에서 직접 거래를 보내는 모델의 도구라, 모든 거래를 수탁자 vault 가 발신하는 모델에서는 Fireblocks Gasless 가 같은 자리를 대신한다. 두 표준의 구성요소·흐름·정산 구조는 6~10장 일반 표준 상세에 있다.

5. 결정 포인트

ETH 없이 되나 · 충전과 대납 중 무엇을 · 기존 설계에서 바뀌는 것 · 남은 확인
질문답
ETH 없이 운영이 되나Fireblocks Relay 면 토큰 운영 기준으로 가능 — "even if you do not hold any ETH". ETH 자체 취급 물량은 별도.
충전(Gas Station)은 왜 안 쓰나결정: Universal Gasless 단일. 서비스가 스테이블코인 전용이라 대납이 안 되는 자산(ETH 자체의 이동)이 애초에 없다 — 충전 경로를 두지 않는다.
기존 설계에서 바뀌는 것감지·확정 판정, 막힘 점검·boost 운영은 그대로. 바뀌는 건 gas 조달 운영 → 월말 인보이스 정산(회계 층).
도입하면 설계가 어떻게 달라지나① Admin — TAP 정책 2종(upgrade policy·Orchestrator rule) 운영 추가 ② 감지·상태 — "relay 거절" 실패 사유 추가, relay 잔고 모니터링 ③ 회계 — gas 운영이 월말 인보이스 대사로 이동 ④ sweep — 전량 Gasless (스테이블코인 전용) ⑤ estimateFee — 우리 비용 추정에서 relay 비용 예측·인보이스 검증으로 역할 이동.
남은 확인인보이스 단가·구독료, MPC↔7702 내부 동작 — CSM/PoC. (ETH 네이티브 전송의 대납 불가는 확정 — 스테이블코인 전용이라 해당 없음)

관련 문서 — 감지·확정 기준은 지갑 설계 워크스루 4장, 수수료 견적은 6장, 출금·boost 는 7장.
