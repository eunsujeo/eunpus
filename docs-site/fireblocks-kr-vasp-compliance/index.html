국내 블록체인 사업 법규 × Fireblocks — 어디까지 풀리고 어디부터 막히는가

한국에서 수탁형 또는 거래중개형 가상자산사업자 (VASP) 로 사업할 때 적용되는 법규를 Fireblocks 의 어떤 기능이 풀어주고, 어떤 부분은 풀어주지 않는지를 정직하게 정리한 reference. "풀린다" 와 "안 풀린다" 의 경계를 흐릿하게 두지 않는 것이 본 문서의 목적.

본 페이지의 출처 — 어디까지가 공식 사실이고, 어디부터가 저자 추정인가

이 문서의 내용은 두 갈래입니다.

공식 문서에 정의된 사실 — 그대로 받아도 안전

  • 한국 법령·규정의 시행일·조문·임계값 — law.go.kr / fsc.go.kr 원전 출처
  • 최근 종합검사 결과 — 금융위 / 금감원 보도자료
  • Fireblocks 의 기능 — Help Center 의 명시적 기재 사항

저자가 합리적으로 추정한 매핑 — 참고용, 본인 환경 검증 권장

  • "이 KR 의무는 이 Fireblocks 기능으로 풀린다" 의 매핑 자체 — 공식 문서에 명시되지 않은 운영 권장
  • Fireblocks SaaS 가 KR 전자금융감독규정의 망분리 해석에 부합하는지 — 별도 검증
  • Fireblocks 가 "금융회사의 정보처리 업무 위탁에 관한 규정" 의 외주 위탁 대상인지 — 별도 검증

10 초 요약 — 4 줄로

  • Fireblocks 는 도구. 법규를 푸는 주체는 사업자 자신. Fireblocks 는 거버넌스 + 거래 통제 + 감사 trail 의 기술 인프라.
  • 풀리는 것 — Policy 엔진, AML/Travel Rule provider 통합, Audit Log, MPC 거버넌스, Whitelist, Cold Wallet workspace 분리.
  • 안 풀리는 것 — 신고제 자체, 실명확인 입출금계정, ISMS 인증, 보험·준비금, 영업행위 규율, 법인 설립, 평가전문기관 취약점 평가.
  • 가장 큰 함정 — 4 종합검사 (두나무·코빗·빗썸·코인원) 의 위반은 모두 도구 부재 가 아니라 운영 통제의 부재. Fireblocks 가 있어도 운영 규율이 없으면 동일 위반.

이 문서가 다루지 않는 것

  • 한국 외 다른 관할 (미국 / EU / 영국 / 싱가포르) — 비교만 참고. 운영 가이드 아님
  • Fireblocks 가 아닌 다른 vendor (BitGo / Anchorage / Copper) — 본 문서는 Fireblocks 한정
  • 법인 설립·자본금·이사회 구성 등 회사법 영역
  • 특정 토큰의 증권성 분석 (자본시장법 / SEC 관할)
  • 금감원·금융위의 비공개 가이드라인 — 공식 공개 문서만 사용

가장 자주 받는 질문 — 3 가지

Q1. "Fireblocks 만 쓰면 한국 VASP 컴플라이언스가 끝나나요?"

아니오. Fireblocks 는 지갑·거버넌스·감사 도구. 신고제·실명계정·ISMS·보험·법인 설립·KYC 시스템 등은 별도. 대부분 시간이 더 걸리는 것은 도구가 아니라 은행 실명계정 발급 과 FIU 신고 심사 3개월.

Q2. "콜드월렛 80% 는 Fireblocks Cold Wallet 하나로 끝나나요?"

아니오. Cold Wallet workspace 는 격리 인프라이지만, "이용자 가상자산의 80% 가 cold 에 있다" 의 검증은 사업자의 일일 reconciliation 에서 일어남. Fireblocks 는 vault balance 를 보여줄 뿐. 경제적 가치 환산 / 이용자 자산 vs 자기 자산 구분 / 매일 검증·기록은 사업자 책임.

Q3. "두나무·빗썸·코빗·코인원 처럼 제재 받는 걸 Fireblocks 가 막아주나요?"

부분적으로만. 4 종합검사의 공통 위반은 ① 미신고 해외 VASP 거래 차단 실패, ② KYC 재이행 실패, ③ 신규 서비스 위험평가 누락. ①과 ②의 차단 메커니즘은 Fireblocks Policy/TAP 으로 구현 가능. 하지만 운영 절차·정책 결정·인사 책임자 지정 은 사업자. 즉 Fireblocks 가 있어도 운영 규율이 없으면 동일 위반. 자세히는 5. 제재 사례와 도구 매핑.
