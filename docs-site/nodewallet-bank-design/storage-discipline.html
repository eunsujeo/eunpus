NEVER STORE — 절대 영속화 금지

DB / 디스크 / 캐시 절대 저장 금지
  • 키 자료 (plaintext) — HSM 또는 SGX 봉인 외부로 plaintext 가 나가지 않는다. HSM 은 PKCS#11 으로만 접근, SGX 는 sealed blob 만 디스크.
  • 마스터 키 평문 — HSM 내부에서 만들어지고 RSA-OAEP wrap 후 enclave 로 전달. 평문이 HSM / enclave 경계를 한 번도 건너지 않는다.
  • ★ Hypothesis (vendor 의 D1a 일반 invariant) — PIN · 패스코드 · 고객 비밀 정보도 approverdb / ledgerdb / chaindb / auditdb 에 저장 금지.

강제 패턴 — prevent_mutation() trigger

CREATE FUNCTION prevent_mutation() RETURNS trigger AS $$
BEGIN
  RAISE EXCEPTION 'append-only: % not allowed on %', TG_OP, TG_TABLE_NAME;
END $$ LANGUAGE plpgsql;

CREATE TRIGGER policy_decisions_no_mutation
  BEFORE UPDATE OR DELETE OR TRUNCATE ON policy_decisions
  FOR EACH STATEMENT EXECUTE FUNCTION prevent_mutation();
-- signing_events · key_lifecycle · master_key_operations 등에 동일 적용

★ trigger 함수의 정확한 구현은 vendor docs 미명시. 위 PL/pgSQL 은 추정 — MySQL / Oracle 로 install 되면 stored function 형태로 변환.

강제 패턴 — set-once trigger

-- 예시: auth_approver_sig 의 set-once
CREATE FUNCTION enforce_set_once_sig() RETURNS trigger AS $$
BEGIN
  IF OLD.auth_approver_sig IS NOT NULL THEN
    IF NEW.auth_approver_sig IS DISTINCT FROM OLD.auth_approver_sig THEN
      RAISE EXCEPTION 'auth_approver_sig is set-once';
    END IF;
  END IF;
  RETURN NEW;
END $$ LANGUAGE plpgsql;

CREATE TRIGGER held_withdrawals_set_once
  BEFORE UPDATE ON held_withdrawals
  FOR EACH ROW EXECUTE FUNCTION enforce_set_once_sig();

MUTABLE WITH CHANGE LOG — admin 가능 + audit append

policy_rules · condition_sets · condition_set_items 가 이 class. 변경마다 policy_change_log 에 old_data / new_data / created_by / changed_at 이 자동 INSERT.

-- 예시: policy_rules 변경 자동 로그
CREATE FUNCTION log_policy_change() RETURNS trigger AS $$
BEGIN
  INSERT INTO policy_change_log
    (table_name, row_id, action, old_data, new_data, created_by, changed_at)
  VALUES
    (TG_TABLE_NAME, NEW.id,
     CASE TG_OP WHEN 'INSERT' THEN 'CREATE'
                WHEN 'UPDATE' THEN 'UPDATE'
                WHEN 'DELETE' THEN 'DELETE' END,
     to_jsonb(OLD), to_jsonb(NEW),
     current_setting('app.current_user'), now());
  RETURN NEW;
END $$ LANGUAGE plpgsql;

RUNTIME-ONLY — 메모리만

vendor docs 가 explicit 하게 enumerate 하지는 않지만 구조적으로 도출 (★ Hypothesis on enumeration):

  • Active rule snapshot — 승인자의 ArcSwap 이 들고 있는 atomic 규칙 set. 변경 source 는 DB 의 policy_rules + policy_change_log 이지만 hot 평가는 in-memory snapshot.
  • DCAP attestation quote — 세션별 생성. 결과 enclave 공개키는 등록 시 한 번 저장되지만 attestation quote 자체는 store 하지 않음.
  • Enclave 세션 state — TLS / CBOR IPC 의 세션 nonce + 채널 state.
  • Pre-computed EvaluationContext — in-flight 요청의 잔액 · 일일누적은 계산 후 evaluation 완료 시 휘발.
  • SGX EPC 메모리 — 마스터 키 · BIP-44 파생 키 · 중간값은 서명 직후 제로화.

storage class 가 무너지는 anti-pattern

  • 운영 권한과 application 권한 미분리 — DBA 가 superuser 권한으로 prevent_mutation trigger 우회. 운영 권한은 read-only · 권한 escalation 은 별도 의식.
  • auditdb를 일반 DB 와 같은 backup 정책 — auditdb 는 longer retention + WORM archive. 일반 backup 으로 rotate 시 forensic 손실.
  • set-once 컬럼을 application 단에서만 강제 — DB trigger 가 없으면 향후 migration / hotfix 가 우회 가능.
  • runtime-only 를 캐시에 저장 — Redis 등 외부 캐시에 evaluation context 를 영속화하면 race condition · stale data risk.

은행 도입 시 결정해야 할 것

  • DB 권한 분리 — application user (INSERT/SELECT only) · admin user (rule 변경) · auditor user (SELECT only) · DBA (구조 변경만, data DML 권한 없음).
  • WORM archive 채택 — auditdb 의 오래된 row 를 어떤 스토리지로 ship. AWS S3 Object Lock · 자행 storage solution.
  • change-log retention — policy_change_log 가 정책 변경 평생 보존. row 크기 × 변경 빈도 → 저장 sizing.
  • migration 정책 — schema 변경 시 trigger 도 함께 update. trigger drop → migrate → recreate 의 risk 윈도우를 어떻게 다룰지.
  • SET-ONCE 우회 발견 시 절차 — set-once 가 깨졌다는 사실이 detect 되면 그 결정의 신뢰가 무너진다. detection 도구 + incident 절차.
