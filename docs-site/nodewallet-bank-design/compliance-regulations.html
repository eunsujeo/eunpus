은행 도입 시 결정적 임계 (Stage 37 ingest)
  • 콜드월렛 80% — 이용자 가상자산의 경제적 가치 80% 를 인터넷과 분리. NodeWallet 은 hot wallet 인프라이므로 자체적으로는 ≤ 20% 만 보관. 나머지 80% 는 별도 cold workspace 필수 (외부 또는 Fireblocks Cold Wallet 등).
  • 트래블룰 100만원 — 시행령 제10조의10. 100만원 이상 출금 시 송·수신인 이름 전송 실패 시 출고 차단 필수.
  • 기록보존 5년 — 특금법 제5조의4. auditdb 의 모든 evidence 가 5년 archive.
  • 신규 신고 심사 3개월 / 변경 45일 — NodeWallet 의 vault 주소 / 신규 자산 추가 시 변경신고 필수.

특금법 — 자금세탁 방지 + 트래블룰의 한국 기반

특금법은 한국에서 VASP 의 등록 · KYC · AML · 트래블룰 의무를 정의한다. 노드월렛 은행 도입 시 은행이 직접 VASP 등록의 주체 (커스터디 / 송금 등) 가 되거나, 자행 고객 대상으로만 운영하는 경우 (in-house custody) 가 된다.

  • 고객 신원 확인 — 외부 KYC 시스템 (은행의 기존 시스템) 과 결합
  • 의심거래 보고 — auditdb 의 결정 + 트랜잭션 export 가 보고서 source
  • 위험 평가 기반 차등 — approval_tier 의 금액 구간으로 표현

EFTA — 전자금융거래법

전자금융기관 / 은행이 전자금융 서비스를 제공할 때의 안정성 · 보안 · 사고 대응 의무. 노드월렛 매핑:

  • 영업시간 운영 — time_window 룰로 영업시간 외 차단
  • 사고 대응 — global_halt kill-switch + 24h Held TTL 의 자동 안전 기본값
  • 보안 조치 — HSM (FIPS 140-3 L3) + 망분리 + 3-key 다중서명
  • 인증 — KCMVP / 보안기능확인서 / GS (NodeInfra 진행 중) + 은행의 ISMS / 정보보호경영시스템

VACPA — 가상자산이용자보호법

2023 시행. 고객 가상자산의 분리보관 · 자산 보호 · 핫/콜드 분리 등 요구.

NodeWallet 의 트래블룰 책임 경계

트래블룰은 두 단계로 나뉜다:

  1. 카운터파티 식별 — 수신 주소가 어느 VASP 의 hot wallet 인지 식별
  2. 정보 교환 — 송수신자 정보를 카운터파티 VASP 에 전달 (TRP / Sygna / Notabene 등)

NodeWallet 은 첫 단계의 기술 통제만 담당 — 미식별 주소로의 출금을 차단. 정보 교환은 외부 솔루션.

자기 보관 (self-custody) 처리

EU TFR 2023/1113 은 1,000 EUR 초과 자기 보관 지갑 송금 시 추가 의무. NodeWallet 운영 패턴:

  1. 미식별 주소 (VASP 화이트리스트 외) 에 대한 출금에 approval_tier 의 SINGLE_APPROVE 적용
  2. 운영자가 KYC 시스템에서 고객이 자기 보관 신고를 했는지 확인 후 결정 채널을 통해 해소
  3. 미신고 자기 보관 주소는 정책 변경 없이 Held 만료 (24h) → 자동 Deny

AML / KYC general

NodeWallet 의 책임 범위:

  • KYC 는 NodeWallet 책임 아님 — 외부 시스템의 KYC 결과를 입력으로 받는다. 자기 보관 신고 등.
  • AML — address_cooldown + velocity_window + audit log export 로 의심거래 패턴 검출 + 보고서 제공
  • sanctions screening — address_list blacklist 모드로 제재 명단 차단. 명단 큐레이션 procedure 는 NodeInfra 내부 cert pack (aml-sanctions-coverage.md) 에 명시

한계 (vendor 자기서술)

  • 정보 교환 미포함 — NodeWallet 은 차단/허용만. 카운터파티 VASP 에 정보 전달은 외부 솔루션.
  • VASP 식별 정확도 의존 — 잘못 식별된 주소 (non-VASP 인데 화이트리스트에 포함) 는 보안 게이트 약화.
  • 체인 메모 미검사 — 일부 트래블룰 구현은 트랜잭션 메모 필드에 ID 첨부. NodeWallet 은 메모 내용을 평가에 사용하지 않음.
  • VACPA 의 cold/hot 분리 — 노드월렛은 hot 인프라. 콜드 보관은 외부 설계.

은행 도입 시 결정해야 할 것

  • VASP 명단 source — 한국 금융정보분석원 (KoFIU) 등록 VASP 명단 + 자체 검증 큐레이션 + 정기 import 주기.
  • KYC 시스템 통합 — customer_ref 와 KYC 시스템의 join key. 자기 보관 신고 여부 lookup 의 SLA.
  • 트래블룰 외부 솔루션 — TRP / Sygna / Notabene / Chainalysis Travel Rule 중 선택. NodeWallet 의 export API 와 통합.
  • 의심거래 보고 (STR) — auditdb export → KoFIU 양식 변환 / 자동 제출 절차.
  • 제재 명단 — UN / OFAC / EU / 한국 자체 명단의 통합 import 와 정기 refresh.
  • VACPA 분리보관 — application layer 의 회계 분리 + 보고서 생성.
