6.3 KR 망분리 / IDC 구성

KR 금융권 IT 망분리 (전자금융감독규정) 환경에서 Fireblocks Cold Wallet 의 배치 옵션. 참고로 KR 가상자산업감독규정 9조 가 별도로 이용자 가상자산의 80% (경제적 가치) 콜드월렛 보관 의무를 부과. (출처: KR 컴플라이언스 가이드 · law.go.kr admRulSeq=2100000244180)

옵션구성장단점
옵션 A — All-SaaS Hot + Cold 모두 Fireblocks SaaS. 은행은 망분리 환경에서 인터넷 segment 의 Console 접근 단말만 운영. 구축 단순. 단 모든 자산 plane 이 Fireblocks 의존. 망분리 규정 해석에 따라 부적합 가능.
옵션 B — Hosted MPC + Cold Hot 은 Hosted MPC (customer-side SGX), Cold 은 SaaS Cold workspace. Hot 의 sovereign key. BCM + Hosted MPC operational burden (Risk-S09).
옵션 C — Key Link + Cold Hot 은 Key Link (customer HSM 직접 보유), Cold 은 SaaS Cold workspace 또는 customer HSM Cold mode. 최대 sovereign. Beta 상태 / Customer Server SPOF.
옵션 C-Thales — Key Link + Thales Luna HSM Fireblocks KeyLink ("secure middleware") ↔ Thales Luna HSM (FIPS 140-3 L3 + Common Criteria 인증) 통합. Hot · Warm · Cold 3-mode signing workflow 지원 (air-gap = USB/SFTP/data diodes). 2025-09-23 vendor 공식 발표 옵션. PQC readiness. KR 미명시 — HKMA / HKSFC / JFSA 만 명시. KR 적용 시 Fireblocks Sales 협의 필요.
옵션 선택 — KR 은행의 일반 권장

망분리 + KR 특금법 cold 요건 + 운영 단순성 균형에서 옵션 A → 옵션 B 로의 단계적 도입이 일반적. 처음부터 옵션 C 도입은 Key Link risk (Customer Server SPOF 등) 부담 큼. KR 금융감독 해석에 따라 변동 가능 — 본 권장은 저자 추정.

4 종합검사 공통 위반 사유 — 은행 도입 시 직접 적용

두나무 (2025-02), 코빗 (2025-12), 빗썸 (2026-03), 코인원 (2026-04) 4 사 종합검사의 공통 위반은:

  1. 미신고 해외 VASP 와 거래 차단 실패 — 두나무 44,948건 / 빗썸 45,772건. Cold workspace 의 whitelist · denylist 양방향 등록이 1차 방어선.
  2. 고객확인 재이행 실패 — 만료 자동락, 주소 검증, 원본성 점검, 위험등급 상향 시 추가 CDD 자동 발동.
  3. 신규 자산·서비스 출시 전 AML 위험평가 누락 — 코빗 NFT 신규 지원 전 미실시 655 건. 제품승인위원회 필수.

4 사 모두 영업일부 정지 · 과태료 · 대표 문책경고. 빗썸 = 영업일부 정지 6 개월 + 과태료 368 억원. 은행은 동일 통제가 첫날부터 작동해야. (출처: KR 컴플라이언스 가이드)

6.7 일일 운영 체크리스트

  • ☐ Audit Log 추출 (Hot + Cold 양측)
  • ☐ "Less than 10% remaining signatures" alert 확인
  • ☐ Hot 잔액 vs Cold 잔액 reconciliation
  • ☐ 의심 거래 review (TAP 규칙 트리거 여부)
  • ☐ IP allowlist 변경 모니터링
  • ☐ User add / delete request 처리
  • ☐ Rebalancing 임계점 확인 (Hot < Y% 또는 Hot > X%)
  • ☐ Fireblocks status page 모니터링 (SaaS outage 사전 인지)

6.8 분기 / 반기 점검

  • ☐ Recovery Passphrase Periodic Verification (월 1회 권장)
  • ☐ Workspace Keys Backup 재생성 (변경된 user / quorum 반영)
  • ☐ Testnet 에서 DR rehearsal (production keys 사용 금지)
  • ☐ Cold device sign capacity audit ("Less than 10%" 도달 전 사전 교체)
  • ☐ Admin Quorum 인원 audit (Threshold ≥ 2 유지 / API Admin 보유 시 ≥ 3)
  • ☐ IP allowlist 갱신 (VPN / NAT 변경)
  • ☐ Policy / Whitelist 일관성 audit
  • ☐ KR 특금법 cold 비율 reporting
