1. Cold Wallet 이란 — Fireblocks 의 정의

Fireblocks Cold Wallet 은 "hot 과 별개의 workspace product". SaaS MPC 의 변종 product line 이며, offline storage 를 위한 별도 구매 (separate purchase) 가 필요하다.

본 페이지의 출처

공식 문서에 정의된 사실

  • 5-level 계층 (Customer Domain → Workspace → Vault Account → Asset Wallet → Deposit Address) — Fireblocks Account and Wallet Structure
  • Workspace 의 Hot / Cold + Mainnet / Testnet 두 직교 축 — Fireblocks Account and Wallet Structure
  • "Fireblocks Cold Wallet workspace 별도 구매" — Fireblocks Vault Structure Best Practices
  • Multi-workspace 6 trigger — Fireblocks Vault Structure Best Practices
  • 15 PDF cluster 의 문서명 — Fireblocks Help Center

저자가 합리적으로 추정한 운영 권장 — 참고용

  • 3 workspace 최소 시작 권장 (Hot-Mainnet + Hot-Testnet + Cold-Mainnet)
  • 15 PDF cluster 의 본문이 wiki 에 미적재 → Cold device hardware spec, signing ceremony 등은 공식 본문에서 확인 필요

1.1 정의 — workspace type 의 직교 축

Fireblocks 의 5-level 계층 (Customer Domain → Workspace → Vault Account → Asset Wallet → Deposit Address) 에서, Workspace 는 두 직교 축으로 분류된다. (출처: Fireblocks 공식 문서 — Account and Wallet Structure)

축값설명
축 1 — 온 / 오프라인 Hot workspacehot wallet 보유, online 운영
Cold workspacecold wallet 보유, offline storage, 별도 product
축 2 — Network Mainnet workspacestaging + production, Mainnet node 만 연결
Testnet workspacesandbox + development, Testnet node 만 연결
두 축의 직교성

은행이 Fireblocks 를 도입할 때 실제 workspace 수 = (Hot 또는 Cold) × (Mainnet 또는 Testnet) × (use case 별 multi-workspace). 따라서 최소 Hot-Mainnet + Hot-Testnet + Cold-Mainnet 3 개로 시작하는 경우가 흔하다 (저자 추정).

1.2 별도 product 인 이유

Fireblocks Vault Structure Best Practices 의 직접 인용:

"Offline 보관 필요 시 Fireblocks Cold Wallet workspace 별도 구매 → hot workspace 와 rebalancing"

(출처: Fireblocks 공식 문서 — Vault Structure Best Practices)

→ Cold Wallet 은 hot workspace 의 옵션이 아니라 독립 product. 별도 구매 = 별도 라이센스 / 별도 계약 / 별도 인프라 / 별도 console 접근권.

1.3 Multi-workspace 6 trigger 중 #6

Fireblocks Vault Structure Best Practices 는 "single workspace 로 충분한가 vs 별도 workspace 가 필요한가" 의 6 가지 trigger 를 명시한다. 그 중 #6 이 Cold Wallet 분리. (출처: Fireblocks 공식 문서 — Vault Structure Best Practices)

#Trigger은행 도입 적용
1독립 client set / policy / 양쪽 — sub-company 분리계열사 · 자회사 분리 시
2End client / investor 에 workspace access 제공기관 고객 직접 접근
3Employee viewing privilege 차등부서별 자산 가시성 분리
4다른 configuration (AML default, DeFi cap, Raw Signing)국내 · 해외 / 자영 · 고객 자산 분리
5별도 geographical location해외 법인 분리
6Cold Wallet 분리 (offline regulation 충족)KR 가상자산업감독규정 9조 — 콜드월렛 80%

1.4 Cold Wallet 의 3-domain cross-cut

Fireblocks Cold Wallet 클러스터 카탈로그에 따르면, Cold Wallet 은 3 개 도메인에 동시 직격한다 — Workspace Management / Security-Access / Mobile-Recovery. (출처: Fireblocks 공식 문서 — Cold Wallet cluster)

DomainCold Wallet 이 미치는 영향관련 페이지
Workspace Management Cold Wallet = 별도 workspace type. Mainnet / Testnet 와 직교 2. Workspace 토폴로지
Security-Access Admin Quorum 의 "Cold Wallet 특수 규칙" + Approval Group 미지원 (Risk-G07) + Vault Structure BP 의 "Cold Wallet 별도 구매" 3. 거버넌스
Mobile-Recovery Cold Wallet device key share backup (Mobile 의 cloud backup model 과 비교점) 5. Signing

1.5 Fireblocks Help Center 의 Cold Wallet 전용 문서 15 건

Fireblocks 의 공식 Help Center (support.fireblocks.io) 에는 Cold Wallet 운영을 위한 별도 문서 묶음이 15 건 분류되어 있다. 이 15 건의 문서명을 아래에 나열한다. 각 문서의 본문은 Fireblocks Help Center 에 로그인해야 열람 가능하며, 본 문서 작성 시점 기준 일부 문서의 본문 정밀 인용은 확보되지 않은 상태이다.

즉 본 페이지의 "Cold Wallet 절차" 설명은:

  1. 아래 15 건의 문서 제목 + 다른 인접 Fireblocks 공식 문서 (Account and Wallet Structure / Vault Structure Best Practices / Approval Groups / Admin Quorum / Audit Log / Mobile Device Requirements 등) 의 명시적 사실
  2. + 인접 사실로부터의 합리적 추정 (저자 추정)

으로 구성된다. 15 건 본문의 1:1 인용이 아니다. 정확한 단계별 절차 (예: provisioning ceremony, signing ceremony) 는 Fireblocks Help Center 의 해당 원문 또는 Fireblocks Sales / Support 협의 권장.

분류Fireblocks Help Center 의 공식 문서명 (15 건)

Device Cold Wallet Device Requirements · Cold Wallet Enhanced Console Experience
Workspace ops (Support 경유) Adding users to a Cold Wallet workspace · Adding API keys to a Cold Wallet workspace · Deleting a user from a Cold Wallet workspace

Provisioning Provisioning an Owner's Cold Wallet Device · Provisioning a Signer's Cold Wallet Device

본 문서가 답하지 못하는 항목 — Fireblocks 원문 또는 Sales 협의 필요

위 15 건 문서의 본문 정밀 인용이 없어, 다음 항목은 본 문서가 정확히 답하지 못한다:

  • Cold Wallet device 의 하드웨어 사양 (별도 hardware? 별도 mobile? air-gapped PC?) — Cold Wallet Device Requirements 원문 필요
  • Owner / Signer cold device provisioning 의 단계별 절차 — Provisioning an Owner's / Signer's Cold Wallet Device 원문 필요
  • Cold Wallet signing 의 ceremony (QR? USB? air-gap transfer?) — Signing transactions with your Cold Wallet device 원문 필요
  • Hot ↔ Cold P2P 의 protocol / governance flow — Connecting Cold Wallet with hot workspaces via P2P 원문 필요
  • Cold Wallet 의 MPC share 분포가 Hot 의 "1 mobile + 2 Fireblocks SGX" 와 같은지 다른지 — Cold Wallet Mobile Key Share Backup and Recovery 원문 필요 (Q-M05)

은행이 실제 도입 시 위 항목들은 Fireblocks Help Center 의 해당 원문 열람 또는 Fireblocks Sales / Support 와 직접 협의로 확보 권장.

1.6 Cold Wallet 은 별도 mobile app

중요 사실 — Cold Wallet 은 별도 앱

Fireblocks 공식 mobile app 문서 직접 인용:

"Cold Wallet 은 별도 앱"

(출처: Fireblocks 공식 문서 — Mobile Device Minimum Requirements)

→ 은행 직원이 Hot workspace 에서 사용하는 Fireblocks mobile app 과 Cold workspace 에서 사용하는 mobile app 이 별개의 앱임. 같은 iPhone / Android 에 두 앱을 모두 설치하는지, 별도 device 에 각각 설치하는지의 운영 정책 결정 필요.

일반 Fireblocks mobile app 의 최소 사양 (Hot 기준):

  • iOS 16.6+ (non-jailbroken) + App Store + biometric capability
  • Android 8.1+ (64-bit) + Google Play Store + biometric capability

(출처: Fireblocks 공식 문서 — Authentication · Mobile App)

Cold Wallet 의 별도 앱이 동일 OS 최소 사양인지, 더 strict 한지는 공식 미명세 (Q-CW09 — 신규 Open Q). 또한 Cold Wallet 별도 앱이 mobile 인지 별도 hardware 의 firmware 인지도 미명세.
