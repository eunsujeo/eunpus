7. Risks & Open Questions — Cold Wallet

Cold Wallet 도입 시 식별 가능한 risk register + 공식 문서에 명시되지 않은 항목. 은행은 Fireblocks 와 직접 계약 협의 시 본 목록을 참고로 사용 권장.

본 페이지의 출처 — 어디까지가 공식 사실이고, 어디부터가 저자 추정인가

이 페이지의 내용은 두 갈래입니다.

  • 완화 방안의 구체 수치 (Admin ≥ 3, threshold ≥ 2 등)

7.1 Risk Register — Cold-specific (7)

R1 Approval Group 미지원 — 거버넌스 부담 증가

출처: Fireblocks 공식 문서 (Approval Groups)

영향: Cold workspace 의 모든 governance 변경에 Admin Quorum 전체 동의 필요. Hot 와 달리 use case 별 위임 불가.

완화: Admin 인원 ≥ 3 + 비상 근무 일정 + Quorum threshold ≥ 2.

R2 Owner Console-direct critical ops — Owner SPOF 강화

출처: Fireblocks 공식 문서 (Admin Quorum — Cold Wallet 특수 규칙)

영향: User delete + 2FA reset 이 Owner 단독 권한. Owner 사고 시 governance halt.

완화: Workspace Keys Backup + Recovery Passphrase + 이사회 결의 절차 사전 정의.

R3 Support 경유 부담 — user / API key 추가의 응답 시간

출처: Fireblocks 공식 문서 (Cold Wallet cluster — adding users / API keys)

영향: 모든 user / API key 추가가 Fireblocks Support 응답 시간에 종속. Hot 의 self-service 대비 운영 latency.

완화: Fireblocks 계약 시 SLA 명시. Cold workspace 의 user 변경 빈도 최소화 (안정된 인원 운영).

R4 Cold device signature quota 소진 — "Less than 10%" 임계

출처: Fireblocks 공식 문서 (Audit Log 카테고리)

영향: Cold device 의 sign capacity 가 유한. 소진 시 signing halt 가능 (정확한 limit 은 공식 문서 미명세).

완화: Sign quota 사전 alert (예: 30%, 20% 단계별). Signer device 인벤토리 운영. 신규 device provisioning 사전 준비.

R5 Workspace type immutability — 1-way door

출처: Fireblocks 공식 문서 (Hosted MPC Workspace Configuration)

영향: Cold workspace 를 한번 생성하면 Hot 으로 변환 불가. 재구성 시 새 workspace + 자산 transfer.

완화: Workspace 생성 전 architecture 결정의 충분한 sandbox testing. 자산 transfer 의 운영 단절 계획.

R6 Default visibility — 모든 workspace user 가 모든 vault 가시

출처: Fireblocks 공식 문서 (Vault Structure Best Practices)

영향: Cold workspace 내부의 부분 가시성 제한 불가. user 수에 비례한 정보 누출 위험.

완화: Cold workspace user 수를 최소화 (Owner + 2–3 Admin + 2 Signer). Viewer / Editor 제한.

R7 Cold MPC share 분포 미명세 — 3 가지 가설

출처: 공식 문서 미명세 (Q-M05 참조)

영향: Fireblocks 의 Cold side cloud share 의존 정도 / cold facility 위치가 미명세. SaaS 장애 / cold facility 침해 영향 평가 불가.

완화: Fireblocks 계약 시 Cold MPC 모델의 명시 요청. BCM 적용 가능성 확인.

7.2 Hot 공통 Risk 의 Cold 적용 (cross-cut)

다음 매핑의 "Cold 영향" 컬럼은 대부분 저자 추정 — Hot 의무가 Cold workspace 에도 동일 적용된다는 가정. 별도 공식 검증 권장.

Risk-S08 — Single-Signer SPOF Single Signer = 자산 접근 상실 Cold 도 동일 (추정). Cold Signer ≥ 2 강제 권장
Risk-S09 — DR Service SPOC xprv+fprv 재구성 = MPC 신뢰 모델 깨짐 Cold backup 도 동일 위험 (추정). Air-gapped + hardened access

7.4c 신고제 운영 — 은행 도입 일정 영향

  • 신고 유효기간 3년, 갱신 만료 45일 전까지 (특금법 시행령)
  • 신규 신고 심사 3개월, 변경 신고 45일 이내 수리 여부 통보 (FIU 공지)
  • 미신고 영업 = 5년 이하 징역 또는 5천만원 이하 벌금 (특금법 7조)
  • 신고서 필수 첨부: 대표자·임원·대주주 현황, 인터넷 도메인, 호스트 서버 소재지, 가상자산 취급·관리 지갑주소 목록, 법령준수체계 자료, 정보보호 관리체계 인증서, 실명계정 발급 확인서·계약서·은행 AML 위험평가 서류

→ 은행이 Fireblocks Cold Wallet workspace 의 vault 주소를 신고서에 등록해야 함. Workspace 변경 (신규 cold vault 추가, address 변경) 마다 45일 변경신고 필수. (출처: KR 컴플라이언스 가이드)
