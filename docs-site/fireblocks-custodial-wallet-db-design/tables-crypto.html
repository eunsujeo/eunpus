11.2 MPC-CMP — Fireblocks 의 threshold 서명 (참고)

SaaS MPC / Hosted MPC 는 MPC-CMP (Canetti-Makriyannis-Peled 2020) protocol 사용. 3-party threshold ECDSA / EdDSA.

  • 3 party 중 2 party 가 협력해야 서명 1 개 완성 (2-of-3)
  • 한 party 의 share 만으로는 서명 불가능 → 단일 침해로 자산 탈취 불가
  • 2023-08 보안 업데이트: GG18 → MPC-CMP 로 전환. "라운드" = 서명 1 회 완성에 필요한 party 간 통신 왕복 수. 8 → 4 로 줄면서 latency / 통신 비용 감소

출처: MPC-CMP Security Update 2023-08

은행 입장에서 — MPC 의 함의

은행은 MPC 내부 동작을 자세히 알 필요는 없다. 알아야 할 것은:

  • 키 share 가 1 곳에 모이지 않으므로, Fireblocks Cloud / 은행 mobile / 은행 cosigner 중 1 곳만 침해되어도 자산 탈취 불가
  • SaaS MPC 는 Fireblocks Cloud + 은행 mobile + Cloud Co-signer 의 3-party. 즉 은행 측 device 가 1 개 필요
  • Hosted MPC 는 은행 측 Co-signer 1 대 추가 — Cloud Co-signer 대신
  • Key Link 는 MPC 가 아닌 단일 HSM 모델 (다른 보안 모델)

11.4 Callback Handler (Hosted MPC 운영 검증)

Hosted MPC 의 API Co-signer 는 거래 서명 직전에 은행의 Callback Handler endpoint 를 호출하여 마지막 게이트로 추가 검증을 받음. 은행이 자체 정책 (KYC / 한도 / counterparty / 시간대 등) 을 Fireblocks TAP 위에 한 번 더 적용 가능.

  • 예: TAP 통과한 거래에 대해 (a) 송신자 KYC 완료 여부 재확인, (b) 24h 누적 한도 재계산, (c) 채널계 / 정산계 잔액 일치 확인 → 모두 OK 시에만 서명 진행
  • 은행이 Endpoint URL + RSA 2048 keypair 를 생성 → public key 를 Fireblocks 에 등록 (Fireblocks 가 발급하는 게 아님). private key 는 은행 secret manager (예: AWS Secrets Manager) 에 별도 보관 — 자세한 컬럼 정의는 8. Internal Users 8.5 절 의 callback_handler_meta 참조
  • secure communication (mTLS) 강제 — 통신 자체가 양방향 인증

11.5 Workspace Keys Backup — Backup 매커니즘

Fireblocks 가 제공하는 자산 회복 매커니즘. mobile device 분실 / Co-signer 손상 등의 시나리오 대응.

매커니즘 (저자 정리)

  • Owner / Admin 이 "Create new backup" 시작 (Fireblocks Console)
  • Recovery passphrase (사용자 입력) 로 backup 암호화
  • Fireblocks 가 backup 의 encrypted form 을 보관
  • Mobile device 분실 시 새 device 에 recovery passphrase 입력 → 복원

★ Recovery passphrase 의 보관
  • 절대 DB / digital storage 에 저장 금지 — 물리 보안 구역의 sealed envelope 권장
  • 다수 custodian 분할 보관 권장 — Shamir's Secret Sharing 또는 split-phrase 패턴
  • 정기 recovery drill — 분기별 1회 testnet workspace 에서 실제 recovery 절차 검증
  • SPOC (Single Point of Compromise) 인식 — "한 번이라도 노출되면 시스템 전체가 위험해지는 critical 지점". recovery passphrase 가 한 번이라도 노출되면 자산 노출로 간주 (Fireblocks 공식 표현: "private key being considered exposed and compromised")

11.6 Recovery — Fireblocks Recovery Utility

Fireblocks 의 Recovery Utility (공식 명칭 — Disaster Recovery Utility 로 통칭되기도 함) 는 자산 회복용 도구. ★ SPOC 경고 — 정기 사용 금지, 1 회 사용도 키 노출 risk 로 간주.

  • 반드시 offline air-gapped machine 에서만 실행. Fireblocks 공식: "Performing this procedure on an online machine will result in your private key being considered exposed and compromised"
  • 4 secrets 매개 — Recovery Kit ZIP + RSA private key + Mobile App Recovery Passphrase + RSA Private Key Passphrase
  • 사용 후 해당 machine 폐기 또는 disk wipe
  • extended private keys (xprv + fprv) 재구성 가능 — 즉 사용자가 키 자체를 손에 쥐는 상태
  • 은행 정책: Recovery Utility 사용 = Admin Quorum 전원 동의 + 외부 감사 ceremony

11.7 Key Link 의 특수성 (별도 reference)

Key Link product 는 customer-held HSM 모델로 위의 모든 룰이 다르게 적용됨:

  • Backup 은 HSM vendor 가 제공 — Thales Luna 의 backup HSM 또는 smart card 백업
  • Workspace Keys Backup 매커니즘 미적용 (Fireblocks 가 키 share 0 이므로)
  • Validation Key + Signing Key 2 key 모델
  • HSM 자체가 SPOC — HSM 침해 / 손상 = 자산 손실
