Key Link: 전량 고객 HSM 보유 (Fireblocks 0 share) — vendor lock-in 최소
DB 개수 7 DB (walletdb · ledgerdb · approverdb · auditdb · chaindb · providerdb · recondb) Fireblocks 가 vault · 정책 · audit log 등 대부분의 DB 책임을 인수. 은행이 직접 운영하는 DB 는 2-3 개 (core + audit + compliance) — 단 webhook 중복 처리 · 5년 보존 · AML/트래블룰 통합 등 새 책임이 발생하므로 운영 부담이 "줄었다" 가 아니라 "성격이 달라졌다"
상태 머신 책임 은행이 17 transaction state · 14-step · approval · signing 전부 운영 Fireblocks 가 17 transaction state 운영 (서명 / 승인 / broadcast). 은행은 webhook 으로 사본 보관 + 은행 자체 비즈니스 상태 별도 운영 (REQUESTED → BANK_VALIDATING → FB_SUBMITTED → … → SETTLED)
거버넌스 책임은행이 Admin Quorum · Approval Group · Policy/TAP 직접 구축Fireblocks Console 이 거버넌스 담당. 은행은 user 등록 + 정책 설정만
감사 로그은행의 append-only auditdbFireblocks Console 의 immutable audit log + 은행은 5 년 보존을 위한 사본 보관
주요 책임모든 것① 은행 사용자 ↔ Fireblocks user 매핑 / ② webhook 수신 + 5 년 보존 / ③ AML · 트래블룰 / ④ KR 컴플라이언스 / ⑤ vendor outage 대응
은행이 갖는 자체 상태 (mirror 이상의 가치)

Fireblocks 가 17 transaction state 를 운영하지만, 은행 application 은 사용자 신청부터 Fireblocks 접수 전 의 자체 상태를 별도로 가진다. 예: REQUESTED (사용자 신청 접수) → BANK_VALIDATING (KYC · 한도 · counterparty 검증) → FB_SUBMITTED (Fireblocks 에 거래 요청 송신) → AWAITING_APPROVAL → SIGNING → BROADCASTED → SETTLED. 이 상태들은 Fireblocks 가 모르는 영역이며, 은행이 자체 DB 에서 관리. 상세는 14. Deposit · Withdrawal Flow 참조.

도입의 핵심 효과

  • 인프라 운영 부담 감소 — MPC 키 분포 · cosigner 운영 · 정책 엔진 · audit log 보안 등 깊은 보안 인프라를 Fireblocks 가 담당
  • DB 가 단순해진다 — 7 DB → 3 DB (core + audit + compliance). 단 webhook 수신 / 중복 처리 방지 / 5년 보존 책임은 여전히 은행
  • 새로운 의존성 발생 — Fireblocks 에 종속되어 다른 vendor 로의 마이그레이션이 어려워지고 (vendor lock-in), Fireblocks SaaS 가 장애를 일으키면 은행 거래 처리도 함께 멈춘다 (outage 의존성). 직접 구축에는 없던 이 vendor 관련 위험들을 별도 위험 목록으로 관리해야 한다 (20. Risks Register)
  • KR 컴플라이언스는 여전히 은행 책임 — Fireblocks 가 자동 제공하지 않음 (특금법 · 가상자산이용자보호법 · 가상자산업감독규정 등) — 상세는 국내 블록체인 사업 법규 × Fireblocks 참조

영역 분리 — 초록 = 은행 자체 운영 (코인계) (DMZ + 코인계 + 보안 구역) / 연보라 = 기존 은행 시스템 (계정계 · 외환계 · 정보계 · 채널계) / 파랑 = Fireblocks (vendor) (SaaS + 운영자 Mobile app) / 노랑 = 3rd-party (외부 IdP · AML provider · Travel Rule provider · Blockchain).
화살표 의미: 실선 = 동기 호출 (request → 즉시 응답, 같은 영역 안 또는 직접 데이터 흐름) / 점선 = 영역 경계 넘는 외부 통신 + 비동기 (webhook · push notification · metric scrape).
은행 ↔ Fireblocks 통신은 양방향 모두 DMZ 의 Outbound Proxy / Webhook endpoint 경유 (망분리 의무). 코인계의 DB · application 은 외부와 직접 통신하지 않음. 보안 구역 (HSM) 은 코인계 Customer Server 의 PKCS#11 호출로만 접근.
두 "Webhook" 노드의 차이: DMZ "Webhook endpoint" = 외부 HTTPS 수신 + HMAC-SHA512 검증 (HA 2-node). 코인계 "Webhook" = 검증 통과한 이벤트의 dedup + core 영역 저장 (worker). 두 노드는 zone 이 다른 별도 컴포넌트.
Cold Wallet workspace 의 위치: Fireblocks SaaS 안의 별도 workspace type (Hot Workspace 와 동급). KR 은행은 가상자산업감독규정 9조 (80% offline) 의무로 Cold Wallet 사실상 필수. Cold Wallet 자체는 Fireblocks 가 운영하지만 Hot/Cold 비율 모니터링 + rebalancing 트리거는 은행 책임.
기존 은행 시스템 통합: 채널계 → 플랫폼 (사용자 facing 진입) · 플랫폼 ↔ 계정계 (KRW 잔액 / 입출금) · 플랫폼 ↔ 외환계 (환율 / 외환 환산) · 플랫폼 → 정보계 (마감 / 감사 보고 push). 실제 통합은 별도 ESB / API Gateway / iPaaS 경유 가능 (본 다이어그램은 단순화 직접 호출). 컴포넌트 별 상세는 2. 인프라 운영, Cold Wallet 운영 상세는 7. Cold Wallet 운영 참조.

핵심 invariant (7) — 어겨서는 안 되는 규칙

invariant = "변하지 않는 핵심 규칙". 도입 운영에서 무엇이 잘못되어도 다음 7 가지는 항상 지켜야 한다. 운영자 · 개발자 · 외부 감사인이 가장 먼저 확인하는 항목.

  1. Workspace 종류는 한 번 정하면 바꿀 수 없다 (immutable) — 한 번 SaaS MPC / Hosted MPC / Key Link 로 생성한 workspace 는 다른 종류로 변환 불가. 변경하려면 새 workspace 생성 + 자산 cross-workspace 이전 필요. (Fireblocks Key Link Overview)
  2. Vault Account = 1 ECDSA + 1 EdDSA (Key Link 시) — 각 vault 에 algorithm 별 1 키만 할당. (Set up your Fireblocks Vault with Key Link)
  3. Webhook 은 멱등 (idempotent) 처리해야 한다 — 같은 event 가 네트워크 재시도로 여러 번 들어와도 결과는 한 번 처리된 것과 같아야 함. event ID 기반 중복 검출 (dedup) 필수. (Configure Webhooks)
  4. Webhook signature 검증 필수 — Fireblocks 가 HMAC-SHA512 로 서명. signature 검증 없는 webhook 처리는 위조 공격의 진입 경로 (vector) 가 된다. (Configure Webhooks)
  5. Admin Quorum 매개 작업은 mobile app 으로만 — Console 에서 시작, mobile 에서 quorum 승인. (Fireblocks Help Center)
  6. 은행 audit trail = Fireblocks audit + 자체 사본 — Fireblocks 가 변경 불가 (immutable) log 를 제공하지만 은행의 5년 보존 의무 (특금법 5조의4) 는 자체 사본으로 별도 보관 필수. (특금법)
  7. 키 material 은 어떤 은행 DB 에도 저장 금지 — Fireblocks 가 키를 관리 (Key Link 의 경우 고객 HSM). 은행 application DB 어디에도 private key / mnemonic / MPC share 가 저장되어선 안 됨.
