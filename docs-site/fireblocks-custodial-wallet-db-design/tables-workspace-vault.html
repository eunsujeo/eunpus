4.3 Vault Account — 고객 단위 격리

Vault Account 는 자산 보관의 격리 단위. 은행은 (a) 고객 1 인 = vault 1 개 (segregated) 또는 (b) 자산군 별 omnibus vault 중 선택.

Sweep-to-omnibus vs Segregated

패턴vault 구성적합한 운영
Sweep-to-omnibusEnd user 입금 vault → Intermediate vault → Omnibus vault대량 사용자 · 자동 sweeping · Gas Station 자동
SegregatedPer-client vault (고객 1 인당 1 vault)institutional 고객 · settlement on-chain atomic · 작은 사용자 base

4.5 Deposit Address — UTXO vs Account-based

Asset Wallet 안에 deposit address 가 생성됨. 자산 유형에 따라 개수가 다르다:

  • UTXO 체인 (BTC, LTC 등): 다중 deposit address 가능. 새 입금마다 새 주소 발급 가능
  • Account-based 체인 (ETH, SOL, ...): 단일 deposit address. 한 asset wallet = 한 주소

One-time vs Permanent address

  • Permanent: deposit address 가 영구 보관, 여러 번 입금 수신
  • One-time: 한 번만 사용 가능, 입금 후 폐기 (privacy 향상)

4.7 Vault → Customer 매핑의 권장 패턴 (저자)

은행 customerdb 의 매핑 패턴:

  • segregated 패턴 — fb_vault_account_map.bank_customer_id = 은행 고객 ID 직접 매핑. 1 고객 = 1 vault
  • omnibus 패턴 — fb_vault_account_map.bank_customer_id IS NULL + 별도 customer_balance_subledger 테이블에 고객별 잔액 mirror. 회계 시스템 통합
  • 혼합 패턴 — Retail (omnibus) + Institutional (segregated) 동시 운영. vault_purpose enum 으로 분리
omnibus vault 의 KR 컴플라이언스 함의 (저자)

omnibus 패턴 시 은행 내부 회계로 고객별 잔액을 분리 관리하더라도, on-chain 에는 1 vault 의 통합 balance 만 표시됨. 대법원 2024도10710 의 "실질 통제" 판단 시 한 vault 안의 자산이 누구의 통제권에 있는지 명확히 구분되어야 함. 은행은 customer_balance_subledger 의 무결성 (audit log 와 정합성) 을 별도로 증명할 책임.
