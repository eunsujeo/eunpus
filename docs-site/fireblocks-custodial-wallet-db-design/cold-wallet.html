5. Cold Wallet 운영

Cold Wallet workspace 의 도입 시 통합 view — Hot/Cold 비율 · rebalancing · 거버넌스
전용 reference 안내

본 페이지는 도입 시 Cold Wallet 운영의 핵심 요약. 상세는 별도 reference 참조: 은행 Fireblocks Cold Wallet 도입 — 수탁형 지갑 reference (8 페이지)

5.1 왜 Cold Wallet 이 필요한가

KR 은행은 두 가지 이유로 Cold Wallet workspace 필수:

  • 규제 — 가상자산업감독규정 9조: 이용자 자산의 80% 를 인터넷과 분리하여 보관 (cold storage)
  • Risk segregation: Hot workspace 의 attack surface (API key 도난 · mobile 분실 · SaaS outage) 에서 격리

출처: 가상자산이용자보호법 · 가상자산업감독규정

5.4 자산 비율 운영 — 80% / 20% 유지

가상자산업감독규정 9조의 80% offline 의무를 일상 운영에서 어떻게 유지하는가.

5.4.1 일일 monitoring

  • 모든 Custodial Hot vault 의 asset balance 합산 (KRW 환산)
  • 모든 Custodial Cold vault 의 asset balance 합산
  • Hot ÷ (Hot + Cold) 비율 계산
  • 임계 (예: Hot 18% 초과) 도달 시 운영팀 alert

5.5 Hot ↔ Cold Rebalancing

임계 도달 시 자산을 Hot ↔ Cold 사이 이동 (별도 P2P 경로).

5.5.1 트리거 시나리오

  • 대량 사용자 입금 후 → Hot ratio 상승 → Cold 로 sweep
  • 대량 출금 예정 → Cold ratio 너무 높음 → 일부 Cold → Hot
  • 정기 rebalancing → 일일 cron 권장 (closing 직후 EOD). 임계 buffer 충분 (예: Cold 목표 85%) + 매일 점검이라 Admin Quorum 부담 최소화. 주간 / 월간은 buffer 가 좁아 위반 risk ↑

5.5.2 rebalancing 절차

5.6 Cold Wallet 의 User 추가 절차 — Support 매개

Cold Wallet workspace 의 user / API key 추가는 Fireblocks Support 매개 필수. 일반 workspace 처럼 Admin Quorum 만으로 추가할 수 없음.

  1. Owner 가 Fireblocks Support 에 ticket 발생 (Console)
  2. Support 가 추가 검증 (정체성 / 권한 / 사유)
  3. Admin Quorum 의 mobile 승인 (7-day window 안에 처리)
  4. Support 가 user 추가 처리
  5. 새 user 의 mobile activation (activation token 7 day · configurable)

출처: Fireblocks 공식 — "Adding users to a Cold Wallet workspace" / "Adding API keys to a Cold Wallet workspace" (Help Center 문서명). 본 reference 의 cross-cut 분석은 Cold Wallet Governance / Quorum 참조.

★ Cold Wallet workspace 의 인원 최소화 권장

Cold Wallet 의 user 추가가 무겁고, default visibility 정책상 모든 user 가 모든 vault 를 조회 가능 → Owner + 2-3 Admin 최소 인원 권장. 대량 사용자 운영은 Hot workspace 에서. Cold 는 정기 rebalancing + 큰 출금 결정만.

5.7 Cold Wallet 의 device 정책

  • device 분리: Cold Wallet user 의 mobile device 는 별도 (Hot workspace 와 같은 device 사용 금지 — 저자 권장)
  • 2FA + biometric 필수: 모든 Cold user 의 mobile
  • device 분실 시: 즉시 Admin Quorum 매개 device migration ceremony
  • 승인 device 추적: customerdb.mobile_device 에 device 등록 / status 관리

5.8 옵션 C-Thales — Key Link + Cold (hypothesis)

Cold Wallet workspace 와 Key Link 의 결합은 저자가 가장 강한 KR 컴플라이언스 옵션으로 제안. 다만 두 product 의 결합 가능 여부 자체가 vendor 공식 명세 미확보 — 저자 hypothesis:

  • Key Link workspace 의 HSM 을 Cold mode 로 운영 (air-gap)
  • 키 share 0 + on-prem HSM + 망분리 IDC + FIPS 140-3 L3
  • 실질 통제 (대법원 2024도10710) 의 가장 강한 주장 근거 (저자 의견)
  • SaaS Cold Wallet workspace vs Key Link Cold signing 의 관계는 vendor 미명시 — Q-FB02
