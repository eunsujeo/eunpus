17. Signing State Machine

Co-Signer Engine routing · 3-share ceremony · zero-trust(?) handoff · SGX MRENCLAVE attestation
본 페이지의 출처 — 어디까지가 Fireblocks 정의이고, 어디부터가 추정인가

이 페이지의 내용은 두 갈래입니다.

Fireblocks 공식 문서에 정의된 사실 — 그대로 받아들여도 안전

  • Two-Tier Co-Signer Model: Customer Co-Signer (mobile 또는 SGX server, 1/3) + Fireblocks Co-Signers (Azure SGX, 2/3)
  • Fireblocks 측 safeguards: "Safeguards in case keys owned by customers are compromised" — tx amount threshold + destination address integrity 검증
  • Co-Signer Broker + Aggregator architecture: Broker 가 MPC 메시지 + end cert broadcast (chain of trust 검증), Aggregator 가 partial signature 결합 → blockchain
  • "Data is not passed between them during signing" — 각 co-signer 는 독립 partial sig 생성 (zero-trust 의 cryptographic 표현)
  • 3-share parallel ceremony: 3 share 가 동시에 partial sig 생성 → Aggregator 가 결합. 어느 한 party 가 reject 하면 즉시 전체 REJECTED
  • Hosted MPC variant: 3 share 모두 customer 환경 — Fireblocks 0 share
  • Solana Sign-Only: SIGNED 상태에서 broadcast 안 함, payload client 에 반환, NOT BROADCAST BY FIREBLOCKS 태그
  • Cached signature (Raw Signing): 동일 raw data 재서명 시 전체 ceremony 우회 — SIGNED 직접 진입

저자가 합리적으로 추정해서 그린 설계 — 참고용, 본인 환경에서 검증 권장

  • signing_requests · signing_events · callback_invocations 3 테이블의 구체 schema
  • signing_events.mrenclave_at_signing 컬럼 — SGX enclave attestation 의 audit trail 기록 패턴 (Fireblocks 내부 구현은 미명시)
  • co_signer_role ENUM 의 3 값 정형화 (customer-mobile / customer-sgx / fb-azure-sgx)
  • State machine 의 정확한 transition 그림 — Fireblocks 가 PARTIAL_SIG_1/2/3 같은 internal state 를 어떻게 부르는지 미명시

Two-Tier Co-Signer Model — 2 계층 서명 모델

mpc-cmp.md, p.5-6 직접 인용: "None of the parties (neither Fireblocks nor the customer) can sign a transaction alone."

Co-Signer Broker + Aggregator Architecture

  • Co-Signer Broker: MPC(?) 메시지 + end cert 를 broadcast (chain of trust(?) 검증)
  • Aggregator: partial signature 들을 full signature 로 결합 → Blockchain
  • "data is not passed between them during signing" — 각 co-signer 는 독립 partial sig 생성 (zero-trust)

Signing State Machine

stateDiagram-v2
  [*] --> QUEUED : Secure Vault → Co-Signer Engine (Step 9)
  QUEUED --> ROUTING : UUID + Policy rules cached
  ROUTING --> AWAITING_CUSTOMER : route to Co-Signer 3 (mobile/SGX)
  ROUTING --> AWAITING_FB_1 : route to Co-Signer 1 (FB Azure SGX)
  ROUTING --> AWAITING_FB_2 : route to Co-Signer 2 (FB Azure SGX)

  AWAITING_CUSTOMER --> PARTIAL_SIG_3 : signed (PIN+biometric or API)
  AWAITING_CUSTOMER --> REJECTED : customer co-signer reject
  AWAITING_FB_1 --> PARTIAL_SIG_1 : FB safeguards pass
  AWAITING_FB_1 --> REJECTED : safeguard violation (amount/destination)
  AWAITING_FB_2 --> PARTIAL_SIG_2 : FB safeguards pass

  PARTIAL_SIG_1 --> AGGREGATING : all 3 collected
  PARTIAL_SIG_2 --> AGGREGATING
  PARTIAL_SIG_3 --> AGGREGATING

  AGGREGATING --> VERIFYING : Auth Engine hash 검증 (Step 11)
  VERIFYING --> SIGNED : Secure Vault tx 조립 (Step 12)
  VERIFYING --> FAILED : hash mismatch
  SIGNED --> READY_TO_BROADCAST
  REJECTED --> [*]
Figure 8. Signing state machine — 3-share ceremony, parallel collection. Either party reject = REJECTED. Auth Engine 가 partial sig hash 검증.

Special Branches

  • Hosted MPC: 3 share 모두 customer 환경 — Fireblocks 0 share. signing_events.co_signer_location 가 모두 'customer'
  • Solana Sign-Only: SIGNED 상태에서 broadcast 안 함, payload client 에 반환. NOT BROADCAST BY FIREBLOCKS 태그
  • Cached signature (Raw Signing): 동일 raw data 재서명 시 전체 ceremony 우회 — SIGNED 직접 진입
  • Co-signer rejection at PENDING_SIGNATURE → tx 전체가 CANCELLED (transaction state machine 참조)
  • ★ Cold Wallet PreHash: Cold Wallet workspace 의 raw signing 은 추가 PreHash object 필수 — content (hex pre-hashed) + hashAlgorithm ENUM(SHA256 / KECCAK256 / BLAKE2 / SHA3 / DOUBLE_SHA256). Regular workspace 는 PreHash 불요. signing_requests.prehash_algorithm 컬럼이 본 분기 영속화 (cold workspace 만 set, regular 은 NULL)
  • Typed Message 4 종 (Fireblocks API UnsignedRawMessage.type): EIP191 (ETH personal_sign) / EIP712 (ETH typed structured) / TIP191 (TRX personal_sign) / BTC_MESSAGE (Bitcoin personal message)

DB Schema

5.1 signing_requests — 서명 요청 본체

CREATE TABLE signing_requests (
  id                BINARY(16) PRIMARY KEY,
  transaction_id    BINARY(16) NOT NULL,
  workspace_id      BINARY(16) NOT NULL,
  policy_rule_id    BINARY(16),                       -- triggering rule
  co_signer_set_id  BINARY(16) NOT NULL,              -- 3-share set 식별자
  algorithm         ENUM('MPC_ECDSA_SECP256K1','MPC_EDDSA_ED25519','MPC_ECDSA_SECP256R1') NOT NULL,
                                                       -- ★ Fireblocks API SigningAlgorithm enum 3 종
  typed_message_type ENUM('EIP191','EIP712','TIP191','BTC_MESSAGE'),
                                                       -- typed message signing 의 protocol type. raw signing 만 set
  prehash_algorithm ENUM('SHA256','KECCAK256','BLAKE2','SHA3','DOUBLE_SHA256'),
                                                       -- ★ Cold Wallet workspace 의 raw signing 만 set. regular workspace 는 NULL
  state             ENUM('QUEUED','ROUTING','AGGREGATING','VERIFYING','SIGNED','REJECTED','FAILED') NOT NULL,
  initiated_by      BINARY(16) NOT NULL,              -- 이 서명 요청 trigger 한 actor (보통 시스템 user — Secure Vault 의 Step 9 호출)
  queued_at         DATETIME(6) NOT NULL,             -- ★ created_at semantic
  signed_at         DATETIME(6),                      -- ★ set-once
  KEY (transaction_id),
  KEY (workspace_id, state)
);
컬럼자료형역할
idBINARY(16) PK서명 요청의 고유 식별자
transaction_idBINARY(16) FK이 서명이 속한 tx
workspace_idBINARY(16) FKworkspace
policy_rule_idBINARY(16) nullable FK이 서명 요청을 trigger 한 Policy rule. designated signer / approver group 등의 ref
co_signer_set_idBINARY(16)3-share set 의 식별자 (key_lifecycle.key_set_id 와 매핑). 서명에 동원되는 share 들의 그룹
stateENUM (7 값)서명 state machine 의 현재 상태. QUEUED → ROUTING → AGGREGATING → VERIFYING → SIGNED 또는 REJECTED/FAILED
initiated_byBINARY(16)서명 요청을 trigger 한 actor. 보통 시스템 user (Step 9 의 Secure Vault → Co-Signer Engine 호출). set-once
queued_atDATETIME(6)서명 요청이 큐에 들어간 시각. created_at semantic. set-once
signed_atDATETIME(6) nullableSIGNED 상태 도달 시각. set-once

5.2 signing_events — 개별 co-signer 의 partial sig 이벤트 (append-only)

-- ★ append-only: BEFORE UPDATE / DELETE 트리거로 강제
CREATE TABLE signing_events (
  id                   BINARY(16) PRIMARY KEY,
  signing_request_id   BINARY(16) NOT NULL,
  co_signer_id         BINARY(16) NOT NULL,
  co_signer_role       ENUM('customer-mobile','customer-sgx','fb-azure-sgx') NOT NULL,
  share_index          TINYINT NOT NULL,                 -- 1, 2, or 3
  event_type           ENUM('partial-sig','reject') NOT NULL,
  partial_sig_hash     BINARY(32),                       -- Auth Engine 검증용
  mrenclave_at_signing BINARY(32),                       -- SGX MRENCLAVE (★ set-once)
  occurred_at          DATETIME(6) NOT NULL,
  KEY (signing_request_id)
);
컬럼자료형역할
idBINARY(16) PKpartial sig 이벤트의 고유 식별자
signing_request_idBINARY(16) FK이 partial sig 가 속한 서명 요청
co_signer_idBINARY(16) FK이 partial sig 를 만든 co-signer (cosigner_configs.id 참조)
co_signer_roleENUM (3 값)customer-mobile=고객 mobile device / customer-sgx=고객 운영 SGX 서버 / fb-azure-sgx=Fireblocks Azure SGX. 3-share ceremony 에서 누가 어느 share 를 들고 있는지 audit
share_indexTINYINT1 · 2 · 3 — 3-share set 중 몇 번째 share 인지
event_typeENUM (2 값)partial-sig 정상 partial signature 생성 / reject 이 co-signer 가 거부. Unanimous-Veto Rule 에 의해 reject 1 개 = 즉시 전체 REJECTED
partial_sig_hashBINARY(32) nullablepartial signature 의 SHA-256 해시. Auth Engine 이 Step 11 에서 검증. reject 이벤트는 NULL
mrenclave_at_signingBINARY(32) nullablefb-azure-sgx 또는 customer-sgx 의 경우 그 시점 enclave 의 MRENCLAVE(?). set-once. 외부 감사자가 attested MRENCLAVE 와 known-good 값 비교로 enclave integrity 검증 가능
occurred_atDATETIME(6)partial sig 또는 reject 발생 시각

5.3 callback_invocations — API Co-Signer 의 Callback Handler 호출 이력 (append-only)

-- API Co-Signer 의 Callback Handler 호출 (optional, ★ append-only)
CREATE TABLE callback_invocations (
  id                   BINARY(16) PRIMARY KEY,
  signing_request_id   BINARY(16) NOT NULL,
  callback_endpoint_id BINARY(16) NOT NULL,
  request_url          VARCHAR(255) NOT NULL,            -- /v2/tx_sign_request or /tx_sign_request
  request_jwt_or_json  ENUM('jwt','json') NOT NULL,
  response_decision    ENUM('approve','reject','ignore','retry') NOT NULL,
  latency_ms           INT,
  invoked_at           DATETIME(6) NOT NULL
);
컬럼자료형역할
idBINARY(16) PKcallback 호출의 고유 식별자
signing_request_idBINARY(16) FK이 callback 이 속한 서명 요청
callback_endpoint_idBINARY(16) FK호출된 callback_endpoints (12. Cosigner) 의 id
request_urlVARCHAR(255)실제 호출된 URL. JWT-bearing 이면 /v2/tx_sign_request, JSON 이면 /tx_sign_request (callback_endpoints.url_uses_v2 의 결정에 따라)
request_jwt_or_jsonENUM (2 값)요청 payload 형식 (auth_option 1/4/5 = jwt, 2/3 = json)
response_decisionENUM (4 값)customer endpoint 의 응답. approve 서명 계속 / reject 거부 / ignore 응답 없음 (auto-sign default 적용) / retry 일시 오류 → 재시도
latency_msINT nullable호출 후 응답까지의 millisecond. 모니터링용 — customer endpoint 의 응답 속도 변화 탐지
invoked_atDATETIME(6)callback 호출 시각
