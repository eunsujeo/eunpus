12. Cosigner(?) & Callback Handler(?)

3 cosigner 종류 · 5 auth option · /v2 URL convention · key model 비대칭
본 페이지의 출처 — 어디까지가 Fireblocks 정의이고, 어디부터가 추정인가

이 페이지의 내용은 두 갈래입니다.

Fireblocks 공식 문서에 정의된 사실 — 그대로 받아들여도 안전

  • 3 cosigner 종류 + 1 test: Mobile Cosigner · API Cosigner (SGX 강제) · Fireblocks Cloud Cosigner (Azure SGX, 2 대) · Communal Test Cosigner (testnet 전용)
  • Chain of Trust 3 단: Co-Signer Certificate → Core Services Intermediate → Co-Signer End Certificate
  • Callback Handler 의 default = auto-sign: 미설정 시 Co-signer 가 모든 요청 자동 승인/서명 (보안상 중요 운영 risk)
  • 5 Authentication Options: Public key (JWT) · Self-Signed Cert pin · Root-CA · Hybrid 2 종 (SGX only, v2025.12.11+)
  • /v2 URL 분기: JWT-bearing (opt 1, 4, 5) 만 /v2 prefix, JSON-bearing (opt 2, 3) 은 prefix 없음
  • Key model 비대칭: Co-signer private key 는 global (페어링된 모든 API user 공유), Callback Handler private key 는 per-API-user 분리
  • Pairing token 1 시간 유효. Callback SSL public key pinning. Re-enroll trigger 2 가지 (auth method 전환 / SSL cert 변경 또는 만료) — 둘 다 Owner 의 key share 승인 필요

저자가 합리적으로 추정해서 그린 설계 — 참고용, 본인 환경에서 검증 권장

  • cosigner_configs · callback_endpoints · designated_signers 3 테이블의 구체 schema
  • cosigner_configs.type 의 4 값 ENUM 정형화 (Fireblocks 자료는 자유 텍스트일 수 있음)
  • callback_endpoints.auth_option 을 TINYINT (1~5) 로 정형화
  • HSM-wrapped private key reference (configuration_db_keyref) 의 정확한 형식 — plaintext 절대 금지가 원칙

Co-Signer Certificate (self-generated, priv → Configuration DB)
       ↓ (CSR via Co-Signer Broker)

       ↓ (sign)
Co-Signer End Certificate (배포)

Callback Handler — Optional 인데 위험한 default

Callback Handler 는 Co-signer 가 서명 전에 "이 요청이 정말 정책에 맞는가" 를 customer 측 외부 endpoint 에 다시 물어보는 추가 검증 단계입니다. 그런데 이게 optional 이라는 게 운영 함정.

⚠️ Default = Auto-Sign — Callback 미설정 시 자동 서명

Fireblocks 의 create-api-co-signer-callback-handler.md 직접 인용:
"If a Callback Handler is not configured for an API user, the Co-signer will automatically sign or approve all requests it receives for that API user."

즉 Callback Handler 가 설정되지 않은 API user 는 Co-signer 가 들어오는 모든 요청을 자동으로 서명/승인 — 외부 business / compliance 검증이 bypass 됩니다. 운영 risk register 에 반드시 등재할 항목.

5 Authentication Options

#명칭MessageTLSVersionSGX only
1Public key authenticationJWT (RSA 2048)HTTPS + trusted CA (prod)all—
2Self-Signed Cert pinningJSONTLS cert pinall—
3Root-CA CertJSONTLS Root-CA validationv2025.12.11+—
4Hybrid — Public key + Cert pinJWTTLS cert pinv2025.12.11+★ SGX only
5Hybrid — Public key + Root-CAJWTTLS Root-CAv2025.12.11+★ SGX only

Hybrid options (4/5) = message-layer (JWT 서명) + TLS-layer (cert) dual security.

Payload / URL Convention

  • Endpoints: tx_sign_request + config_change_sign_request (Co-signer → Callback Handler POST)
  • /v2 URL 분기:
    • JWT-bearing (1, 4, 5): https://<base>/v2/tx_sign_request
    • JSON-bearing (2, 3): https://<base>/tx_sign_request (no /v2 prefix)
  • URL setting 시 base URL + custom relative path 만 입력 — /v2/... 는 자동 추가
  • Production = HTTPS w/ trusted CA cert 강제 권장 / dev = HTTP 허용

Key Model 비대칭 — Co-signer 키 vs Callback Handler 키

키범위비고
Co-signer private keyglobal — 해당 Co-signer 에 페어링된 모든 API user 의 request 서명에 재사용"The same Co-signer private key is used to sign request messages... for all API users paired with this Co-signer."
Callback Handler private keyper-API-user — API user 별 별도 public key 를 Co-signer 에 등록RSA 2048 only (response auth)

→ Co-signer 측 single global key compromise = 모든 API user 의 request 서명 위조 가능. Callback Handler 측 key 는 per-user 격리.

Pairing / Re-enroll

  • Pairing token 1시간 유효
  • Callback Handler SSL public key pinning — Co-signer 가 cert 고정 신뢰
  • Re-enroll 요구: (a) auth method 전환, (b) SSL 인증서 변경 또는 만료 — 둘 다 Owner 의 key share 승인 필요

DB Schema

8.1 cosigner_configs — 등록된 Co-signer 들의 설정

CREATE TABLE cosigner_configs (
  id                      BINARY(16) PRIMARY KEY,
  workspace_id            BINARY(16) NOT NULL,
  paired_api_user_id      BINARY(16),                       -- API Co-signer 의 경우
  type                    ENUM('mobile', 'api-sgx', 'communal-test', 'fb-cloud-sgx') NOT NULL,
  end_cert_pem            TEXT NOT NULL,
  end_cert_fingerprint    BINARY(32) NOT NULL,
  intermediate_cert_id    BINARY(16) NOT NULL,             -- chain of trust
  configuration_db_keyref VARCHAR(128),                    -- ★ HSM-wrapped private key reference
  registered_by           BINARY(16) NOT NULL,              -- 페어링 시작한 actor
  registered_at           DATETIME(6) NOT NULL,             -- ★ created_at semantic
  modified_by             BINARY(16) NOT NULL,
  modified_at             DATETIME(6) NOT NULL,
  re_enrolled_at          DATETIME(6),
  UNIQUE KEY (end_cert_fingerprint)
);
컬럼자료형역할
idBINARY(16) PKcosigner 설정의 고유 식별자
workspace_idBINARY(16) FK이 cosigner 가 속한 workspace
paired_api_user_idBINARY(16) nullable FKAPI Cosigner 의 경우 페어링된 API user. Mobile / Fireblocks Cloud cosigner 는 NULL
typeENUM (4 값)mobile 사용자 device / api-sgx customer 운영 SGX 서버 / communal-test testnet 전용 공유 / fb-cloud-sgx Fireblocks Azure SGX
end_cert_pemTEXTChain of Trust 의 leaf cert (PEM 인코딩)
end_cert_fingerprintBINARY(32) UNIQUEleaf cert 의 SHA-256 지문. 같은 cert 가 중복 등록되지 않도록 UNIQUE
intermediate_cert_idBINARY(16) FK이 leaf cert 를 서명한 Core Services Intermediate Cert 의 id (체인 추적)
configuration_db_keyrefVARCHAR(128) nullableHSM-wrapped private key reference. plaintext 절대 저장 안 함
registered_by · registered_atBINARY(16) · DATETIME(6)최초 페어링 시작한 actor + 시각. 이 row 의 created semantic. set-once
modified_by · modified_atBINARY(16) · DATETIME(6)마지막 변경 (cert update / config 수정 등) actor + 시각
re_enrolled_atDATETIME(6) nullable가장 최근 재등록 시각 (auth method 전환 또는 SSL cert 변경 시)

8.2 callback_endpoints — Callback Handler 의 endpoint 설정 (per-API-user)

CREATE TABLE callback_endpoints (
  id                  BINARY(16) PRIMARY KEY,
  cosigner_id         BINARY(16) NOT NULL,
  paired_api_user_id  BINARY(16) NOT NULL,             -- per-API-user key model
  url_base            VARCHAR(255) NOT NULL,
  custom_path         VARCHAR(128),
  auth_option         TINYINT NOT NULL,                -- 1 ~ 5
  jwt_or_json         ENUM('jwt', 'json') NOT NULL,
  url_uses_v2         BOOLEAN NOT NULL,
  callback_pubkey     BLOB NOT NULL,                   -- RSA 2048 public
  tls_pin_sha256      BINARY(32),                      -- option 2, 4 의 cert pin
  registered_by       BINARY(16) NOT NULL,
  registered_at       DATETIME(6) NOT NULL,
  modified_by         BINARY(16) NOT NULL,
  modified_at         DATETIME(6) NOT NULL,
  last_invoked_at     DATETIME(6)
);
컬럼자료형역할
idBINARY(16) PKendpoint 의 고유 식별자
cosigner_idBINARY(16) FK이 callback 이 속한 Cosigner
paired_api_user_idBINARY(16) FK이 endpoint 의 대상 API user. per-API-user 격리 — Co-signer 의 global key 와 달리 callback 은 user 별 별도 key
url_base · custom_pathVARCHAR(255) · VARCHAR(128)customer 가 운영하는 endpoint URL. /v2 prefix 는 자동 결정 (JWT 면 추가, JSON 이면 미추가)
auth_optionTINYINT1~5 — 위 "5 Authentication Options" 표의 번호
jwt_or_jsonENUM (2 값)auth_option 1/4/5 = jwt / 2/3 = json. url_uses_v2 의 분기 조건
url_uses_v2BOOLEANJWT-bearing 이면 TRUE (URL 에 /v2 prefix 추가)
callback_pubkeyBLOBcallback handler 의 response 서명 검증용 public key (RSA 2048)
tls_pin_sha256BINARY(32) nullableauth_option 2 / 4 의 TLS cert pin SHA-256
registered_by · registered_atBINARY(16) · DATETIME(6)최초 등록 actor + 시각. created semantic. set-once
modified_by · modified_atBINARY(16) · DATETIME(6)마지막 변경 actor + 시각
last_invoked_atDATETIME(6) nullable마지막으로 이 endpoint 가 호출된 시각 (운영 상태 모니터링용)

8.3 designated_signers — Policy rule 의 designated signer 지정 (junction)

-- Policy 의 NS 라벨이 적용된 rule 의 signer set
CREATE TABLE designated_signers (
  id                          BINARY(16) PRIMARY KEY,
  policy_rule_id              BINARY(16) NOT NULL,
  signer_user_id              BINARY(16),
  signer_user_group_id        BINARY(16),
  internal_exchange_excluded  BOOLEAN NOT NULL DEFAULT TRUE,
  granted_by                  BINARY(16) NOT NULL,
  granted_at                  DATETIME(6) NOT NULL,
  revoked_by                  BINARY(16),
  revoked_at                  DATETIME(6),
  KEY (policy_rule_id),
  KEY (policy_rule_id, revoked_at)
);
컬럼자료형역할
idBINARY(16) PK지정 이벤트의 surrogate PK
policy_rule_idBINARY(16) FK이 designated signer 가 적용되는 Policy rule. 10. Policy 의 policy_rules.designated_signer_user_group_id 가 단일 group 만 가리키지만, 본 테이블은 ad-hoc 지정도 표현
signer_user_idBINARY(16) nullable단일 user 지정인 경우. user_group_id 와 둘 중 하나만 set
signer_user_group_idBINARY(16) nullablegroup 지정인 경우
internal_exchange_excludedBOOLEANNSA / Editor 의 designated signer 흐름이 internal exchange transfer 만 제외하는 default 정책. TRUE = 제외
granted_by · granted_atBINARY(16) · DATETIME(6)지정 actor + 시각. set-once
revoked_by · revoked_atBINARY(16) nullable · DATETIME(6) nullable지정 해제 actor + 시각. NULL = 현재 active. set-once when set

Putting It Together — Signing 시퀀스

sequenceDiagram
  autonumber
  actor Initiator as 👤 tx initiator
(API user 또는 Console user)
  participant FB as 🛡️ Fireblocks Core
  participant Policy as 📜 Policy Engine
  participant Cosigner as 🖥️ API Cosigner
(SGX)
  participant Callback as 🌐 Callback Handler
(customer endpoint)
  participant Chain as ⛓️ Blockchain

  Initiator->>FB: tx 요청 (api_keys + cert)
  FB->>Policy: Policy rule 평가 (initiator / source / destination / amount)

  alt Policy action = Approved by + designated_signer 지정됨
    Policy->>Cosigner: signing 위임 (designated_signers 의 signer_user/group)
  else action = Allow
    Policy->>Cosigner: 일반 cosigner 흐름
  end

  Cosigner->>Cosigner: cosigner_configs 의 cert chain 검증

  alt callback_endpoints 가 등록됨
    Cosigner->>Callback: tx_sign_request POST
(JWT 또는 JSON, /v2 분기)
    Note over Callback: customer 측 추가 검증
(compliance / business rule)
    Callback->>Cosigner: ACK 또는 REJECT
    alt callback REJECT
      Cosigner->>FB: 서명 거부
      FB->>Initiator: tx FAILED
    end
  else callback 미등록
    Note over Cosigner: ⚠️ Auto-sign default
외부 검증 단계 bypass
  end

  Cosigner->>FB: MPC share 서명 (3-share ceremony 의 cosigner 측 share)
  FB->>Chain: 서명 완료 tx broadcast
  FB->>Initiator: tx accepted
Figure 28. tx 서명 흐름 + cosigner + callback. 핵심: ① Policy Engine 이 rule 매칭 후 designated_signers 가 지정된 경우 signing 을 그 user/group 에 위임. ② Cosigner 가 자기 cert chain (cosigner_configs) 을 검증. ③ Callback Handler 가 등록된 경우 서명 직전에 customer 측 endpoint 에 추가 검증 요청 (callback_endpoints) — REJECT 시 서명 거부. ④ callback 미등록 = auto-sign default — 운영상 가장 중요한 보안 risk. ⑤ 검증 통과 후 비로소 MPC ceremony 의 cosigner 측 share 가 서명에 참여. cosigner private key 가 global (모든 API user 공유) 인 것 vs callback key 가 per-user 인 것의 비대칭은 위 "Key Model 비대칭" 절 참조.
