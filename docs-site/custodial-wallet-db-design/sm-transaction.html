14. Transaction — 17 Primary Status State Machine

17 status state machine · 시간 제약 · chain 별 특이 제약 · Outgoing/Incoming 흐름 분리
본 페이지의 출처 — 어디까지가 Fireblocks 정의이고, 어디부터가 추정인가

이 페이지의 내용은 두 갈래입니다.

Fireblocks 공식 문서에 정의된 사실 — 그대로 받아들여도 안전

  • 17 Primary Status 의 이름과 API code, color 분류 (Yellow / Blue / Green / Red)
  • 시간 제약: Pending Authorization 2h · Pending Signature 2h · Cancelling 30s typical · Broadcasting 1min typical · Solana 6번째 tx 2h Submitted timeout
  • Chain-Specific 처리: EVM blockchain-standard 직렬화 / Solana per-vault 5 + workspace 600 / EVM withdrawal nonce 충돌 / Bitcoin unconfirmed 25-tx chain
  • Special Branches: Approvers Unanimous-Veto(?) Rule (1 명 reject = 즉시 rejected) · Outgoing rejected 자산 즉시 사용 가능 · Incoming rejected = Admin unfreeze 까지 lock · Raw Signing cached signature · Solana Sign-Only (NOT BROADCAST BY FIREBLOCKS 태그)

저자가 합리적으로 추정해서 그린 설계 — 참고용, 본인 환경에서 검증 권장

  • transactions · transaction_events 두 테이블의 구체 schema
  • Outgoing/Incoming 흐름의 transition edge — Fireblocks 문서가 17-status 의 의미는 명시하지만 그 사이 전이 그림은 그려져 있지 않아 status 별 설명을 종합해서 재구성
  • raw_payload_cbor 의 CBOR(?) 직렬화 선택 (audit cross-DB 비교를 위한 byte-deterministic)

Chain-Specific 처리 모델

  • EVM(?)-compatible: 동일 vault account(?) 의 EVM tx 들은 blockchain-standard 단위 직렬화 (Ethereum + Polygon → 순차, BTC + Solana → 병렬). 추가로 transfer type 3 종 (Fireblocks API evmTransferType): NATIVE (ETH 등 native transfer) / TOKEN (ERC-20 등 log 기반) / INTERNAL (smart contract 내부 호출, trace 기반)
  • Solana: per-vault 동시 5 tx + workspace-wide 600 tx queue cap. EVM/BTC 와 달리 hard stuck 아닌 soft throttle (6번째부터 Submitted 대기, max 2h 후 terminated) — 1 vault 로도 운영 가능
  • EVM withdrawal: nonce(?) 충돌 위험 → multiple withdrawal vault 권장 round-robin
  • Bitcoin withdrawal: unconfirmed input 25-tx chain limit(?) (Bitcoin Core default) → multiple withdrawal vault
  • TON: tonTransferType = NATIVE 또는 JETTON. ★ TON 은 arbitrary message body 지원 — messageComment 필드가 raw payload 노출. 비표준 format custom parsing 필요
  • ★ Canton (2-step transfer protocol): 다른 chain 과 lifecycle 자체가 다름. Fireblocks API transactionType 5 enum:
    • OFFER — sender 가 transfer 제안. recipient 의 action 대기 (1-step 의 시작)
    • ACCEPT — recipient 가 OFFER 수락. 자금 이동 완료
    • REJECT — recipient 가 거부. 자금 이동 안 됨
    • WITHDRAW — sender 가 OFFER 취소 (recipient 가 action 하기 전). 자금 이동 안 됨
    • PRE_APPROVAL — recipient 가 사전 승인. ★ 1-step instant transfer (Kraken 등 외부 source 에서 들어오는 자동 승인). 17-status state machine 의 Confirming 으로 직진
    traceableId + hashes.{offerUpdateId, acceptUpdateId, rejectUpdateId, withdrawUpdateId, preApprovalUpdateId} 가 OFFER → 후속 action 의 cross-reference. DB 영향: transactions.operation 외에 chain_specific_action ENUM('OFFER','ACCEPT','REJECT','WITHDRAW','PRE_APPROVAL') + parent_tx_id BINARY(16) 컬럼이 Canton 자산 보유 시 필요. 일반 chain 은 NULL
  • Polkadot (DOT): substrateExtrinsicId 필드 — extrinsic ID 로 tx 추적. tx_hash 와 별개 plane
  • Sui: gas 가 4-way 분해 — storageCost / storageRebate (storage cleanup 환급) / computationCost / nonRefundableStorageFee. 단순 networkFee 단일 컬럼으로는 부족
  • Hedera (HBAR): 별도 hbarTxHash 필드 — HBAR-specific transaction hash

Special Branches

  • Approvers Unanimous-Veto Rule: "If at least one person chooses to reject, the transaction is rejected." Approvers N명 → reject 1표 = tx 즉시 rejected
  • Outgoing rejected: 자산 즉시 사용 가능 (re-tx 가능)
  • Incoming rejected: 자산이 Admin 가 unfreeze 할 때까지 사용 불가
  • Raw Signing (cached signature): 동일 raw data 재서명 시 Submitted → Completed (전체 ceremony 우회)
  • Solana Sign-Only: signed payload client 에 반환, Fireblocks 가 broadcast 안 함, NOT BROADCAST BY FIREBLOCKS 태그

DB Schema

6.1 transactions — tx 본체 (state machine 의 current state)

CREATE TABLE transactions (
  id                  BINARY(16) PRIMARY KEY,
  workspace_id        BINARY(16) NOT NULL,
  source_vault_id     BINARY(16),                       -- outgoing: source / incoming: NULL
  destination_type    ENUM('VAULT_ACCOUNT','EXCHANGE_ACCOUNT','INTERNAL_WALLET','EXTERNAL_WALLET','UNMANAGED_WALLET','ONE_TIME_ADDRESS','NETWORK_CONNECTION','FIAT_ACCOUNT'),
  asset_id            VARCHAR(32),
  amount_decimal      DECIMAL(38, 18),
  chain               VARCHAR(32),
  operation           ENUM('TRANSFER','CONTRACT_CALL','PROGRAM_CALL','TYPED_MESSAGE','RAW','MINT','BURN') DEFAULT 'TRANSFER',
  status              ENUM('SUBMITTED','PENDING_AML_SCREENING','PENDING_ENRICHMENT','PENDING_AUTHORIZATION','PENDING_3RD_PARTY','PENDING_3RD_PARTY_MANUAL_APPROVAL','QUEUED','PENDING_SIGNATURE','BROADCASTING','CONFIRMING','COMPLETED','SIGNED','CANCELLING','CANCELLED','BLOCKED','REJECTED','FAILED') NOT NULL,
  network_status      ENUM('DROPPED','BROADCASTING','CONFIRMING','FAILED','CONFIRMED'),  -- blockchain-layer status (별개 plane)
  status_changed_at   DATETIME(6) NOT NULL,
  created_by          BINARY(16) NOT NULL,              -- tx 시작한 user (incoming 의 경우 시스템 user)
  created_at          DATETIME(6) NOT NULL,
  modified_by         BINARY(16) NOT NULL,              -- 마지막 상태 전이를 trigger 한 actor
  modified_at         DATETIME(6) NOT NULL,             -- = 가장 최근 status_changed_at
  external_tx_id      VARCHAR(255) UNIQUE,              -- ★ idempotency key (Fireblocks 공식 "critical practice")
  raw_payload_cbor    BLOB,                              -- ★ append-only — set-once after TEE 서명
  tx_hash             VARCHAR(128),                      -- ★ set-once (broadcast 시점)
  chain_nonce         VARCHAR(64),                       -- ★ EVM transaction nonce. EVM 만 set, 그 외 NULL. Fireblocks API transaction-objects.nonce 와 정합. RBF/Boost/Drop 의 binding key
  -- Relay 모델 (feeInfo) — Gasless / sponsored tx (현재 vault 가 fee 대납 안 함)
  paid_by_relay       BOOLEAN NOT NULL DEFAULT FALSE,    -- ★ relay 가 fee 대납 여부
  relay_type          ENUM('LOCAL','THIRD_PARTY'),       -- LOCAL=같은 tenant 내 다른 vault / THIRD_PARTY=다른 tenant
  relay_vault_id      BINARY(16),                         -- relay 가 LOCAL 이면 vault id 참조 (Gas Station vault 등)
  relay_tenant_name   VARCHAR(128),                       -- THIRD_PARTY relay 의 tenant 이름
  -- Chain-specific 식별자 (tx_hash 외 별도 hash 가 필요한 chain)
  chain_specific_payload_cbor BLOB,                       -- ★ chain-별 추가 필드 (HBAR hbarTxHash / DOT substrateExtrinsicId / TON messageComment+jetton* / Sui gasUsed breakdown 등) CBOR 직렬화
  -- Canton 2-step transfer protocol 분기
  canton_action       ENUM('OFFER','ACCEPT','REJECT','WITHDRAW','PRE_APPROVAL'),
  parent_tx_id        BINARY(16),                         -- Canton OFFER → 후속 ACCEPT/REJECT/WITHDRAW 의 parent. 일반 chain 은 NULL
  -- Algorand staking rewards
  algo_src_rewards    DECIMAL(38, 18),                    -- ALGO source 측 rewards acknowledged
  algo_dest_rewards   DECIMAL(38, 18),                    -- ALGO destination 측 rewards acknowledged
  -- Sui gas 4-way breakdown
  sui_storage_cost            DECIMAL(38, 18),
  sui_storage_rebate          DECIMAL(38, 18),
  sui_computation_cost        DECIMAL(38, 18),
  sui_non_refundable_storage  DECIMAL(38, 18),
  pending_auth_at     DATETIME(6),                       -- 2h timeout 산정 기준
  pending_sign_at     DATETIME(6),                       -- 2h timeout 산정 기준
  routing_type        ENUM('DEFAULT','NODE_ROUTER','MEV') DEFAULT 'DEFAULT',  -- NODE_ROUTER = customer-provided node, MEV = MEV protection routing (EVM only)
  base_fee            DECIMAL(38, 18),                   -- EIP-1559 base fee (EVM only)
  priority_fee        DECIMAL(38, 18),                   -- EIP-1559 priority fee (EVM only) / Solana priority fee
  rent_fee            DECIMAL(38, 18),                   -- Solana account rent fee
  KEY (workspace_id, status),
  KEY idx_external_tx (workspace_id, external_tx_id),
  KEY idx_evm_nonce (source_vault_id, chain, chain_nonce),  -- stuck detection / RBF lookup
  KEY idx_canton_parent (parent_tx_id),                      -- Canton OFFER → action lookup
  KEY idx_relay (relay_vault_id, paid_by_relay)              -- Gas Station / sponsored tx 조회
);

-- Multi-destination tx (UTXO 가 한 tx 에서 N destinations 분기 가능)
-- single-destination (EVM 등) 은 본 테이블 사용 안 함, transactions.destination_type 만으로 표현
CREATE TABLE transaction_destinations (
  transaction_id    BINARY(16) NOT NULL,
  sequence_no       SMALLINT NOT NULL,                    -- destination index (0, 1, 2 ...)
  destination_type  ENUM('VAULT_ACCOUNT','EXCHANGE_ACCOUNT','INTERNAL_WALLET','EXTERNAL_WALLET','UNMANAGED_WALLET','ONE_TIME_ADDRESS','NETWORK_CONNECTION','FIAT_ACCOUNT') NOT NULL,
  destination_id    VARCHAR(128),                          -- peer ID. ONE_TIME_ADDRESS 일 때 NULL (대신 ota_address)
  ota_address       VARCHAR(128),                          -- ONE_TIME_ADDRESS 의 destination
  ota_tag           VARCHAR(64),                           -- XRP tag / XLM memo_text / EOS·HBAR·XDB memo / ALGO notes
  amount_decimal    DECIMAL(38, 18) NOT NULL,
  net_amount        DECIMAL(38, 18),                       -- fee 차감 후 (treatAsGrossAmount=true 흐름)
  PRIMARY KEY (transaction_id, sequence_no),
  KEY idx_destination (destination_type, destination_id)
);
컬럼자료형역할
idBINARY(16) PKtx 의 고유 식별자
workspace_idBINARY(16) FK이 tx 가 속한 workspace

6.2 transaction_events — 상태 전이 이력 (append-only)

-- ★ append-only — 모든 status 전이의 audit trail
CREATE TABLE transaction_events (
  id              BINARY(16) PRIMARY KEY,
  transaction_id  BINARY(16) NOT NULL,
  from_status     VARCHAR(32),
  to_status       VARCHAR(32) NOT NULL,
  reason          VARCHAR(255),                  -- 전이 사유 (예: "2h timeout", "user cancel", "DCCP threshold")

  occurred_at     DATETIME(6) NOT NULL,
  KEY (transaction_id, occurred_at)
);
