13. Recovery Passphrase(?) & Workspace(?) Keys Backup

3 recovery scenarios · 6-file backup package · 4 secrets · SPOC(?) 경고
본 페이지의 출처 — 어디까지가 Fireblocks 정의이고, 어디부터가 추정인가

이 페이지의 내용은 두 갈래입니다.

Fireblocks 공식 문서에 정의된 사실 — 그대로 받아들여도 안전

  • Recovery passphrase 의 역할: mobile device 의 MPC key share 를 cloud 에 backup 할 때 암호화하는 비밀. Owner / Admin / Signer 가 initial setup 시 mobile app 에서 필수 생성
  • 요구사항: ≥10 chars + ≥1 capital + ≥1 number + ≥1 special. 검증은 mobile client-side
  • 저장 정책: DB 에는 hash 도 저장 안 함 (forbidden storage) — Owner 가 별도 보관
  • 3 Recovery Scenarios: Owner key share / Admin·Signer key share (다른 authorized signer 의 passphrase 사용) / Workspace Keys Recovery (full private key 재구성)
  • Verify + Periodic Verification: mobile app 에서 본인 passphrase 검증, 3 회 연속 실패 시 5 분 lockout. 월 1회 알림
  • Workspace Keys Backup 의 6 file 구성: ECDSA 3 + EdDSA 3, mobile share 는 passphrase-encrypted, FB Cloud 2 share 는 RSA-4096-encrypted
  • Hosted MPC variant: Owner mobile + 2 Guard Co-Signer 가 함께 backup 참여 (3-share)
  • 4 secrets for reconstruction: Recovery Kit ZIP · RSA private key · Mobile Recovery Passphrase · RSA Private Key Passphrase
  • SPOC 경고: online machine 에서 reconstruction 시 즉시 key compromise — 반드시 offline air-gapped machine 에서만
  • Auto-passphrase 옵션: Enterprise tier, Support enable 필요. mobile 이 secure random passphrase 자동 생성 → 고객 RSA key 로 암호화

저자가 합리적으로 추정해서 그린 설계 — 참고용, 본인 환경에서 검증 권장

  • recovery_events · passphrase_verification_attempts · workspace_keys_backups 3 테이블의 구체 schema (auditdb 위치, 모두 append-only)
  • recovery_events 의 air_gapped_machine_*_attested 컬럼 — DCAP attestation 으로 offline 기계의 무결성 입증을 schema 에 표현하는 선택
  • passphrase_verification_attempts 의 3-fail / 5-min lockout 강제는 application layer 에서 처리하고 본 schema 는 attempt 기록만 보관
  • workspace_keys_backups.passphrase_owner_user_id + rsa_pubkey_fingerprint 가 SaaS vs Hosted variant 구분

Recovery Passphrase — 역할과 위치

recovery-passphrase.md, p.1 직접 인용:

"Fireblocks uses the recovery passphrase(?) to create an encrypted backup of the mobile device's private key share, which is stored securely in Fireblocks' cloud servers."
  • 누가 생성: Owner / Admin / Signer — initial user setup 시 mobile app 에서 필수 생성
  • Requirements: ≥10 chars + ≥1 capital + ≥1 number + ≥1 special. Mobile client-side validate
  • 역할: Mobile device 의 MPC(?) key share 를 cloud backup 으로 암호화하는 키
  • 저장 위치: Owner 가 별도 보관 — DB 에는 hash 도 저장 안 함 (forbidden storage(?))

3 Recovery Scenarios

Scenario사용 자산사용처
Owner key share recovery본인 recovery passphrase (또는 password-less)Owner device 분실 / 신규
Admin/Signer key share recovery다른 authorized signer의 recovery passphraseAdmin / Signer device 분실
Workspace Keys RecoveryRecovery passphrase + Workspace Keys BackupOwner의 full private key 재구성

Verify Passphrase + Periodic Verification

  • Mobile app Settings > Verify recovery passphrase — cloud 에서 backup download → 입력한 passphrase 로 decrypt 시도
  • 3회 연속 실패 → 5분 lockout
  • 월 1회 알림, Owner/Admin/Signer 대상 (iOS 2.5.7+, Android 2.5.2+)
  • Owner / Admin 이 workspace(?) audit logs 에서 key share risk status 검토 가능 — log 에 verification 시점 + 정상 verify 여부 포함

Workspace Keys Backup — 6 files 의 구성

generating-a-workspace-key-backup-package-fireblocks-recovery-utility.md 직접 인용: "The package is composed of six files that contain the following key share components."

Backup Package — 6 encrypted shares:
  ┌── ECDSA shares (3 files)
  │   ├── Mobile share        — passphrase-encrypted
  │   ├── FB Cloud share #1   — RSA-4096 encrypted
  │   └── FB Cloud share #2   — RSA-4096 encrypted
  └── EdDSA shares (3 files)
      ├── Mobile share        — passphrase-encrypted
      ├── FB Cloud share #1   — RSA-4096 encrypted
      └── FB Cloud share #2   — RSA-4096 encrypted

Hosted MPC Backup — 3-share variant

SaaS MPC 와 달리 Owner mobile + 2 Guard Co-Signer 가 함께 backup 에 참여 (Hosted MPC 의 customer-3-share 모델).

Share출처암호화 방식전달 경로
1. Mobile key shareOwner mobile devicepassphrase-encryptedencrypted kit via email → download → air-gapped machine #1
2. Guard Co-Signer #1 shareGuard CS#1 (SGX(?))RSA public key (customer 업로드)자동 생성 → local host file
3. Guard Co-Signer #2 shareGuard CS#2 (SGX)RSA public key자동 생성 → local host file

→ Asymmetric encryption layers: mobile = passphrase, Guard = RSA. 2 air-gapped machines 요건 (download + assembly 분리).

Reconstruction — 4 secrets

Recovery Utility 의 offline-only procedure 가 요구하는 4 가지 비밀:

  1. Recovery Kit ZIP (6-file package)
  2. RSA private key (Guard share 의 복호화)
  3. Mobile App Recovery Passphrase
  4. RSA Private Key Passphrase
⚠️ SPOC 경고 — Fireblocks 직접 인용

"Performing this procedure on an online machine will result in your private key being considered exposed and compromised."

→ DR Recovery Utility 는 offline air-gapped machine 에서만 사용. Online 실행 = 즉시 key compromise.

Auto-passphrase (Enterprise 옵션)

  • Support enable 필요 (자체 활성 불가)
  • Mobile device 가 secure random passphrase 자동 생성 → 고객 RSA key 로 암호화 → Fireblocks 에 저장
  • Offline machine 에서 decrypt (recovery 시)
  • 효과: 사용자 인적 오류 (분실/유출) 제거, 표준화
  • Trade-off: 새로운 SPOF = RSA private key 의 안전 보관

DB Schema — auditdb 의 3 append-only 테이블

키 material 자체는 forbidden storage 영역이라 DB 에 없고, 복구 절차의 event 와 attempt 만 audit-grade 로 기록합니다. 모두 별도 auditdb 에 위치 + BEFORE UPDATE/DELETE trigger 로 append-only 강제.

5.1 recovery_events — 3 scenario 의 복구 시도 이력

CREATE TABLE recovery_events (
  id                            BINARY(16) PRIMARY KEY,
  workspace_id                  BINARY(16) NOT NULL,
  scenario_type                 ENUM('owner-key-share','admin-signer-key-share','workspace-keys-recovery') NOT NULL,
  initiated_by_user_id          BINARY(16) NOT NULL,
  initiated_at                  DATETIME(6) NOT NULL,
  completed_at                  DATETIME(6),                  -- ★ set-once
  status                        ENUM('initiated','verifying','reconstructed','failed','aborted') NOT NULL,
  air_gapped_machine_1_attested BOOLEAN,                       -- DCAP attestation evidence
  air_gapped_machine_2_attested BOOLEAN,
  KEY (workspace_id, scenario_type)
);
컬럼자료형역할
idBINARY(16) PK복구 시도 이벤트의 고유 식별자
workspace_idBINARY(16) FK복구가 진행되는 workspace
scenario_typeENUM (3 값)owner-key-share Owner 본인 device 분실 시 / admin-signer-key-share Admin·Signer device 분실 시 (다른 authorized signer 의 passphrase 사용) / workspace-keys-recovery full private key 재구성
initiated_by_user_idBINARY(16) FK복구 시작한 user. set-once
initiated_atDATETIME(6)복구 시작 시각. set-once
completed_atDATETIME(6) nullable복구 완료 또는 실패 시각. set-once when set
statusENUM (5 값)initiated 시작 / verifying passphrase 검증 중 / reconstructed 키 재구성 완료 / failed 실패 / aborted 사용자 중단
air_gapped_machine_1_attestedBOOLEAN nullableworkspace-keys-recovery 시 사용된 첫 번째 air-gapped 머신의 무결성 attestation (DCAP / TPM 같은 cryptographic 증명). TRUE = 정상, NULL = 미적용 scenario
air_gapped_machine_2_attestedBOOLEAN nullable두 번째 air-gapped 머신 (Hosted MPC 의 download + assembly 분리 요건) 의 attestation

5.2 passphrase_verification_attempts — 검증 시도 이력 (lockout audit)

CREATE TABLE passphrase_verification_attempts (
  id           BINARY(16) PRIMARY KEY,
  user_id      BINARY(16) NOT NULL,
  attempt_type ENUM('verify','periodic','recovery') NOT NULL,
  result       ENUM('verified','incorrect','lockout') NOT NULL,
  attempted_at DATETIME(6) NOT NULL,
  KEY (user_id, attempted_at)
);
컬럼자료형역할
idBINARY(16) PK시도 이벤트 식별자
user_idBINARY(16) FKpassphrase 를 시도한 user (자기 자신만 시도 가능)
attempt_typeENUM (3 값)verify 사용자 본인의 자발적 검증 / periodic 월 1 회 자동 알림 검증 / recovery 실제 복구 시도
resultENUM (3 값)verified 통과 / incorrect 틀린 입력 / lockout 3 회 연속 실패로 5 분 lockout 발효 (application layer 가 강제, 본 row 는 그 시점 기록)
attempted_atDATETIME(6)시도 시각
KEY (user_id, attempted_at)—"이 user 의 최근 실패 패턴" 조회 인덱스 — 의심 활동 탐지

5.3 workspace_keys_backups — backup package 메타데이터

CREATE TABLE workspace_keys_backups (
  id                       BINARY(16) PRIMARY KEY,
  workspace_id             BINARY(16) NOT NULL,
  variant                  ENUM('saas-mpc','hosted-mpc') NOT NULL,
  share_count              INT NOT NULL,                    -- 6 (SaaS) or 3 (Hosted)
  passphrase_owner_user_id BINARY(16) NOT NULL,             -- 누구의 passphrase 로 암호화
  rsa_pubkey_fingerprint   BINARY(32),                       -- Hosted MPC Guard 의 RSA
  created_by               BINARY(16) NOT NULL,
  created_at               DATETIME(6) NOT NULL,
  superseded_at            DATETIME(6),                      -- Owner transfer 시 파기 결정
  destroyed_at             DATETIME(6),                      -- 파기 완료
  KEY (workspace_id)
);

-- ★ Forbidden columns 의 ABSENCE 가 schema 자체로 보이도록 audit
-- 절대 추가 X: passphrase_plaintext, passphrase_hash, rsa_private_key, backup_blob_plaintext
컬럼자료형역할
idBINARY(16) PKbackup package 의 고유 식별자
workspace_idBINARY(16) FK이 backup 이 속한 workspace
variantENUM (2 값)saas-mpc 기본 SaaS MPC (mobile + 2 FB Cloud) / hosted-mpc customer 가 3 share 전부 보유
share_countINTbackup 의 file 수 — SaaS 는 6 (ECDSA 3 + EdDSA 3), Hosted 는 3
passphrase_owner_user_idBINARY(16) FK이 backup 의 mobile share 를 암호화한 passphrase 의 소유 user
rsa_pubkey_fingerprintBINARY(32) nullableHosted MPC 의 경우 Guard share 를 암호화한 customer RSA pubkey 의 SHA-256 지문. SaaS variant 는 NULL
created_byBINARY(16)backup 생성을 trigger 한 user (보통 Owner). set-once
created_atDATETIME(6)backup 생성 시각. set-once
superseded_atDATETIME(6) nullableOwner transfer 등으로 이 backup 이 무효화된 시각. NULL = 현재 활성
destroyed_atDATETIME(6) nullablebackup file 들이 실제로 파기 완료된 시각. superseded 와 분리 — supersede 결정 후 실제 파기까지의 시간차 audit

  Owner->>New_M: air-gapped machine #2 로 ZIP 이동 (USB 등)
+ RSA private key 입력

  Owner->>Console: 신규 device enrollment
  Console->>FB: key_lifecycle INSERT
