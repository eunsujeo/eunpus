잔액과 내역 조회 — getBalance · transactionsOf

고객 화면의 두 숫자 — 그런데 잔액은 숫자 하나가 아니다

무엇·언제: 고객 홈 화면(잔액)과 거래내역 화면이 부르는 읽기 동사 둘입니다. 잔액의 규칙부터 — 잔액은 세 칸입니다: 가용(available — 출금에 쓸 수 있는 돈) / 대기(pending — 들어왔지만 아직 확정 전, 4p) / 잠김(locked — 나가는 중인데 상대 수락 대기, 5p). 출금 가능 판정은 가용만 봅니다 — 대기·잠김을 합쳐 보여주는 화면은 자유지만, 합쳐서 판정하는 순간 없는 돈을 쓰게 됩니다.

getBalance(account, asset) → { available, pending, locked }
transactionsOf(account, 기간) → 입출금 내역 (시간순)

▸ 자체 분면 — 잔액·내역은 4·5페이지의 부산물이다

sequenceDiagram
    autonumber
    participant BE as 지갑 백엔드
    participant MGR as 자체 매니저
    participant PJ as 인덱서 기록 (수신 — 4p)
    participant TX as 파이프라인 기록 (송신 — 5p)

    BE->>MGR: getBalance(계정, 자산)
    MGR->>PJ: 확정 입금 합산 (+ 대기분 별도)
    MGR->>TX: 나가는 중·잠김 차감 반영
    MGR-->>BE: { 가용, 대기, 잠김 }

    BE->>MGR: transactionsOf(계정, 기간)
    MGR->>PJ: 수신 내역
    MGR->>TX: 송신 내역 — "보내는 중"(전파 전 기록 덕) 포함
    MGR-->>BE: 병합·시간순 정렬

따로 만드는 기능이 아니다 — 입금(4p)이 쌓은 기록과 출금(5p)이 단계마다 남긴 기록을 합쳐 읽을 뿐이다. 출금을 전파 전에 기록한 덕에 내역에 "보내는 중" 상태까지 보여줄 수 있다. 체인 차이는 잠김의 출처 — 이더리움은 잠김이 거의 없고(전파 후 곧 확정 추적), Canton 은 수락 대기 출금이 잠김 칸에 그대로 나타난다 — 고객이 "내 돈 어디 갔어요?"라고 물을 때 보여줄 칸이 있어야 한다.

▸ Fireblocks 분면 — 두 호출 다 벤더 API 한 번

sequenceDiagram
    autonumber
    participant BE as 지갑 백엔드
    participant FBI as Fireblocks 구현
    participant FB as Fireblocks (SaaS)

    BE->>FBI: getBalance(계정, 자산)
    FBI->>FB: vault 잔액 API — 가용·대기·잠김을 구분해 준다
    FB-->>BE: { 가용, 대기, 잠김 }

    BE->>FBI: transactionsOf(계정, 기간)
    FBI->>FB: 거래 목록 API (벤더가 입·출금 양방향 기록)
    FB-->>BE: 내역

벤더가 양방향을 다 기록하므로 병합이 필요 없다. 단 회계가 걸리는 숫자는 주기적으로 대조한다 — 벤더 잔액 vs 우리 기록(4p 의 "통지는 힌트" 규칙이 잔액에도 적용된다). Canton 자산의 잠김(수락 대기)이 벤더 응답에 어떻게 표현되는지는 적용 전 확인.

한 가지 경계만 분명히 — 이 동사들은 우리 고객 계정의 조회입니다. 임의 외부 주소(우리 고객이 아닌 지갑)의 잔액·이력 조회는 Fireblocks 가 주지 않는 별개 기능으로, 필요해지면 자체 인덱서를 그 용도로 따로 둡니다 — custody 와 독립적인 선택이라 전환(7p)과도 무관합니다.

백엔드에서 이렇게 부른다 — 판정은 가용만

// 출금 가능 판정 — 세 칸 중 available 만 본다 (대기·잠김은 표시용)
fun canWithdraw(account: Account, asset: Asset, amount: Amount): Boolean =
    accounts.getBalance(account, asset).available >= amount

// 내역 화면 — 입출금이 합쳐진 한 목록
fun historyScreen(account: Account, range: BlockRange): List =
    transactions.transactionsOf(account, range)    // 자체 분면이면 "보내는 중" 상태까지 포함

판정 코드에 available 만 쓰는 것 — 6페이지 규칙이 코드 한 줄로 강제되는 자리다.
