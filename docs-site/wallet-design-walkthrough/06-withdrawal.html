출금 — exactly-once 의 진짜 적

매트릭스 6~9행: estimateFee · submitTransaction · getStatus · boost/cancel

익숙한 것 ↔ 깨지는 지점 중복 요청은 멱등 키로 막는다 — 여기까진 늘 하던 일입니다. 깨지는 지점: 멱등 키는 외부의 재시도만 막습니다. 진짜 적은 자기 자신의 중간 사망이고, 체인에는 rollback 이 없어서 그 사고는 되돌릴 수 없습니다.

사고를 먼저 봅니다. 트랜잭션을 전파한 직후, 기록하기 직전에 프로세스가 죽었습니다. 저장소엔 흔적이 없으니 재시도가 멱등 가드를 그대로 통과하고, 새 순번(nonce)으로 새 트랜잭션을 만듭니다 — 옛것과 새것은 순번이 달라 둘 다 유효하고, 같은 출금이 두 번 나갑니다. DB 였다면 트랜잭션 롤백으로 끝날 일이, 체인에선 고객 자금 사고입니다.

해법은 백엔드 개발자에게 익숙한 모양입니다 — WAL(write-ahead log). 단 로그의 위치가 생명입니다: 기록은 전파 "전"(불변식 ③)이어야 하고, 복구는 기록된 단계에서 같은 서명본으로만 이어갑니다(새로 조립하면 새 순번 = 같은 사고):

// BUILT → SIGNED → BROADCAST — 단계마다 영속화하고 다음으로
resume(rec) {                          // 재기동 시 미완 건 복구
  switch (rec.state) {
    case 'BROADCAST': return            // 이미 전파됨 — 인덱서가 확정을 추적
    case 'SIGNED':    return broadcast(rec.signedTx)   // 같은 서명본 재전파만!
    case 'BUILT':     return signAndBroadcast(rec)     // 같은 tx(같은 순번)로 재개
  }
}

출금 상태머신. 어느 단계에서 죽어도 "그 단계부터, 같은 산출물로" 재개된다. 순번(nonce)은 계정별로 직렬화해 점유 — 분산 락의 체인 버전인데, 막히면 뒤 순번 전체가 멈추므로 막힌 트랜잭션은 같은 순번에 수수료만 올려 덮어쓴다(boost). Canton 은 이 그림이 달라진다 — 순번도 수수료 시장도 없고, "전파"가 OFFER 제출이라 상대가 수락해야 완료되며 그동안 자금이 잠긴다(locked). 멈추려면 boost 가 아니라 cancel(WITHDRAW)이다.

1페이지 매트릭스의 "재촉·취소" 행에 ? 가 붙어 있던 이유가 여기서 풀립니다 — boost 는 수수료 시장이 있는 체인(이더리움)의 동사라서, Canton 구현에는 타입부터 없습니다(불변식 ⑥).

같은 동사, 두 구현 — submitTransaction 을 나란히

자체 구현 — 위 상태머신이 실제로 도는 모습입니다:

sequenceDiagram
    autonumber
    participant BE as 지갑 백엔드
    participant SELF as 자체 구현 (TransactionPort)
    participant HSM as 정책 게이트 + HSM (8p)
    participant CH as 이더리움 노드
    participant IDX as 인덱서 (7p)

    BE->>SELF: submitTransaction(승인된 출금 + 멱등 키)
    SELF->>SELF: 조립 — nonce 점유 · BUILT 영속화
    SELF->>HSM: 서명 요청 (게이트 검증 통과 후)
    HSM-->>SELF: 서명본 — SIGNED 영속화
    SELF->>CH: 전파 — BROADCAST 기록
    CH-->>SELF: txRef(hash)
    SELF-->>BE: txRef
    IDX-->>BE: 확정(CONFIRMED) 은 인덱서가 push

자체 구현. 단계마다 영속화(BUILT→SIGNED→BROADCAST)가 끼어 있는 게 핵심 — 어디서 죽어도 같은 산출물로 재개된다. Canton 이면 5번이 OFFER 제출이 되고, 8번 앞에 "상대 수락 대기"(자금 잠김)가 끼어든다.

Fireblocks 구현 — 2페이지에서 해부했던 그 한 줄입니다:

(TAP·co-signer 정책이 8p 게이트의 자리)
    FB-->>FBI: 트랜잭션 id (= txRef)
    FBI-->>BE: txRef
    FB-->>BE: 상태 변화는 webhook push (확정 포함)

Fireblocks 구현. 자체 그림의 2~6번이 벤더 안으로 들어가고, 우리 멱등 키는 externalTxId 로 이어진다. 그래서 전환 후 자체 nonce 관리를 병행하면 벤더 내부 순번과 충돌한다 — 이 파이프라인을 "끄는" 것까지가 설계다.
