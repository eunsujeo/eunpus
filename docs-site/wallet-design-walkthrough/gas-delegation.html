가스 대납 — 누가 수수료를 내게 할 것인가

Fireblocks Gasless Service · Gas Station, 그리고 일반 표준(GSN · Paymaster)과의 구분

본 페이지의 출처

Fireblocks Gasless Service · Gas Station 내용은 Fireblocks 공식 문서(헬프센터·개발자 문서)에서 확인한 사실이다. GSN · ERC-4337 Paymaster 절은 일반 EVM 표준에 대한 저자 정리로, 본인 환경 적용 전 1차 자료 검증을 권장한다. 미확정으로 표시한 항목(정산 단가 등)은 Fireblocks CSM/Support 확인 대상이다.

문제 — EVM 의 gas 는 발신 계정에서 나간다

EVM 은 토큰(USDC 등)을 보낼 때도 수수료(gas)를 base asset(ETH)으로, 발신 계정에서 차감합니다. 수탁 지갑에서 이게 아픈 지점은 두 곳입니다.

지점왜 아픈가
고객 vault → 중앙 vault 이동(sweep)고객별 vault 수만 개 각각에 ETH 가 있어야 그 안의 토큰을 옮길 수 있다 — ETH 배포·잔고 모니터링·충전이 대량 운영이 된다.
운영 전반의 ETH 보유gas 용 ETH 를 상시 조달·보관해야 한다 — 은행 관점에서 "운영 목적의 가상자산 상시 보유"는 재무·회계·리스크 처리 부담이 크다.

선택지 지형 — 충전이냐, 대납이냐

해법은 두 축입니다. 충전(발신 vault 에 ETH 를 채워 준다)과 대납(다른 주체가 gas 를 낸다). Fireblocks 는 양쪽 다 제품이 있습니다.

"ETH 불요"는 토큰 전송 기준이다 — 고객이 ETH 자체를 출금하면 보내는 자산이 ETH 라서 그 물량은 별도로 필요하다. 스테이블코인 중심 서비스라면 사실상 ETH-free 운영이 된다.

Fireblocks Gasless Service — 확정 사실

지원 토큰의 fee 지불을 전용 vault / 외부 워크스페이스 / Fireblocks 에 위임하는 서비스입니다. 공식 문서가 명시합니다 — "Gasless Service 는 Gas Station 과 별개 제품이고, 다른 프로토콜을 쓴다."

항목내용
메커니즘ERC-3009 · ERC-2771 · EIP-7702 — ERC-4337 paymaster 가 아니다.
Limited Gasless (구)이더리움의 USDC·DAI(ERC-3009) + tokenization mint/burn(ERC-2771)에 한정.
Universal Gasless (신)EIP-7702(Pectra) 기반 — 첫 gasless 거래 때 vault(EOA)가 smart contract wallet 로 자동 승격된다. 이후 모든 이더리움 자산(ERC-20/721/1155)의 Transfer · Contract Call · Mint · Burn 을 지원.
지원 체인 (Universal)Ethereum(1) · Optimism(10) · Base(8453) · Arbitrum(42161) · Polygon PoS(137) · BSC(56) + 각 testnet. Solana·Tron(GasFree)은 별도 메커니즘.
설정Console: Settings → General → Gasless transactions — relay 3택 + 기본값 3모드(On by default / Off by default / Off, 거래별 재정의 가능) + Policies 연동.
API트랜잭션 API 에 Gasless(meta-tx) 경로 존재 — 미설정 시 error 1455 "Missing Gasless configuration (relayer/fee payer)".

운영 caveat — 대납이어도 남는 것
  • 막힌 거래의 자동 재촉 없음 — 공식 문서 명시: Gasless Relay 는 stuck 거래 auto-boost 를 지원하지 않는다. 수동 RBF boost가 필요하므로, 막힘 점검(워크스루 4장)과 Admin 의 boost·cancel(7장) 설계는 대납을 써도 그대로 필요하다.
  • 비용이 사라지는 게 아니라 지불 수단이 바뀐다 — 온체인 ETH → 월말 청구서(법정화폐). 정산은 회계 층의 일이 된다. 단가·구독료 수준은 미확정(CSM 확인 대상).
  • MPC 서명 ↔ EIP-7702 위임의 내부 동작은 공식 문서에 상세가 없다 — PoC/CSM 확인 대상.

일반 표준과의 구분 — GSN · ERC-4337 Paymaster

같은 "gas 대납" 문제를 푸는 일반 EVM 표준이 둘 있습니다. Fireblocks 는 이 둘을 그대로 쓰지 않습니다 — 아래는 저자 정리입니다(출처 callout 참조).

GSN (Gas Station Network)ERC-4337 Paymaster
무엇meta-transaction relay 네트워크 — 사용자는 서명만 하고, relayer 가 대신 온체인 제출하며 gas 를 낸다account abstraction 의 gas 대납 컨트랙트 — UserOperation 의 gas 를 스폰서하거나 ERC-20(USDC 등)으로 받는다
전제수신 컨트랙트가 ERC-2771(trusted forwarder)을 지원해야 — 일반 ERC-20 전송엔 못 쓴다지갑이 smart account 여야 + EntryPoint·bundler 인프라
왜 쓰나ETH 없는 사용자의 온보딩 UXgasless UX · 토큰으로 수수료 · 스폰서십
체인EVM (컨트랙트가 지원할 때)EntryPoint 가 배포된 EVM 전반 — Base 생태계가 활발
현황생태계가 4337 로 이동 — GSN 자체는 쇠퇴 계보account abstraction 표준의 주류

관계 정리 — Fireblocks 는 GSN "네트워크"가 아니라 ERC-2771 표준을 자체 relay 로 구현했고, paymaster(4337) 대신 EIP-7702 노선을 택했다. 참고로 Fireblocks 의 "Gas Station"(충전 자동화)은 GSN 과 이름만 유사할 뿐 무관하다. 이 둘은 사용자가 자기 지갑에서 직접 거래를 보내는 모델의 도구라, 모든 거래를 우리 vault 가 발신하는 수탁 모델에서는 Fireblocks Gasless 가 같은 자리를 대신한다.

이 문서의 결정 포인트

질문답
ETH 없이 운영이 되나Fireblocks Relay 면 토큰 운영 기준으로 가능 — "even if you do not hold any ETH". ETH 자체 취급 물량은 별도.
Gas Station 과 무엇을 고르나충전(Gas Station·ETH 운영 유지) vs 대납(Gasless·인보이스 정산) — 상호 배타가 아니라 병존 가능한 두 축. ETH 보유 부담과 프리미엄 비용의 트레이드오프.
기존 설계에서 바뀌는 것감지·판정(4장)·막힘 점검·boost(4·7장)는 그대로. 바뀌는 건 gas 조달 운영 → 월말 인보이스 정산(회계 층).
남은 확인인보이스 단가·구독료, MPC↔7702 내부 동작, ETH 네이티브 전송 gas 의 대납 여부 — CSM/PoC.
