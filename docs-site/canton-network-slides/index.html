Why Canton06 / 12

The design goal

사일로 없이 프라이버시를 만들기 위해.

01

필요한 사람만 본다

거래를 통째로 전 네트워크에 복제하지 않고 당사자별 뷰만 전달한다.

02

당사자가 검증한다

전역 검증 대신 그 거래의 이해관계자가 권한·규칙·중복 여부를 확인한다.

03

내용 없이 동기화한다

공용 계층은 암호봉투의 순서와 확인만 맞추고 금액·상대는 읽지 못한다.

선택적 공개 + 이해관계자 검증 + 가시성 없는 동기화 = 프라이버시와 무결성의 동시 확보
Three architectural pillars복제 범위를 거래 단위로 줄인다

Canton은 퍼블릭 체인의 코드를 가져와 방화벽 뒤에 둔 구조가 아닙니다. 데이터 배포, 검증 주체, 동기화 계층을 분리해 처음부터 선택적 공개가 가능하도록 설계했습니다. 이 세 기둥은 하나라도 빠지면 성립하지 않습니다.

Transaction flow10 / 12

How it works

한 거래는 암호봉투로 이동하고,
당사자의 확인으로 확정된다.

01제출

앱이 Ledger API로 자기 Validator에 거래를 보낸다.

02뷰 분해

Validator가 수신자별 거래 뷰를 만들고 암호화한다.

03순서화

Sequencer가 암호봉투에 전역 순서와 시간을 붙인다.

04검증

각 Validator가 자기 뷰의 권한·규칙·중복을 확인한다.

05확인 취합

Mediator가 당사자의 confirm을 모아 평결을 만든다.

06커밋

당사자 노드가 같은 결과를 기록하고 즉시 확정한다.

Synchronizer가 아는 것: 순서·시간·라우팅·확인 결과　 모르는 것: 금액·계약 내용·거래 상대의 업무 정보
submit → encrypt → order → validate → confirm → commit내용과 조율의 분리

Synchronizer는 중앙 원장이 아닙니다. Sequencer는 암호화된 메시지의 순서를 정하고, Mediator는 당사자 확인을 취합합니다. 실제 거래 유효성은 내용을 볼 수 있는 당사자 Validator가 검증하고, 확정 결과는 관련 노드에만 커밋됩니다.
