9. 거래소 + 자체 인덱서 운영 사례

자체 노드 · 자체 인덱서를 운영하는 회사들의 공개 아키텍처

9.1 개요

본 페이지는 거래소 또는 대규모 서비스가 자체적으로 노드와 인덱서를 운영하는 회사들 의 공개 아키텍처를 정리. 인덱서를 product 로 판매하는 vendor 는 10. 인덱서 / 데이터 인프라 vendor 에서 다룬다.

모든 정보는 공식 docs · tech blog · 채용 페이지 · 공식 announcement 만 사용. 내부 비공개 구현은 "미확인" 으로 명시. 3 단계 분류:

분류의미
확인됨공식 docs 또는 tech blog 에 명시
부분 확인채용 페이지 / 인터뷰 / 우회 자료에서 추론 가능
미확인공개 자료로 확인 불가

9.9 6 회사 공통 패턴

위 6 회사의 공개 자료에서 보이는 공통 패턴:

  1. 3 평면 분리 — 원시 체인 수집 / 파생 인덱서 / 사용자 facing API. Coinbase 가 가장 명확하게 공개.
  2. Event-driven backend — Kafka / Event Sourcing 이 표준. 거의 모두 사용.
  3. Durable workflow — Temporal (Korbit, Coinbase) 또는 자체. 입출금의 multi-step 흐름 관리.
  4. 실시간 + REST 이중 인터페이스 — Private WebSocket 으로 실시간 잔고 변경, REST 로 이력.
  5. Status enum 세분화 — 단순 success/fail 이 아닌 5-6 단계 분리 (Korbit, Coinone 이 모범).
  6. AML 외부 vendor 통합 — Chainalysis 가 가장 자주 등장.
