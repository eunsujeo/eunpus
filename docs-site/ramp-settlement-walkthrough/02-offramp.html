오프램프 — 코인 → 법정통화 (환전)

충전을 거꾸로 돌린 흐름이다. 고객에서 은행 풀로 코인이 옮겨 가며, DB 는 즉시·블록체인 전송은 15분 배치로 처리한다

무엇·언제: 사용자가 스테이블코인을 원화로 환전합니다. 환전은 고객에서 은행 풀로 코인이 옮겨 가는 일입니다. 1단계에서 고객 사용가능 잔액을 곧바로 차감하고 원화도 즉시 입금하며, 같은 코인이 고객에서 풀로 실제로 옮겨 가는 블록체인 전송은 15분 배치로 모아서 처리합니다. 환전이므로 총계정상 부채가 줄어듭니다.

실무 기본형은 사전 민팅 재고 풀입니다. 소각이 느려서(수 분~수십 분+), 평상시에는 고객 코인을 풀로 회수만 하고 회수한 코인을 다음 충전에 재사용합니다 — 발행사·Circle·거래소는 끼지 않습니다. 발행사 소각·Circle 상환·거래소 매도가 등장하는 것은 풀을 줄이는 rebalance(또는 재고 과다 시) 뿐입니다. 아래 다이어그램의 소각·처분 흐름은 그 재고 소진 경로입니다 (→ 공통 골격: 사전 민팅 재고 풀).

소각(burn)·처분 권한은 누구에게

원화코인(KRWK) 소각 = 발행사에 소각 요청(지갑 → 발행사로 코인 송금 후 소각).

달러코인(USDC) 처분 = Circle 상환(1차 시장 · 소각의 역방향) 또는 외부 거래소 매도(2차 시장).

보관 지갑(Fireblocks)은 코인을 발행사/거래소로 내보내기만 할 뿐, 소각 권한은 없습니다.

▸ Case A — 원화코인 → 원화 (발행사 소각, 1:1)

예시: 1:1 고정. 사용자가 KRWK 1,000 → KRW 1,000 환전.

▸ Case B — 달러코인 → 원화 (Circle 상환 또는 거래소)

예시: 시세 1,310 KRW/USD. 사용자가 USDC 1 → KRW. 평상시 환전은 코인을 풀로 회수하므로 흐름은 원화코인과 같습니다. 풀을 줄이는 처분 채널(Circle 상환 · 거래소 매도, 스프레드)은 별도의 rebalance 경로입니다.

Figure 2-B. 달러코인 환전. 평상시 흐름은 원화코인과 동일하다 — 1단계 DB 즉시(사용가능 차감 + 원화 입금) + 델타 PENDING, 2단계 15분 배치로 고객 → 풀 온체인 전송 후 settled. Circle 상환·거래소 매도는 풀을 줄이는 rebalance 경로라 이 흐름에는 등장하지 않으며, 스프레드·수수료 손익도 그쪽에서 발생한다.

핵심 포인트

  • 1단계 = DB 즉시 + 델타 PENDING — 사용가능을 바로 줄여 같은 코인이 두 번 환전되는 일을 막고, 원화도 즉시 입금합니다. 고객에서 풀로의 이동은 "DB 는 됐지만 블록체인 전송 전" 상태로 델타 큐에 PENDING 으로 쌓입니다.
  • 2단계 = 15분 블록체인 배치 — 모아 둔 PENDING 을 고객 지갑 → 은행 풀 지갑 온체인 전송으로 처리한 뒤 settled 로 마감합니다.
  • 충전의 역방향 — 코인이 고객에서 풀로 돌아오고(부채 ↓), 델타 방향만 뒤집힐 뿐 구조는 같습니다. 델타는 계정계와 무관합니다.
